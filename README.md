# justusing

**업로드 없이, 브라우저에서 바로 쓰는 파일 도구** — https://justus.ing

PDF 합치기·나누기·압축, 이미지 변환·크기 조절 같은 일을 프로그램 설치도, 회원 가입도, 파일 업로드도 없이
브라우저 안에서 끝내는 무료 도구 사이트입니다. 한국어와 영어로 쓸 수 있습니다.

## 어떤 도구가 있나요

**PDF**

| 묶음      | 도구                                                                             |
| --------- | -------------------------------------------------------------------------------- |
| 페이지    | 보기, 합치기, 나누기, 회전, 정리(순서·삭제), 모아찍기, 자르기                    |
| 변환      | PDF를 이미지로, 이미지를 PDF로, 압축                                             |
| 글자      | 글자 인식(OCR, 한국어·영어), 글자 추출, 쪽 번호, 워터마크, 머리말·꼬리말         |
| 편집      | 편집(글자·가리기·형광펜), 이미지 넣기, 서명 넣기, 양식 채우기, 가리기(영구 삭제) |
| 보안·정보 | 암호 걸기, 암호 해제, 사진 꺼내기, 문서 정보 고치기·지우기                       |

**이미지**: 압축, 크기 조절, 형식 변환

## 왜 안전한가요

핵심 약속은 하나입니다. **파일이 내 기기를 떠나지 않습니다.**
이 사이트에는 파일을 받을 서버도, 업로드 기능도, 데이터베이스도 없습니다. 아래는 그 약속을 코드로 어떻게 지키는지입니다.

### 1. 모든 처리는 내 브라우저 안에서

PDF를 읽고 고치는 일(pdf.js, pdf-lib), 글자 인식(Tesseract), 이미지 변환이 모두 내 컴퓨터·휴대폰의
브라우저에서 돕니다. 결과 파일도 브라우저 안에서 만들어 바로 내려받습니다(Blob URL). 파일 내용이나
파일 이름이 담긴 네트워크 요청을 만드는 코드는 이 저장소에 없고, 넣지 않는 것이 규칙입니다.

### 2. 도구는 격리된 칸 안에서만 돈다

무료로 운영하기 위해 바깥 페이지에는 광고와 방문 통계 스크립트가 있습니다. 이런 스크립트는 보통 같은 페이지의
화면 내용을 읽을 수 있습니다. 그래서 **파일을 고르고, 보고, 처리하고, 내려받는 영역 전체를 따로 떨어진 iframe에 넣었습니다.**

- iframe은 `sandbox="allow-scripts allow-downloads"`로 띄웁니다. `allow-same-origin`이 없어서 브라우저는 이 칸을
  **출처가 없는 별개의 문서**로 다룹니다. 바깥 페이지의 광고·통계 스크립트는 칸 안의 파일 이름, PDF 글자,
  미리보기에 접근할 수 없습니다.
- 칸 안에서 다른 곳으로 연결하는 것도 막혀 있습니다. 칸 문서의 보안 정책(CSP)은 `default-src 'none'`에서 시작해
  **우리 사이트의 파일(프로그램·글꼴)을 읽는 것만** 허용합니다. 도구 코드에 실수가 있거나 누가 코드를 끼워 넣더라도,
  브라우저가 외부로 보내는 요청을 막습니다. 양식 제출(`form-action 'none'`)도 막혀 있습니다.
- 파일을 화면에 끌어다 놓을 때는 칸이 화면 전체로 넓어져 격리된 칸이 파일을 받습니다. 그래도 바깥에 놓인 파일은
  페이지의 다른 스크립트보다 먼저 가로채 버려서 광고 스크립트에 넘어가지 않습니다.

### 3. 필요한 프로그램은 모두 우리 사이트에서

라이브러리, 워커, 글꼴, OCR 언어 데이터를 외부 CDN에서 불러오지 않고 이 사이트에 직접 올려 둡니다.
글꼴·OCR 데이터처럼 큰 파일은 처음 한 번 받을 때 크기를 먼저 알리고 동의를 받습니다. 다음 방문에 다시 받지 않도록
브라우저에 보관하는데, 칸은 받은 데이터를 **빌드 때 적어 둔 SHA-256 값과 크기로 확인한 뒤에만** 씁니다.
바깥 페이지를 거쳐 받더라도 중간에 바뀐 데이터는 쓰지 않습니다.

### 4. 테스트가 약속을 매번 확인

PR마다 도는 E2E 테스트가 도구들로 실제 파일을 처리하면서 나가는 요청을 전부 기록하고, 같은 기준
([`tests/e2e/local-only.ts`](tests/e2e/local-only.ts))으로 확인합니다.

- 도구 칸의 요청은 우리 사이트로 가는, 본문 없는 요청뿐이어야 합니다.
- 바깥 페이지는 정해 둔 방문 통계·광고 주소로만 더 연결할 수 있고, 그 주소와 본문에 테스트 파일의 이름이나
  PDF 내용이 들어 있으면 실패합니다.

### 직접 확인하는 방법

브라우저 개발자 도구(F12)의 **네트워크** 탭을 연 채로 파일을 처리해 보세요. 파일 크기만 한 업로드 요청이 없다는 것을
직접 볼 수 있습니다. 이 저장소는 공개되어 있어 위 내용을 코드로도 확인할 수 있습니다.

### 알아 둘 점

- 광고와 방문 통계는 바깥 페이지에서 동작합니다. 방문 통계는 쿠키 없는 Cloudflare Web Analytics이고, 광고는
  Google AdSense입니다. 자세한 내용은 사이트의 개인정보처리방침에 있습니다.
- 처리 속도와 다룰 수 있는 파일 크기는 내 기기의 성능을 따릅니다.
- 가리기처럼 내용을 지우는 도구는 무엇이 남고 무엇이 지워지는지 각 도구의 화면과 FAQ에 밝혀 두었습니다.

## 개발

Astro(정적 사이트) + Svelte 5 + TypeScript, Cloudflare에 배포합니다.

```sh
npm install
npm run dev        # 개발 서버 http://localhost:4321 (격리·CSP가 꺼져 있음)
npm run build      # dist/에 정적 사이트 생성
npm run preview    # 배포와 같은 방식(격리·CSP 켜짐)으로 미리보기 http://localhost:4322
npm run test:e2e   # 빌드 결과로 E2E (먼저 npm run build)
```
