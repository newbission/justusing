# pdf-n-up — 검증·오류·수정 히스토리

## 요약

- 2026-10-15: 쪽을 그림으로 바꾸지 않고 pdf-lib `embedPages`로 줄여 넣기로 했다 (선명하고 검색 가능). 회전된 쪽은 보이는 방향대로, 내용이 없는 빈 쪽은 pdf-lib가 넣지 못해 칸만 비운다 (`e557775`)
- 2026-10-15: Letter를 골라도 미리보기 종이가 A4 비율이었다 → 화면도 워커와 같은 종이 비율을 쓴다 (`398d58b`, 리뷰 P2)
- 2026-10-15 **큰 오류 (리뷰 P1)**: `embedPages`는 쪽 내용만 옮겨, 작성한 양식 입력값·서명·도장이 결과에서 조용히 빠졌다. 주석 모양을 쪽 내용에 먼저 그려 넣도록(평면화) 했다 (`c4c23d2`, `src/lib/pdf/flatten-annotations.ts`)
- 2026-10-15: 평면화를 다듬은 리뷰 지적이 이어졌다
  - 인쇄 결과이므로 `Print` 플래그가 켜지고 숨김이 아닌 주석만 넣는다 (`e3a5d35`)
  - 모양(/AP) 없이 저장된 입력값은 pdf-lib로 모양을 만든다. pdf-lib가 기본 글꼴에 없는 글자(한글 등)를 **오류 없이 빼 버리므로** 먼저 검사하고, 못 만들면 결과를 막고 알린다 (`9d5effb`)
  - 모양 없는 형광펜·밑줄·취소선은 /QuadPoints로 다시 그리고, 그 밖에 그릴 수 없는 인쇄 주석이 있으면 조용히 빼지 않고 알린다 (`8c859b6`). 물결 밑줄은 물결로, 기울어진 글자는 네 점의 기울기대로 (`2690b7f`, `406154a`)
  - 인쇄되지 않는 입력 칸은 글자 검사에서 뺀다 (`0341e96`). 드롭다운은 표시 문자열이 내보내는 값과 다르면 같은 모양을 못 만들어 알린다 (`8ca4bb9`)
- 배운 점: 쪽 내용만 옮기는 처리는 주석으로 보이는 내용을 잃는다. 결과에서 무엇이 빠질 수 있는지 먼저 따지고, 빠지면 조용히 넘기지 말고 알린다
- 남은 일: 목차 링크처럼 모양 없는 인쇄 링크가 결과를 막는 문제의 수정(`cabf22f` 등)은 `feat/pdf-redact` 브랜치에 있고 아직 dev에 없다
