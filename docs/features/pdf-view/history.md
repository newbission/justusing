# pdf-view — 검증·오류·수정 히스토리

## 요약

- 2026-10-10: 사이트의 첫 도구. pdf.js 준비 모듈(`src/lib/pdf/pdfjs.ts`)을 만들며 워커를 격리 frame용 blob으로 띄우고 CMap·글꼴·wasm을 우리 사이트(`/vendor/pdfjs/`)에서 읽게 했다. 이후 모든 PDF 도구가 이 모듈을 쓴다
- 2026-10-10: pdf.js 6은 문서에 `destroy`가 없어 여는 작업을 닫아야 메모리가 풀린다 → `openPdf()`가 `close()`를 함께 돌려주게 했다 (`72ae119`)
- 2026-10-10 **큰 오류**: 배포 환경에서 암호를 넣어도 열리지 않았다. 원인은 sandbox에 `allow-forms`가 없어 `<form>` 제출이 막힌 것. 개발 서버는 격리가 꺼져 있어 보이지 않았다. 격리를 느슨하게 하지 않고 버튼·Enter 키로 직접 처리했다 (`fb8e603`)
  → 배운 점: 도구는 반드시 빌드 후 배포 방식(wrangler)으로 확인한다 (`CLAUDE.md` 규칙이 됨)
- 2026-10-10: FAQ의 "인터넷을 끊어도 열 수 있다"는 사실이 아니어서 뺐다 (처음 열 때 워커·글자 정보를 받아 옴, `cf6469a`). FAQ에는 실제 동작만 쓴다
- 2026-10-10~11: 휴대폰 폭에서 도구 막대 글자가 두 줄로 접히거나 넘쳤다 → 글자 한 줄 고정, 좁은 화면에서 파일 이름·배율·‹ › 숨김 (`c404d29`, `099569a`)
- 2026-10-11: 열면 도구 칸이 화면을 채우게 스크롤, 전체 화면 버튼(지원 안 하면 숨김) 추가
- 2026-10-11: 여러 파일 보기로 바꿨다. 파일마다 연 암호를 기억하고, 빠르게 바꿔 눌러도 늦게 열린 앞 파일이 화면을 덮지 않게 했다. "다른 파일"은 "파일 추가"로 바꿨다 (`7072660`, `ed9bf60`, `f7490da`)
- 2026-10-11: 합치기·나누기·정리를 공개할 때마다 이 도구 FAQ의 "준비 중" 문장을 고쳐야 했다. 다른 도구를 안내하는 문장은 그 도구 상태가 바뀔 때 같이 본다
