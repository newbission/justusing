## 1. 어떤 기능인지

- PDF를 올리지 않고 브라우저에서 바로 열어 페이지를 넘겨 본다. 보기 전용이다
- 입력: PDF 여러 개 (한 번에 고르거나 끌어다 놓기). 개수 제한 없음
- 출력: 없음 (파일을 만들지 않는다)
- 할 수 있는 것
  - 세로로 이어진 페이지를 스크롤, ‹ › 로 한 쪽씩 이동, 지금 쪽 번호 표시
  - − / + 확대·축소(50~300% 단계), "폭 맞춤"
  - 전체 화면 (지원하지 않는 브라우저에서는 버튼을 숨긴다. 아이폰 사파리 등)
  - 여러 파일: 왼쪽 목록(좁은 화면은 위쪽 고르기 상자)에서 바꿔 보기, "파일 추가", × 로 빼기
  - 암호 PDF: 열 때 암호를 묻는다. 한 번 연 암호는 파일마다 기억해 다른 파일을 보다 돌아와도 다시 묻지 않는다
  - 한글·한자 PDF: CMap을 우리 사이트(`/vendor/pdfjs/`)에서 받아 그린다
- 한계 (FAQ와 같음)
  - PDF 안에 글꼴이 빠져 있으면 비슷한 글꼴로 대신 보일 수 있다
  - 파일 전체를 메모리에 올리므로 메모리가 적은 휴대폰에서는 아주 큰 파일이 느릴 수 있다
  - 고치기·합치기는 하지 않는다 (FAQ가 합치기·나누기·회전·정리 도구를 안내)
  - 처음 열 때 워커·글자 정보를 사이트에서 받아 오므로 "인터넷 없이 열린다"고 쓰지 않는다 (`cf6469a`)

공통 부품: `src/frame/FileDrop.svelte`(첫 화면), `src/frame/drop.ts`의 `onFrameFiles`(어디에 놓든 받기),
`src/frame/parent.ts`의 `requestShowTool()`(열리면 바깥 페이지를 스크롤해 도구 칸이 화면을 채움).

### 처리 흐름

1. `FileDrop`으로 고르거나 frame 어디에 놓는다 → `add(files)`가 바이트를 읽어 목록 끝에 더하고, 더한 것 중 첫 파일을 연다
2. `show(file)` → 보던 문서를 `closeDoc()`으로 닫고 → `load(password)`
3. `openPdf(bytes.slice(), password)`. 암호 오류면 `phase = 'password'`(틀렸으면 안내), 다른 오류면 "열 수 없음"
4. 열리면 모든 쪽의 `PDFPageProxy`를 받아 `PdfPage`로 세로로 늘어놓고 `requestShowTool()`
5. 스크롤할 때 화면 위쪽 1/3 선에 걸친 쪽을 "지금 쪽"으로 잡는다. 배율이 바뀌면 그 쪽을 유지하도록 다시 스크롤한다

### 결정과 이유

- **`bytes.slice()`로 연다**: pdf.js는 받은 버퍼를 워커로 넘겨 비워 버린다. 다른 파일을 보다 돌아와 다시 열 수 있게 복사본을 준다
- **문서를 반드시 닫는다**: pdf.js 6에는 문서 `destroy`가 없고 여는 작업(loading task)을 닫아야 메모리가 풀린다. 그래서 `openPdf()`가 `close()`를 같이 돌려준다 (`72ae119`). 암호 오류·손상 파일이어도 닫는다
- **늦게 열린 파일 버리기**: 빠르게 파일을 바꿔 누르면 앞 파일이 늦게 열려 화면을 덮을 수 있다. 열린 뒤 `current !== target`이면 닫고 버린다 (`ed9bf60`)
- **보이는 쪽만 그린다**: 수백 쪽 문서도 열리게 하려고. 자리는 미리 잡아 스크롤 위치가 흔들리지 않는다
- **"다른 파일" 대신 "파일 추가"**: 여러 파일을 보게 되면서 목록을 비우는 버튼은 맞지 않아, 보던 파일은 두고 더하게 바꿨다 (`f7490da`)
- **도구 막대 높이 48px 고정**: 상태가 바뀌어도 아래가 밀리지 않게. 좁은 화면에서는 파일 이름·배율 숫자를 숨기고(520px 이하), ‹ › 버튼도 숨긴다(400px 이하, 쪽 번호는 남김) (`c404d29`, `099569a`)

### 주의할 점

- **암호 입력에 `<form>`을 쓰지 않는다.** sandbox에 `allow-forms`가 없어 배포에서만 제출이 막혔다. "열기" 버튼과 Enter 키로 직접 처리한다 (`fb8e603`)
- `scrollIntoView` 대신 페이지 목록의 `scrollTop`을 바꾼다 (바깥 페이지까지 스크롤되므로)
- 전체 화면은 frame 문서(`document.documentElement`)에 건다. Esc로 빠져나와도 버튼 상태가 맞도록 `fullscreenchange`로 맞춘다
- 파일 놓기는 도구가 직접 받지 않는다. `onFrameFiles(add)`로만 받는다 (보는 중에 놓으면 목록에 더하고 그 파일로 바뀐다)
- 이 도구의 FAQ는 다른 도구 이름을 안내한다. 도구를 새로 공개할 때 "준비 중" 같은 문장이 남지 않게 한다 (`e41a381`, `c219468`, `995b537`)

## 4. 검증

### 자동 테스트

`tests/e2e/pdf-view.spec.ts`

- PDF를 열면 페이지가 그려지고 이동·확대가 된다
- 파일을 연 뒤의 요청에는 파일이 기기 밖으로 나가는 것이 없다 (`expectLocalOnly`)
- 도구 화면은 출처 없는 격리 frame이다 (sandbox, 바깥과 서로 접근 불가)
- 도구 화면 안에서 외부 연결은 CSP가 막는다
- 한글 PDF가 그려진다 (CMap을 우리 사이트에서 받음)
- 암호 PDF: 틀리면 안내하고, 맞으면 열린다
- PDF가 아닌 파일은 안내 문구를 보여준다
- PDF를 열면 도구 칸이 화면을 채우도록 스크롤된다
- 격리 frame 안에서 전체 화면으로 볼 수 있다
- 여러 PDF를 올려 목록에서 바꿔 보고, 연 암호는 다시 묻지 않는다
- 파일 추가로 목록에 더하고, 빼면 다음 파일을 연다
- 좁은 화면에서는 고르기 상자로 파일을 바꾼다
- 방문 통계 스크립트는 바깥 페이지에만 있고 도구 frame에는 없다

파일 끌어 놓기 전체 흐름은 `tests/e2e/drop.spec.ts`가 본다.
