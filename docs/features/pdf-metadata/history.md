# pdf-metadata — 검증·오류·수정 히스토리

## 요약

- 2026-10-15 처음부터 정한 것: Info에 적고 XMP는 지운다 (보기 프로그램이 XMP를 먼저 읽어 예전 값이 보이는 일을 막음).
  이 작업만 `updateMetadata: false`로 열어 pdf-lib가 만든 프로그램·고친 날짜를 바꾸지 않게 한다.
- 2026-10-15~16 Codex 리뷰가 #61에 23개를 지적했다. 종류로 나누면:
  - 모두 지우기가 덜 지움 (가장 많음): 사용자 정의 Info 키, 쪽·그림·안에 든 사전의 XMP, PieceInfo, LastModified,
    주석 작성자·날짜, 첨부 파일 날짜, `/ID`
  - 지운 값이 파일에 남음: 참조만 끊은 XMP 객체, 고친 기록의 옛 XMP → 저장 전에 닿지 않는 객체를 모두 지우기
    (`removeUnused`, 압축 도구에서 공통 모듈로 옮김). 같이 쓰는 XMP를 바로 지우던 것도 이것으로 함께 고쳤다
  - 읽기: XMP에만 있는 제목·작성자·키워드(`dc:subject`)·만든 프로그램·날짜
  - 날짜: 시간대 반영, 날짜만 있는 XMP 값이 서쪽 시간대에서 전날로 보임, 연도·연월만 있는 값, 축약 PDF 날짜
  - 안내: 암호가 풀린다는 사실(화면·FAQ), XMP와 함께 PDF/A 표시가 지워진다는 사실(FAQ)
- 2026-10-16 배운 점: 숨은 정보 자리를 지적마다 하나씩 더하다가, 규격에서 자리를 모두 찾아 한 번에 지우도록 바꿨다
  (`12a49a2`: 기사 흐름 정보, 서명 사전, 주석 `/NM`, 첨부 파일 Mac 정보, `/SpiderInfo`). 지우는 코드는 처음에
  "어디에 숨을 수 있는가"를 규격에서 다 찾고 시작해야 한다.
- 2026-10-16 pdf-lib는 닿지 않는 객체도 저장한다. 참조를 끊는 것만으로는 파일에서 지워지지 않는다 (가리기와 같은 교훈).
- 고치지 않은 지적: 보통 저장에서 XMP를 지우지 말라 → 의도한 동작으로 두고 FAQ에 밝혔다.
  가리기 링크가 아직 없다 → #58을 먼저 병합하기로 했다.
- 남은 지적 (2026-10-16 기준): 전자 서명이 무효가 된다는 경고, 보이기 층(OCG)의 만든 프로그램 정보 지우기.
- 고칠 때마다 "예전 코드에서는 실패하는" E2E를 같이 넣었다. 결과 바이트에 비밀 글자가 없는지 본다.
