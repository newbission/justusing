## 1. 어떤 기능인지

- PDF의 이름·주민번호·전화번호 같은 개인정보를 검은 상자로 가리고, 가린 글자를 **파일에서 완전히 지운다**.
  편집 프로그램에서 검은 사각형만 덮으면 밑의 글자가 남는 문제를 막는 도구다.
- 입력: PDF 한 개 (암호 PDF는 `SinglePdfTool`에서 암호를 받아 연다)
- 출력: `<원래이름>_가림.pdf` (영어 화면 `_redacted`)
- 할 수 있는 것
  - 쪽 위를 끌어 상자 그리기, 상자 고르기·끌어 옮기기, "가운데에 상자 넣기", "마지막 것 지우기", "모두 지우기"
  - 키보드: 상자를 고른 뒤 화살표로 옮기기(Shift는 크게), Alt+화살표로 크기 바꾸기, Delete로 지우기
  - "찾아서 가리기": 적은 말을 모든 쪽에서 찾아 상자를 한 번에 만든다 (대소문자·생김새가 같은 글자 무시)
- **하지 않는 것·한계** (화면 `note`·FAQ와 같다)
  - 가린 쪽은 쪽 전체가 그림(JPG)이 된다. 그 쪽의 다른 글자도 고르거나 찾을 수 없다 → "PDF 글자 인식"을 권한다
  - 스캔한 쪽은 글자가 그림이라 찾지 못한다. 줄이 바뀌는 곳에 걸친 말도 찾지 못한다
  - 찾은 말은 글자 폭을 어림해 넉넉하게 가린다. 옆 글자가 조금 함께 가려질 수 있다
  - 책갈피·링크·양식(입력 칸)·문서 정보·첨부 파일은 결과에 넣지 않는다.
    양식에 적힌 값과 인쇄되는 주석(메모·서명)은 보이는 모습 그대로 쪽에 그려 넣는다
  - 가리지 않은 쪽과 같이 쓰는 그림·묶음 그림(로고·머리글·워터마크)과 글꼴은 그대로 옮긴다. 그 안을 가리려면 나오는 쪽을 모두 가려야 한다.
    글꼴 파일에는 가린 쪽에서 쓴 글자 모양이 남을 수 있다 (순서·자리는 남지 않음)
  - 서명된 PDF를 열면 서명이 풀린다고 알린다 (`SinglePdfTool`의 `saves`)
  - 가린 쪽이 그림이라 파일이 커질 수 있다 → "PDF 압축"을 권한다

### 처리 흐름

1. 파일 고르기 → `SinglePdfTool`이 pdf.js로 연다. 쪽을 `PageSheet`로 크게 그리고 위에 상자를 겹친다.
   상자 좌표는 화면에 보이는 쪽(회전·CropBox 적용) 기준 비율(0~1)이다 (`RedactBox`)
2. 찾기: `findText()`가 쪽마다 `getTextContent()`를 받아
   - 같은 줄에 이어 놓인 조각을 묶고(방향이 같고, 세로 어긋남 반 글자 미만, 간격 1.5글자 미만, `hasEOL`에서 끊음)
   - 조각 사이가 글자 크기의 0.15배보다 넓고 공백이 없으면 가상 공백 하나를 넣어 잇는다
   - 글자 묶음(grapheme)마다 NFKC → 공백 하나로 → 언어 무관 `toLowerCase()`로 바꾸고, 바꾼 글의 자리가
     원문 어디서 왔는지(`from`·`to`) 적어 둔다 (`folded`)
   - 찾은 부분의 폭은 조각 글꼴 계열(`sans-serif` 등)로 잰 글자 폭 비율로 나누고(`prefixWidths`, 글꼴별 캐시),
     조각 끝에서 멀수록 여유를 넓힌다(`matchSpan`: 높이의 25% + 끝까지 거리의 25%). 아래로 높이의 0.3배 더 덮는다
   - 오른쪽에서 왼쪽으로 쓰는 글자(RTL)가 섞인 조각은 조각 전체를 가린다
3. "가리고 저장" → `canUse('pdf/redact')` 확인 → `redactPdf()`
   - 가린 쪽마다 pdf.js로 200 DPI, `intent: 'print'`로 그린다(화면 스레드, pdf.js가 잘게 나눠 그림)
   - 그림을 그림 저장 워커에 넘겨 상자 자리를 칠하고 JPG(화질 0.9)로 저장한다
4. 고치기 워커(`modify.worker.ts` → `redact()`):
   1. 남길 쪽에 있는 입력 칸만 모양을 만든다(`renderMissingFormAppearances(source, pages)`)
   2. 남길 쪽마다 주석 평면화 → 자원 정리(`prunePage`)
   3. Type3 글꼴은 모든 쪽을 본 뒤 찍은 글자 모양만 남긴다(`finishType3`)
   4. 남길 쪽에 `keepRenderingOnly()`
   5. 원본에서 꺼 둔 보이기 층에 표시를 해 두고(`markLayerStates`) `copyPages`를 **한 번** 부른 뒤,
      새 PDF에 `/OCProperties`를 만들어 꺼진 층은 `/OFF`에 넣는다(`copyLayerStates`)
   6. 원래 쪽 순서대로 복사한 쪽과 그림 쪽(`viewSize` 크기, 원래 `/UserUnit` 유지)을 섞는다
5. 저장 → "다운로드"

### 결정과 이유

- **가린 쪽은 그림으로 바꾼다.** 글자·도형을 골라 지우는 방식은 글꼴 인코딩·겹친 그림 등으로 빠뜨리기 쉽다.
  쪽 전체를 그림으로 바꾸면 그 쪽의 원래 내용이 결과에 들어갈 길이 없다.
- **원래 PDF를 고치지 않고 새 PDF에 남길 쪽만 복사한다.** pdf-lib는 아무도 가리키지 않는 객체도 저장해,
  원래 PDF를 고치면 지운 쪽의 내용이 파일 안에 남는다.
- **`copyPages`는 한 번만 부른다.** 쪽마다 따로 복사하면 같이 쓰는 글꼴·그림이 쪽 수만큼 복제된다.
- **같이 쓰는 자원은 연산자별로 정리한다.** 이름만 모으면 `/F1 Tf`(글꼴)와 `/F1 Do`(그림)를 구분하지 못한다.
  `content-tokens.ts`로 토큰을 나누고 `content-usage.ts`가 연산자마다 자원 종류를 정한다
  (Do→XObject, Tf→Font, gs→ExtGState, sh→Shading, cs/CS→ColorSpace, scn/SCN→Pattern, BDC/DP→Properties).
  연산자 바로 앞의 이름 피연산자만 자원 사용으로 센다. 묶음 그림은 부른 자리의 글꼴·q/Q 상태로 이어 훑는다.
- **Type3 글꼴은 찍은 글자 모양만 남긴다.** 글자 모양(CharProcs)이 다른 쪽의 내용을 담을 수 있다.
  `/Differences`에 없는 코드를 찍었으면 어떤 모양인지 알 수 없어 모두 남긴다.
- **빼는 목록이 아니라 남기는 목록(허용 목록)이다** (`rendering-only.ts`). 처음에는 "이 항목도 빼라"는 지적
  (첨부 파일 `/AF`, XMP `/Metadata`, `/PieceInfo`, `/Alternates`, `/Ref`·`/OPI`, 스트림의 `/F` …)이 올 때마다
  하나씩 더했다. 새 항목이 나올 때마다 샐 수 있어, 쪽에서 시작해 규격 구조를 따라가며 그리기에 쓰는 항목만 남기고
  나머지는 모두 지우도록 바꿨다(`1f30b13`).
- **보이기 층 상태를 옮긴다.** 새 PDF에는 문서 전체 설정이 없어 꺼 두었던 층(숨긴 내용)이 켜진 채로 보였다.
  BaseState·ON·OFF에 볼 때·인쇄할 때 저절로 적용되는 규칙(`/AS`)과 사용 정보(`/Usage` ViewState·PrintState)를 더해 끈다.
  층 조합의 보이기 식(`/VE`)은 층과 함께 옮기고, 꺼진 층에 딸린 주석은 굳힐 때도 같은 층으로 감싼다.
- **가린 쪽과 내용 스트림을 같이 쓰는 쪽도 그림으로 바꾼다** (`SHARED_CONTENT`). 남길 쪽의 내용이 가린 쪽 내용을
  담고 있으면 글자가 남는다. 워커가 그런 쪽 번호를 돌려주면 화면이 그 쪽도 그림으로 그려(`plain`, 칠할 자리 없음)
  다시 보낸다. 내용이 깨져 훑을 수 없는 쪽도 같은 길로 그림이 된다.
  처음에는 닿는 스트림 전체(그림·묶음 그림 포함)를 견줬는데, 로고 하나를 같이 쓰는 모든 쪽이 그림이 되어 내용 스트림만 견주게 줄였다.
  그래서 같이 쓰는 그림·글꼴은 옮겨지고, 이 한계를 FAQ·가이드에 밝혔다.
- **기본 회색 색공간(`/DefaultGray`)은 장치 회색으로 칠할 때만 쓴 것으로 센다.** 칠하는 색 상태를 q/Q와 함께 따라간다.
- **Type3 글꼴의 기본 인코딩은 pdf.js 표를 쓴다** (`base-encodings.ts`). 알려진 인코딩이면 찍은 글자 모양만 남긴다.
- **고치지 않은 지적: 쪽 그리기를 워커로 옮기기.** pdf.js `page.render()`가 일을 잘게 나눠 화면에 차례를 넘기고
  (진행 표시가 계속 갱신됨), 무거운 해석은 이미 pdf.js 워커에서 한다. 옮기려면 공통 그리기 구조를 크게 바꿔야 한다.
  칠하기와 JPG 저장은 워커로 옮겼다.

### 주의할 점

- 남길 쪽에 새 항목을 남기고 싶으면 `rendering-only.ts`의 자리(Role) 표에 더한다. 모르는 항목은 지워지는 것이 정상이다.
  더할 때는 그 항목이 다른 쪽 자료를 가리킬 수 없는지 먼저 따진다.
- 색공간 이름은 내용에 나오지 않고 사전 안에서 불릴 수 있다 (`usedThroughNames`): 그림·음영·무늬의 `/ColorSpace`,
  `/Group /CS`, 마스크 그림, 색공간 배열 안(Indexed 기본, Separation·DeviceN 대체, Pattern 바탕, ICC `/Alternate`),
  `/DefaultGray`·`/DefaultRGB`·`/DefaultCMYK`(늘 남김). 별색 이름(`/Gold`)은 자원이 아니다.
- 묶음 그림은 깊이로 자르지 않고, 지금 훑는 묶음 그림을 다시 부를 때만 멈춘다.
- 바로 써 넣은 그림(BI … ID … EI)의 바이트 안 `EI`를 끝으로 착각하지 않게 `/L`·크기로 길이를 재거나,
  ASCII85(`~>`)·ASCIIHex(`>`) 끝 표시를 본다 (`content-tokens.ts`).
- 가린 쪽은 `intent: 'print'`로 그린다. 남길 쪽의 평면화도 인쇄되는 주석만 넣으므로 기준을 맞춘다.
- `flatten-annotations.ts`의 링크 처리는 모아찍기도 같이 쓴다 (`tests/e2e/pdf-n-up.spec.ts`).
- `content-tokens.ts`는 사진 꺼내기 도구와 같이 쓴다. 바로 써 넣은 그림의 끝은 DCT(EOI)·LZW(EOD, EarlyChange)·
  RunLength(EOD)·Flate(실제로 풀어 봄)로 찾는다.

## 4. 검증

### 자동 테스트

- `tests/e2e/pdf-redact.spec.ts` (브랜치에만 있음). 결과 파일의 모든 스트림을 풀어 숨긴 글자가 없는지 본다
  - 찾거나 그려 가린 쪽의 글자는 파일에서 지워지고 다른 쪽은 그대로다 (`expectLocalOnly`)
  - 같이 쓰던 자원과 링크를 타고 가린 쪽의 내용이 딸려 오지 않는다
  - 키보드로 상자를 넣고 옮기고 지운다
  - 찾기: 폭이 다른 글자가 섞인 줄, 소문자로 바꾸면 길어지는 글자 뒤, RTL 조각, 글꼴이 바뀌어 나뉜 조각,
    공백 없이 띄워 놓은 조각, 합자·자모로 나눈 한글·줄 안 띄움 공백
  - 자원 정리: 같은 이름의 글꼴과 그림, 남길 쪽들이 같이 쓰는 그림은 한 번만, 나뉜 내용 스트림, 기본 색공간,
    물려받는 묶음 그림, 자기 자원 묶음 그림, 깊이 겹친 묶음 그림, 투명 마스크 묶음 그림, 그래픽 상태(gs) 글꼴
  - Type3: 남길 쪽에서 찍은 글자 모양만, 기본 인코딩, 물려받은 글꼴로 찍은 글자, gs로 바꾼 글꼴은 세지 않음
  - 색공간: 이름으로 부르는 색공간, 배열 안 색공간, 색공간 정의가 부르는 색공간, 별색 이름은 남기지 않음,
    바로 써 넣은 색 목록 그림의 기본 색공간, 투명도 묶음의 색공간
  - 빠져야 하는 것: 그림의 첨부 파일·XMP·대체 그림·마스크 그림 XMP, 묶음 그림의 다른 PDF 연결, 스트림의 `/F`
  - 내용 토큰: 바로 써 넣은 그림 바이트 속 `EI`, ASCII85 그림 바이트
  - 가리는 쪽에만 있는 모양 없는 한글 입력 칸은 막지 않는다
  - 가린 쪽은 인쇄할 때 보이는 주석만 그림에 넣는다
  - 큰 도면 쪽의 `UserUnit`, 원본에서 꺼 둔 보이기 층
- `tests/e2e/pdf-n-up.spec.ts`: 모양·테두리 없는 링크는 건너뛰고, 모양이나 테두리(점선 포함)를 정한 링크는 그려 넣는다
