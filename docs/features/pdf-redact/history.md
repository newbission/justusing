# pdf-redact — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-15 처음부터 정한 것: 가린 쪽은 칠한 그림(JPG)으로 바꾸고, 원래 PDF를 고치지 않고 남길 쪽만 새 PDF에 복사한다.
  pdf-lib는 아무도 가리키지 않는 객체도 저장해, 원래 PDF를 고치면 지운 쪽의 내용이 파일에 남기 때문이다.
- 2026-10-15~16 Codex 리뷰가 #58에 47개를 지적했다. 종류로 나누면:
  - 같이 쓰는 자원으로 새는 길 (가장 많음): 묶음 그림·무늬·투명 마스크 안의 자원 목록, 이름만 보고 종류를 섞음,
    물려받는 자원, 깊이 한도, 색공간 이름을 사전 안에서 부르는 자리, Type3 글자 모양 → 연산자별 정리(`content-usage.ts`)와
    재귀 정리, Type3는 찍은 글자 모양만 남기기로 고쳤다
  - 내용 토큰 읽기: 바로 써 넣은 그림 바이트 속 `EI`, ASCII85 끝 표시, 연산자 앞 이름만 세기 → `content-tokens.ts`
  - 보이지 않는 항목으로 새는 길: 첨부 파일·XMP·PieceInfo·대체 그림·다른 PDF 연결·바깥 파일 연결
  - 찾기 정확도: 비례 글꼴 폭, 소문자로 바꾼 뒤 위치, 브라우저 언어, RTL, 조각 잇기, 가상 공백, NFKC
  - 그 밖: 링크 평면화, 가린 쪽의 입력 칸 검사, 쪽 복사 한 번, 인쇄용 주석 기준, `/UserUnit`, 보이기 층 상태
- 2026-10-16 배운 점: "이 키도 빼라"는 지적이 끝없이 이어져, 빼는 목록을 버리고 그리기에 쓰는 항목만 남기는
  허용 목록(`rendering-only.ts`, `1f30b13`)으로 바꿨다. 새 항목이 나와도 처음부터 남지 않는다.
  유출을 막는 코드는 허용 목록으로 시작해야 한다.
- 2026-10-16 원본에서 꺼 둔 보이기 층(OCG)이 새 PDF에서 켜져 숨긴 내용이 보이던 것을 고쳤다 (`b7e3b40`).
  새 PDF를 만들면 문서 전체에 딸린 설정이 빠진다는 점을 따로 챙겨야 한다.
- 2026-10-16 고치지 않은 지적: 쪽 그리기를 워커로 옮기기. pdf.js가 이미 잘게 나눠 화면에 차례를 넘기고,
  옮기려면 공통 그리기 구조를 크게 바꿔야 한다. 칠하기·JPG 저장만 워커로 옮겼다 (`06ae75b`).
- 고칠 때마다 "예전 코드에서는 실패하는" E2E를 같이 넣었다. 결과 파일의 모든 스트림을 풀어 비밀 글자가 없는지 본다.
