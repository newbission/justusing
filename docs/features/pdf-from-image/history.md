# pdf-from-image — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-14 이미지 한 장이 한 쪽. JPG·PNG는 원본 바이트를 그대로 넣어 화질 손실이 없고, 그 밖 형식만 PNG로 다시 저장한다.
- 2026-10-14 휴대폰 사진은 화소가 누워 있고 EXIF 방향 표시만 있어, 그대로 넣으면 PDF에서 눕는다. EXIF 방향(0x0112)을 직접 읽어 방향이 있는 사진만 세워 JPG로 다시 저장한다.
  E2E는 쪽 크기뿐 아니라 PDF 안 이미지의 `/Width`·`/Height`까지 확인해 "누운 화소를 늘려 넣지 않았음"을 본다.
- 2026-10-14 큰 휴대폰 사진을 화면 canvas에서 다시 저장하면 멈췄다 (Codex 지적). 워커가 File을 직접 읽어 세우고 PDF까지 만든다. File을 넘기므로 바이트 복사도 없다.
- 2026-10-14 읽는 중인 이미지가 결과 비교에 들어가지 않아, 이미지를 더한 직후 이전 다운로드를 누르면 새 이미지가 빠진 PDF를 받았다. 서명에 읽는 중인 항목도 넣었다.
- 2026-10-14 시작할 때 쪽 크기·여백을 고정하고, 읽는 중에 뺀 이미지는 썸네일 Blob URL을 만들지 않는다 (해제할 곳이 없어 남는다).
- 2026-10-14 썸네일 그림자를 `--shadow-page` 토큰으로 옮겼다 (PDF 썸네일도 같이).
