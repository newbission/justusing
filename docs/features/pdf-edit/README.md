## 1. 어떤 기능인지

- PDF 쪽 위에 **글자 상자**, **흰색 가리기**, **형광펜**을 더한다. 가리고 그 위에 고쳐 쓰는 것이 주된 쓰임이다
- 입력: PDF 하나. 글자를 넣을 때만 글꼴이 필요하다 (가리기·형광펜만이면 받지 않아도 된다)
- 출력: `<원래 이름>_편집.pdf` (영어 화면 `_edited.pdf`)
- 편집 도구 네 가지: 고르기·옮기기 / 글자 넣기 / 흰색으로 가리기 / 형광펜

| 넣는 것     | 넣는 법                          | 고칠 수 있는 것                                         |
| ----------- | -------------------------------- | ------------------------------------------------------- |
| 글자 상자   | 글자 도구로 쪽 위를 누름         | 글자(여러 줄), 크기 4~200pt(기본 14), 색 검정·파랑·빨강 |
| 흰색 가리기 | 끌어서 사각형                    | 자리·크기                                               |
| 형광펜      | 끌어서 사각형 (노랑, 진하기 0.4) | 자리·크기                                               |

- 키보드: "가운데에 … 넣기" 버튼으로 쪽 가운데에 넣고, 화살표로 옮기고(Shift는 크게), Alt+화살표로 사각형 크기,
  Delete로 지운다. Tab으로 옮겨 가기만 해도 고른 상태가 된다
- **하지 않는 것·한계** (화면·FAQ와 같게)
  - PDF 안의 **원래 글자를 직접 고치지 못한다**. 흰색으로 가리고 위에 새 글자를 쓴다
  - **흰색 가리기는 위에 흰 사각형을 덮을 뿐이라 아래 글자가 파일에 남아** 복사·검색될 수 있다.
    가리기 도구를 고르면 화면에 경고(`whiteoutNote`)가 뜨고 FAQ·가이드에도 밝힌다. 개인정보 지우기에 쓰지 말라고 안내
  - 서명·도장·이미지는 "PDF 서명 넣기"·"PDF 이미지 넣기"를 쓴다
  - 결과 PDF에는 원본 암호가 남지 않는다

### 처리 흐름

1. PDF를 연다. 처음 도구는 "글자 넣기"
2. 쪽 위 조작 (`onSheetDown`·`onItemDown`·`onMove`·`onUp`)
   - 글자 도구: 누른 자리에 빈 글자 상자를 만들고 아래 입력 칸으로 간다. 빈 글자 상자는 놓을 때 버린다
   - 가리기·형광펜: 끈 범위로 사각형. 쪽 비율 0.01(`MIN_RECT`)보다 작으면 실수로 보고 버린다
   - 고르기: 넣은 것을 끌어서 옮긴다. 쪽을 넘기면 고른 것을 놓는다
3. 자리는 모두 **화면에 보이는 쪽 기준 비율**(0~1, 왼쪽 위 0,0)로 둔다. 글자 크기만 pt
4. "편집한 PDF 만들기" → `canUse('pdf/edit')` → `editPdf({ items, font? })`
   - 빈 글자 상자는 빼고 넘긴다(`cleaned`). 글자 상자가 있을 때만 글꼴 바이트(400 굵기)를 넘긴다
5. 워커 `drawEdits()`
   - **사각형을 먼저, 글자를 나중에** 그린다 (가린 자리 위에 새 글자가 보이게)
   - 글자: 줄마다 `drawText`, 첫 줄 바닥선 = 위 + 크기 × `BASELINE`, 줄 간격 `LINE_HEIGHT`. 크기는 `/UserUnit`으로 나눈다
   - 사각형: 흰색은 `rgb(1,1,1)`, 형광펜은 `HIGHLIGHT` 색·진하기. 쪽 회전만큼 돌려 그린다
   - 넣을 글자가 없으면 글꼴 없이 그대로 저장한다
6. 결과 `signature` = 넣은 것 JSON + (글자가 있으면) 글꼴 id

### 결정과 이유

- 편집도 글꼴이 필요해 글자 넣기 워커(`text-pdf.worker.ts`)에 `edit` 작업을 더했다 (`02f4f28`)
- 글자를 늘 사각형 위에 그리는 것은 **의도한 동작**이다 (가린 자리에 고쳐 쓰기, 형광펜이 글자를 흐리게 덮지 않게).
  리뷰에서 "미리보기와 같은 순서로"라는 지적에 저장 쪽은 두고 **미리보기를 저장과 같게** 맞췄다 (`.item.text { z-index: 1 }`)
- 글자 도구에서는 사각형이 눌림을 받지 않는다(`.mode-text .item.rect { pointer-events: none }`).
  가린 자리를 누르면 사각형이 옮겨지기만 하던 문제를 고쳤다 (주된 쓰임이 "가리고 고쳐 쓰기")
- 가리기·형광펜 도구에서는 넣은 것 모두 눌림을 받지 않는다 (위에서 새로 그릴 때 기존 것이 옮겨지지 않게)
- 미리보기 글자 상자는 CSS 줄 높이 때문에 워커와 바닥선이 다르다. `TEXT_SHIFT`만큼 올려 맞춘다
- 글자 크기 칸: 범위(4~200) 밖이나 빈 값은 쓰이지 않으므로 칸을 떠날 때(`change`) 실제로 쓰는 크기로 되돌린다
- 진짜 지우기(아래 내용 삭제)는 이 도구에 넣지 않고 따로 만든다 ("가리기(영구 삭제)" 도구, `CLAUDE.md` 8단계)

### 주의할 점

- 미리보기 순서(CSS)와 워커 그리기 순서(`drawEdits`의 정렬)는 함께 고친다. 둘 다 서로를 가리키는 주석이 있다
- 화면 경고·FAQ·가이드의 "흰색 가리기는 아래 내용이 남는다"는 문구는 동작이 바뀌지 않는 한 지우지 않는다
- `LINE_HEIGHT`·`BASELINE`을 바꾸면 미리보기와 결과가 함께 바뀐다 (`edit-constants.ts` 한 곳)
- 키보드 조작 안내(`keys`)와 FAQ의 키 설명은 실제 키(`onItemKey`)와 맞춘다

## 4. 검증

### 자동 테스트

`tests/e2e/pdf-edit.spec.ts` (결과 첫 쪽의 글자와 채우기 연산 수를 pdf.js로 센다)

- `글자를 넣고 흰색으로 가리고 형광펜을 칠한다` — 두 줄 한글 글자, 가리기 경고 문구, "3개를 PDF에 넣습니다.",
  결과 이름 `three-pages_편집.pdf`, 원래 글자와 새 글자, 사각형 2개 이상, `expectLocalOnly`
- `가리기만 하면 글꼴 없이 만들고, 키보드로 지울 수 있다` — Delete로 하나 지우고 글꼴 없이 결과 만들기
- `가린 자리를 글자 도구로 누르면 그 위에 새 글자 상자를 만든다`
- `키보드만으로 사각형을 넣고 크기를 바꾼다` — "가운데에 가리기 넣기" + Enter, 새 사각형에 포커스, Alt+→로 넓어지고 Shift+↑로 올라감
- `Tab으로 옮겨 가기만 해도 고르고, 잘못된 글자 크기는 되돌린다` — 포커스로 "고른 것" 칸이 열림, 500을 적고 떠나면 원래 값
- `글자를 넣었는데 글꼴이 없으면 받으라고 알린다` — 안내 문구와 버튼 꺼짐
