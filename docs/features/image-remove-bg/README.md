## 1. 어떤 기능인지

- 사진에서 사람·상품·동물만 남기고 배경을 지운다 ('누끼 따기'). 쇼핑몰 상품 사진, 발표 자료에 얹을 그림, 반려동물 스티커에 쓴다
- 입력: 사진 한 장 또는 여러 장 (브라우저가 읽는 형식, HEIC는 libheif로 연다)
- 출력: 투명 배경이면 `<원래 이름>_배경제거.png`, 색 배경이면 `.jpg` (영어 `_no-bg`). 원본과 같은 가로·세로.
  "물체에 맞춰 자르기"를 고르면 남은 곳 둘레(긴 변의 1% 여백)만. 여러 장이면 ZIP 하나(`이미지_배경제거.zip`, 영어 `background-removed-images.zip`),
  받을 수 있는 사진이 한 장뿐이면 그 파일 하나
- 할 수 있는 것
  - 사진 가운데의 물체를 저절로 남긴다. "물체 고르기"로 다른 곳을 누르면 그 물체도 남긴다 (누른 곳마다 나눠 겹침)
  - "지우개"·"되살리기" 붓 (지름은 사진 긴 변의 1~12%), "되돌리기"(Ctrl+Z), "처음부터"
  - 가장자리: 좁히기·넓히기(−5~+5), 부드럽게(0~5)
  - 배경: 투명(PNG)·흰색·다른 색(JPG, 화질 0.92)
  - 키보드: 미리보기 칸에서 방향키로 자리(십자)를 옮기고 Enter로 그 도구를 쓴다
  - 여러 장 (2026-10-24): 목록(결과 그림 칸)에서 사진마다 가운데 물체를 미리 남겨 보여 준다. "고치기"로 들어가 위의 고치기를 그대로 쓰고
    ("이전 사진"·"다음 사진"·"목록으로"), 누른 곳·붓질·되돌리기는 사진마다 따로 기억한다. 가장자리·배경·물체에 맞춰 자르기는 모든 사진에
    같이 쓰고, 고치는 화면의 "이 사진만 따로 정하기"로 그 사진만 따로 정한다. "모두 받기 (ZIP, n장)", 저장 중 진행 n/N과 "그만두기".
    한 장만 넣으면 지금처럼 바로 고치는 화면이 나온다
- **하지 않는 것·한계** (화면·FAQ·가이드에 같게 밝힘)
  - 머리카락·털 끝을 한 올씩 반투명하게 나누지 못한다 (경계를 찾는 모델이라 뭉개지거나 조금 잘린다)
  - 유리·비닐처럼 비치는 물체는 잘 안 되고, 반투명하게 남기지 못한다 (남기거나 지우거나)
  - 여러 장은 사진 가운데를 누른 것으로 미리 나눈다 (물체가 한쪽에 치우친 사진은 열어서 눌러야 한다)
  - 휴대폰 메모리: 받을 결과(PNG는 1,200만 화소 한 장에 10MB 안팎)를 모두 메모리에 모았다가 ZIP으로 묶는다. FAQ·가이드에 10장 안팎씩 나눠 받으라고 밝힌다
  - 그림자는 대개 지워진다 (그림자를 남기려면 "되살리기")

### 처리 흐름

1. 사진 고르기 → 도구 화면(`Workspace`)을 불러온다. 한 장이면 바로 고치는 화면, 여러 장이면 목록. 목록의 사진은 `CutoutJobs`가 워커에서 읽어
   크기와 목록 그림 바탕(긴 변 320)을 만든다 (화면 스레드에서 원본을 풀지 않는다. 고치는 화면에 연 사진은 그 화면이 읽은 것을 쓴다).
   고치는 화면을 열면 사진 워커(`CutoutPhoto`)가 바로 세워 읽고(EXIF 방향) 미리보기(긴 변 1600)와 나누기용 사진(긴 변 1024)을
   넘긴 뒤 원본은 버린다. 남길 곳은 사진마다 가운데 한 점으로 시작한다
2. 데이터가 보관돼 있으면 바로, 없으면 "데이터 받기"(엔진 13.5MB + 모델 6.2MB, 증명사진에서 엔진을 받았으면 모델만) 뒤에
   물체 나누기 워커를 띄우고 나누기용 사진의 사본을 넘긴다
3. 데이터가 준비되면 목록의 사진마다 미리 나눈다 (`pump`, 동시에 CPU 수에 맞춘 1~3장). 데이터가 이미 있으면 읽을 때 나누기용 사진(긴 변 1024)도
   함께 만들어 한 번만 풀고, 물체 나누기 워커에 사진 번호와 함께 넘긴다
4. 물체 나누기 워커는 사진 한 장만 든다. 요청마다 사진 번호(photo)를 받아, 들고 있는 사진이 아니면 사진을 함께 보내라고 답한다(`stale` → 화면이
   사진을 붙여 다시 묻는다). 점마다 `segment(image, { keypoint })` → 물체일 가능성(0~255, 나누기용 사진 크기)을 기억해(사진이 바뀌면 비움)
   다시 나누지 않고, 모두 겹쳐(최댓값) 남은 곳 비율과 함께 화면에 준다. 엔진은 한 번에 하나씩 돈다(화면 쪽 줄 `ObjectFinder.segment`).
   화면은 결과를 요청한 그 사진(`Entry`)에만 넣고, 그사이 남길 곳이 바뀌었으면 버리고 다시 나눈다. 남은 곳이 0.2%보다 적으면 "찾지 못했습니다"
5. 고치는 사진이면 마스크 사본을 사진 워커에 사진 번호와 함께 넘기고, 사진 워커가 미리보기를 그린다 (`paint`). 목록 그림은
   `CutoutJobs`가 바탕·마스크 사본·모양을 받아 그린다 (물체에 맞춰 자르기는 빼고)
   - `refine`: 넓히기·좁히기(단계마다 나누기용 사진 긴 변의 1/256, 네모 최대·최소 거름) → 부드럽게(상자 흐림 두 번) →
     투명도 (부드럽게 0이면 확신 35~65%만 비례로, 나머지는 다 남기거나 다 지움)
   - 투명도 그림을 결과 크기로 늘려 깔고(선형 보간), 붓질을 차례로(지우개 `destination-out`, 되살리기 `source-over`),
     그 모양대로 사진을 남긴다(`source-in`). 색 배경이면 뒤에 칠한다(`destination-over`)
   - "물체에 맞춰 자르기"면 붓질까지 반영한 남은 곳 칸을 나누기용 크기에서 찾아 점선으로 보여 준다
6. 저장: `CutoutJobs`가 그 사진의 파일·마스크 사본·모양을 한꺼번에 받아 원본을 다시 읽고 같은 `paint`를 원본 크기로 그린다.
   canvas 하나에 못 그리면 줄 묶음씩 그려 PNG·JPG를 이어 쓴다 (`saveDrawing`). 여러 장은 워커 수만큼 나란히 저장해 모은 뒤 `makeZip`.
   한 장이 실패하면(지우개로 다 지워 남은 곳이 없음, 너무 커서 못 그림) 그 장만 빼고 받고 뺀 장수를 알린다.
   "그만두기"는 기다리는 일을 빼고 하던 워커를 끝낸다

### 결정과 이유

- **모델 비교** (2026-10-23, Chrome, 사진 7장: 모래 위 슬리퍼, 회색 배경 운동화, 나뭇가지 앞 고양이, 회색 배경 꽃,
  포도밭 앞 유리잔, 흰 배경 사람 2장(AI 가상 인물·NASA 공개 사진). 누른 곳은 모두 사진 가운데)

  | 후보                                                                   | 크기                                       | 허가                               | 결과                                                                                                                                  |
  | ---------------------------------------------------------------------- | ------------------------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
  | MediaPipe Selfie Segmenter (증명사진이 이미 씀)                        | 0.25MB                                     | Apache-2.0                         | 사람 2장은 됐고 고양이는 아래 담장이 조금 남았다. 운동화·꽃은 거의 다 지웠고 슬리퍼는 그림자까지 남겼다. 사람 전용이라 상품에 못 쓴다 |
  | **MediaPipe MagicTouch** (`interactive_segmenter` v1, float32)         | **6.2MB** (+ 엔진 13.5MB, 증명사진과 같음) | **Apache-2.0** (모델 카드)         | 유리잔 빼고 모두 깔끔했다 (운동화·꽃·고양이·사람). 슬리퍼는 한 짝이 흐리게 남았다. 한 번 나누기 0.12초 안팎                           |

  | RMBG-1.4 (BRIA)                                                        | 44MB(int8)~176MB                           | 상업적 사용에 별도 계약            | 허가 때문에 뺐다                                                                                                                      |
  | BiRefNet·IS-Net(DIS)                                                   | 100MB 넘음                                 | MIT·Apache-2.0                     | 너무 커서 뺐다                                                                                                                        |
  - MagicTouch로 정했다. 증명사진이 이미 받는 엔진으로 돌아 사이트에 새 실행 엔진이 늘지 않고, 처음 받는 양도 엔진을
    받아 둔 사람은 6.2MB다. 사람용(작음)·모든 물체(큼) 고르기는 두지 않았다. MagicTouch가 사람도 Selfie Segmenter만큼
    나눠 한 모델로 충분했다
  - 누른 곳을 고르는 모델이라 '알아서 주인공 찾기'는 하지 않는다. 처음에는 가운데를 누른 것으로 하고, 다른 물체는 눌러 더한다

- 나누기는 긴 변 1024 사진으로 한다. 모델은 512로 줄여 보므로 더 크게 넣어도 경계가 좋아지지 않고, 마스크만 커진다.
  원본에는 마스크를 늘려 씌운다 (원본 화소는 그대로)
- 붓질은 사진 비율 좌표·지름(긴 변 비율)으로 둔다. 미리보기·원본·줄 묶음 어디에 그려도 같은 자리다
- 워커를 나눈다: 물체 나누기 워커(엔진), 고치는 사진의 미리보기 워커, 읽기·목록 그림·저장 워커(여러 개). 큰 사진 때문에 사진 워커가 죽어도 엔진은 살아 있다.
  엔진 워커가 죽으면 엔진을 버리고 "다시 해 보기"에서 보관본으로 다시 띄운다
- 여러 장 (2026-10-24)
  - 한 장씩 남길 곳을 보며 고치는 장점은 그대로 두고, 미리 나눈 결과를 목록에서 훑어 잘못된 것만 고치게 했다
  - 설정은 '모두에 같이 + 이 사진만 따로'로 했다. 설정은 다섯 값(넓히기·부드럽게·배경·색·자르기)뿐이라 사진마다 사본(`Settings`)을
    하나 더 들면 되고, 화면도 고치는 화면에 확인란 하나라 구조가 크게 늘지 않았다. 배경색이 다른 사진, 가장자리를 따로 다듬을 사진이 실제로 있다
  - 메모리: 사진마다 드는 것은 마스크(나누기용 크기, 1024×768이면 0.75MB)와 목록 그림 둘(긴 변 320)뿐이다. 원본·미리보기는 고치는 사진 한 장만,
    원본은 저장하는 동안만 워커가 든다. 동시 저장은 `jobLimit()`(CPU 수 − 1, 1~3)
  - 데이터 받기는 그대로다. frame 첫 화면 JS는 오히려 줄었다 (gzip 42.2 → 34.6KB): 목록·고치기·저장 화면(`Workspace`, gzip 11.8KB)을 사진을 고를 때
    불러온다. ZIP 워커는 받을 때 띄운다
  - 목록은 `ImageBatch`를 쓰지 않는다. 그것은 화면 스레드에서 사진을 원본 크기로 한 번 풀고(HEIC는 libheif로 한 번 더), 한 장일 때 고치는 화면의
    풀기와 겹쳐 큰 사진의 순간 메모리가 두 배가 됐다
- 기본 부드럽게는 0: 1로 두니 상품 사진 테두리에 탁자 색이 2~3화소 비쳤다
- 투명 배경은 PNG, 색 배경은 JPG로 정했다 (형식 고르기를 따로 두지 않음). 흰 배경 상품 사진은 JPG가 흔하고 작다

### 주의할 점

- 늦게 끝난 예전 사진의 나누기 결과를 쓰지 않는다 (리뷰 P1, 여러 장에서 같은 종류를 모두 막음)
  - 점마다 나눈 결과는 물체 나누기 워커만 사진별로 기억하고(새 사진을 받으면 비움), 화면 쪽에 점별 기억을 두지 않는다 (다른 사진의 가운데 점과 겹친다)
  - 물체 나누기·사진 워커 요청에는 늘 사진 번호를 붙이고, 워커가 들고 있는 사진과 다르면 쓰지 않는다. 사진 바꾸기와 나누기는 한 요청으로 보낸다
    (따로 보내면 다른 사진의 요청이 사이에 끼어든다)
  - 결과는 요청한 `Entry`에만 넣는다. 고치는 화면에는 `photo.entry === entry`일 때만, 마스크 판(`maskVersion`)이 그대로일 때만 넘긴다
  - 저장은 파일·마스크 사본·모양을 한 요청에 담아 보낸다 (워커의 상태에 기대지 않는다)

- 마스크(`Mask`)의 첫 번째 확신 마스크가 '누른 물체'다 (모델 카드: 배경·물체 두 갈래를 softmax). 순서를 바꾸면 거꾸로 지운다
- 데이터 동의 이름은 `cutout`이지만 엔진 파일은 증명사진(`face`)과 같은 주소다. 보관소는 주소로 보관하므로 엔진은 한 번만 받는다.
  `missingData`가 보관 안 된 파일만 세서 "모델만 받는다"를 알린다
- `points[0] === CENTER`(같은 객체)로 '가운데를 저절로 남김' 안내를 고른다. 처음부터를 누를 때도 `CENTER`를 그대로 넣는다
- 체크무늬는 두 테마 모두 밝게 그린다 (`--color-paper` 기준). 어두운 칸이면 어두운 물체와 헷갈린다
- 격리 frame 규칙(워커는 `createWorker`, `style=""` 금지, form 금지)은 [격리 frame](../../foundations/frame-isolation/README.md)

### 자동 테스트

- `tests/e2e/image-remove-bg.spec.ts`
  - 데이터 받기 전에는 다운로드를 막고 크기를 밝힌다 → 받으면 가운데 사람만 남긴 800×1200 PNG. 배경 쪽 네 곳은 투명(알파 16 미만),
    얼굴·옷 쪽은 불투명(240 넘음). 파일 이름 `portrait_배경제거.png`. 받은 데이터는 엔진·모델 둘뿐, googleapis 요청 없음.
    다시 들어오면 묻지 않고 바로 나눈다
  - "다른 색"(#ff0000) JPG: 배경 쪽이 빨강, 사람 쪽은 원래 색. 흰색 + "물체에 맞춰 자르기": 세로가 줄고 귀퉁이가 흰색
  - 키보드: "지우개"를 고르고 방향키·Enter로 옷 한가운데를 칠하면 그곳이 투명, Ctrl+Z로 되돌리면 다시 불투명
  - 열 수 없는 파일은 알린다
  - 아이폰 사진(`iphone.heic`, 크롬은 libheif 경로)을 바로 세운 300×400으로 연다
  - 여러 장: 견본 머그잔·견본 증명사진·face.jpg 3장 → ZIP 안 파일 3개와 이름, 사진마다 배경 투명·물체 불투명. 흰 배경을 모두에 주면 모두 JPG
  - 한 장만 고치기: face.jpg에 지우개 한 번 + "이 사진만 따로 정하기"로 파란 배경 → 다음 사진에는 붓질이 없고, 돌아오면 남아 있다.

  - 섞이지 않기: 두 장을 나눈 뒤 두 장을 더 넣고 바로 뒤 사진을 연다 → 그 사진 한 장 받기와 ZIP 4장 모두 제 사진의 배경·물체
  - 그만두기: 6000×4500 사진 두 장을 저장하다 "그만두기" → 받지 않고 "모두 받기"가 다시 켜진다
  - 다 지운 사진: 머그잔을 가장 큰 지우개로 모두 지우면 그 장만 빠진 ZIP(2장)과 "1장은 … 뺐습니다"
