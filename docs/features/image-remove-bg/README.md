## 1. 어떤 기능인지

- 사진에서 사람·상품·동물만 남기고 배경을 지운다 ('누끼 따기'). 쇼핑몰 상품 사진, 발표 자료에 얹을 그림, 반려동물 스티커에 쓴다
- 입력: 사진 한 장 (브라우저가 읽는 형식, HEIC는 libheif로 연다)
- 출력: 투명 배경이면 `<원래 이름>_배경제거.png`, 색 배경이면 `.jpg` (영어 `_no-bg`). 원본과 같은 가로·세로.
  "물체에 맞춰 자르기"를 고르면 남은 곳 둘레(긴 변의 1% 여백)만
- 할 수 있는 것
  - 사진 가운데의 물체를 저절로 남긴다. "물체 고르기"로 다른 곳을 누르면 그 물체도 남긴다 (누른 곳마다 나눠 겹침)
  - "지우개"·"되살리기" 붓 (지름은 사진 긴 변의 1~12%), "되돌리기"(Ctrl+Z), "처음부터"
  - 가장자리: 좁히기·넓히기(−5~+5), 부드럽게(0~5)
  - 배경: 투명(PNG)·흰색·다른 색(JPG, 화질 0.92)
  - 키보드: 미리보기 칸에서 방향키로 자리(십자)를 옮기고 Enter로 그 도구를 쓴다
- **하지 않는 것·한계** (화면·FAQ·가이드에 같게 밝힘)
  - 머리카락·털 끝을 한 올씩 반투명하게 나누지 못한다 (경계를 찾는 모델이라 뭉개지거나 조금 잘린다)
  - 유리·비닐처럼 비치는 물체는 잘 안 되고, 반투명하게 남기지 못한다 (남기거나 지우거나)
  - 여러 장 한꺼번에·ZIP은 없다. 사진마다 남길 곳을 보고 고쳐야 해서 한 장씩 다룬다
  - 그림자는 대개 지워진다 (그림자를 남기려면 "되살리기")

### 처리 흐름

1. 사진 고르기 → 사진 워커가 바로 세워 읽고(EXIF 방향) 원본을 들고 있다. 화면에는 미리보기(긴 변 1600)와
   나누기용 사진(긴 변 1024)을 넘긴다. 남길 곳은 사진 가운데 한 점으로 시작한다
2. 데이터가 보관돼 있으면 바로, 없으면 "데이터 받기"(엔진 13.5MB + 모델 6.2MB, 증명사진에서 엔진을 받았으면 모델만) 뒤에
   물체 나누기 워커를 띄우고 나누기용 사진의 사본을 넘긴다
3. 물체 나누기 워커가 남길 곳(점)마다 `segment(image, { keypoint })` → 물체일 가능성(0~255, 나누기용 사진 크기).
   점마다 기억해(사진이 바뀌면 비움) 다시 나누지 않고, 모두 겹쳐(최댓값) 남은 곳 비율과 함께 화면에 준다. 겹치기도 워커에서 해
   점이 늘어도 화면이 멈추지 않는다. 화면은 그사이 다른 사진을 열지 않았을 때만 사진 워커에 넘긴다. 남은 곳이 0.2%보다 적으면 "찾지 못했습니다"
4. 사진 워커가 미리보기를 그린다 (`paint`)
   - `refine`: 넓히기·좁히기(단계마다 나누기용 사진 긴 변의 1/256, 네모 최대·최소 거름) → 부드럽게(상자 흐림 두 번) →
     투명도 (부드럽게 0이면 확신 35~65%만 비례로, 나머지는 다 남기거나 다 지움)
   - 투명도 그림을 결과 크기로 늘려 깔고(선형 보간), 붓질을 차례로(지우개 `destination-out`, 되살리기 `source-over`),
     그 모양대로 사진을 남긴다(`source-in`). 색 배경이면 뒤에 칠한다(`destination-over`)
   - "물체에 맞춰 자르기"면 붓질까지 반영한 남은 곳 칸을 나누기용 크기에서 찾아 점선으로 보여 준다
5. 저장: 같은 `paint`를 원본 크기로. canvas 하나에 못 그리면 줄 묶음씩 그려 PNG·JPG를 이어 쓴다 (`saveDrawing`)

  포도밭 앞 유리잔, 흰 배경 사람 2장(AI 가상 인물·NASA 공개 사진). 누른 곳은 모두 사진 가운데)

  | BiRefNet·IS-Net(DIS)                                                   | 100MB 넘음                                 | MIT·Apache-2.0                     | 너무 커서 뺐다                                                                                                                        |
  - MagicTouch로 정했다. 증명사진이 이미 받는 엔진으로 돌아 사이트에 새 실행 엔진이 늘지 않고, 처음 받는 양도 엔진을
    받아 둔 사람은 6.2MB다. 사람용(작음)·모든 물체(큼) 고르기는 두지 않았다. MagicTouch가 사람도 Selfie Segmenter만큼
    나눠 한 모델로 충분했다
  - 누른 곳을 고르는 모델이라 '알아서 주인공 찾기'는 하지 않는다. 처음에는 가운데를 누른 것으로 하고, 다른 물체는 눌러 더한다

- 나누기는 긴 변 1024 사진으로 한다. 모델은 512로 줄여 보므로 더 크게 넣어도 경계가 좋아지지 않고, 마스크만 커진다.
  원본에는 마스크를 늘려 씌운다 (원본 화소는 그대로)
- 붓질은 사진 비율 좌표·지름(긴 변 비율)으로 둔다. 미리보기·원본·줄 묶음 어디에 그려도 같은 자리다
- 워커 둘: 물체 나누기 워커(엔진)와 사진 워커(원본). 큰 사진 때문에 사진 워커가 죽어도 엔진은 살아 있다.
  엔진 워커가 죽으면 엔진을 버리고 "다시 해 보기"에서 보관본으로 다시 띄운다
- 기본 부드럽게는 0: 1로 두니 상품 사진 테두리에 탁자 색이 2~3화소 비쳤다
- 투명 배경은 PNG, 색 배경은 JPG로 정했다 (형식 고르기를 따로 두지 않음). 흰 배경 상품 사진은 JPG가 흔하고 작다

### 주의할 점

- 늦게 끝난 예전 사진의 나누기 결과를 쓰지 않는다: 점마다 나눈 결과는 물체 나누기 워커만 사진별로 기억하고(새 사진을 넘기면 비움),
  화면은 `ticket === generation`일 때만 사진 워커에 넘긴다 (리뷰 P1). 화면 쪽에 점별 기억을 두면 다른 사진의 가운데 점과 겹친다

- 마스크(`Mask`)의 첫 번째 확신 마스크가 '누른 물체'다 (모델 카드: 배경·물체 두 갈래를 softmax). 순서를 바꾸면 거꾸로 지운다
- 데이터 동의 이름은 `cutout`이지만 엔진 파일은 증명사진(`face`)과 같은 주소다. 보관소는 주소로 보관하므로 엔진은 한 번만 받는다.
  `missingData`가 보관 안 된 파일만 세서 "모델만 받는다"를 알린다
- `points[0] === CENTER`(같은 객체)로 '가운데를 저절로 남김' 안내를 고른다. 처음부터를 누를 때도 `CENTER`를 그대로 넣는다
- 체크무늬는 두 테마 모두 밝게 그린다 (`--color-paper` 기준). 어두운 칸이면 어두운 물체와 헷갈린다
- 격리 frame 규칙(워커는 `createWorker`, `style=""` 금지, form 금지)은 [격리 frame](../../foundations/frame-isolation/README.md)

## 4. 검증

### 자동 테스트

- `tests/e2e/image-remove-bg.spec.ts`
  - 데이터 받기 전에는 다운로드를 막고 크기를 밝힌다 → 받으면 가운데 사람만 남긴 800×1200 PNG. 배경 쪽 네 곳은 투명(알파 16 미만),
    얼굴·옷 쪽은 불투명(240 넘음). 파일 이름 `portrait_배경제거.png`. 받은 데이터는 엔진·모델 둘뿐, googleapis 요청 없음.
    다시 들어오면 묻지 않고 바로 나눈다
  - "다른 색"(#ff0000) JPG: 배경 쪽이 빨강, 사람 쪽은 원래 색. 흰색 + "물체에 맞춰 자르기": 세로가 줄고 귀퉁이가 흰색
  - 키보드: "지우개"를 고르고 방향키·Enter로 옷 한가운데를 칠하면 그곳이 투명, Ctrl+Z로 되돌리면 다시 불투명
  - 열 수 없는 파일은 알린다
