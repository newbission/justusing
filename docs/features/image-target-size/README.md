## 1. 어떤 기능인지

- "200KB 이하", "1MB 이하"처럼 정한 용량 이하로 사진을 줄인다. 관공서·지원서·과제 첨부 제한, 메신저 등
- 입력: JPG·PNG·WebP·HEIC, 여러 장 (이미지 압축과 같은 `ImageBatch({ heic: true })`, `anyFormat` 아님). HEIC는 2026-10-24
- 출력
  - 한 장: `<원래 이름>_<목표>.<확장자>` (예: `photo_200KB.jpg`, 영어도 같음)
  - 여러 장: `이미지_<목표>.zip` (영어 `images-<목표>.zip`). 맞춘 것은 결과를, 이미 목표 이하라 원본 그대로 둔 것은 원본을 넣는다
  - 목록의 ↓ 버튼으로 한 장씩도 받는다
- 설정
  - 목표 용량: 100KB·200KB(기본)·500KB·1MB·2MB 또는 직접 입력(숫자 + KB/MB, 10KB~50MB)
  - 줄이는 방법: 필요하면 크기도 줄이기(기본) / 크기는 그대로, 화질만
  - 저장 형식: JPG로 저장(기본) / 원래 형식 그대로
- 결과 줄: `용량 · 가로×세로(줄였으면 '(줄임)') · 화질 n%(PNG는 n색) · 투명한 곳은 흰색(해당할 때)`, 결과 비교(공통)
- 하지 않는 것·한계 (화면·FAQ·가이드와 같게)
  - 1KB = 1,000바이트, 1MB = 1,000,000바이트로 맞춘다 (1,024로 세는 곳보다 엄격). 목록 표시는 1,024로 세므로 결과가 목표보다 조금 작게 보인다
  - 이미 목표 이하이고 형식이 같으면 원본을 그대로 둔다 (EXIF도 그대로). 다시 저장한 결과에는 EXIF가 없다
  - HEIC는 HEIC로 저장하지 못하고 받는 곳도 드물어, 원래 형식 그대로를 골라도 JPG로, 목표 이하여도 바꿔 맞춘다 (HEIC가 있으면 설정 아래 안내)
  - 화질만: 화질 10%까지. 그래도 넘으면 "맞추지 못함: 화질만으로는 n KB까지"
  - 크기도 줄이기: 긴 변이 100픽셀보다 작아져야 맞으면 "목표가 너무 작음"
  - JPG로 저장하면 투명한 곳이 흰색이 된다. 원래 형식 그대로면 PNG는 색 수를 줄인다 (투명 유지)
  - 원본이 WebP이고 원래 형식 그대로인데 브라우저가 WebP로 저장하지 못하면(Safari) 알린다

## 2. 어떻게 만드는지

### 파일

| 파일                                      | 역할                                                                                                                            |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `src/tools/image/target-size/meta.ts`     | 이름·한 줄 설명·아이콘, 묶음 `optimize`, 관련 도구 `image/compress`·`image/resize`·`image/id-photo`                             |
| `src/tools/image/target-size/content.ts`  | 쓰임새 3·사용법 5단계·FAQ 7개 (한·영)                                                                                           |
| `src/tools/image/target-size/messages.ts` | 화면 문구, `Method`(`resize`·`keep`)·`Format`(`jpg`·`same`)·`Unit`                                                              |
| `src/tools/image/target-size/App.svelte`  | 목표·방법·형식 고르기, 원본 유지 판단, 실행·결과 표시·받기                                                                      |
| `src/lib/image/fit-size.ts`               | 화질 사다리, 이분 탐색 `highestFitting()`, 다음 배율 `nextScale()`, 상수                                                        |

| `src/lib/image/process.worker.ts`         | `fit()`: 크기마다 한 번 그리고 화질만 바꿔 저장해 본다, 투명 확인(`hasAlpha`)                                                   |
| 공통                                      | `ImageBatchTool`·`ImageBatch` ([이미지 공통](../../foundations/image-common/README.md)), `ActionBar`, `downloadFile`, `makeZip` |

### 처리 흐름

1. `ImageBatchTool`로 이미지를 넣는다 (`new ImageBatch({ heic: true })`, JPG·PNG·WebP·HEIC)
2. "용량 맞추기" → `canUse('image/target-size')` → 지금 설정으로 아직 `done`이 아닌 이미지만 처리한다
3. 이미지마다: 원본이 목표 이하이고 결과 형식이 원래 형식과 같으면 `kept` (워커에 보내지 않음)
4. 아니면 `fitImage(file, { type, limit: { bytes, resize } })`. 워커(`fit()`):
   1. 배율 1로 그린다 (JPG면 흰 바탕 위에. JPG가 아닌 원본이면 그 전에 투명 화소가 있는지 본다 → `flattened`)
   2. `highestFitting()`: 화질 사다리(높은 → 낮은)에서 상한에 드는 가장 높은 값을 이분 탐색. 첫 값(92%)으로 맞으면 한 번에 끝
   3. 맞으면 `done`(바이트·가로·세로·화질 또는 색 수). 화질만이면 여기서 `over(keep-size)`
   4. 크기도 줄이기면 어림 화질(75%, PNG는 256색)로 저장한 용량에서 `nextScale()`로 배율을 줄이고 1로 돌아간다.
      어림이 긴 변 100px 아래로 가면 100px에서, 마지막(8번째) 차례도 100px에서 해 보고, 그 크기에서도 넘을 때만 `over(too-small)`
5. 결과: `done`·`kept`·`over`(가장 작게 한 용량·까닭)·`failed`(`decode`·`encode`)
6. 막대: 실패 > 못 맞춤(까닭별 안내) > 모두 원본 그대로 > "완료: n장 모두 ○○ 이하입니다." 순으로 보인다
7. 받기: 한 장이면 "다운로드", 여러 장이면 "모두 받기 (ZIP, n장)". `done`이 없으면(모두 원본 그대로) 받기 버튼이 없다

### 탐색 값 (`fit-size.ts`)

| 상황                 | JPG·WebP 화질    | PNG 색 수 (0 = 줄이지 않음)  | 크기 줄일 때 어림 |
| -------------------- | ---------------- | ---------------------------- | ----------------- |
| 필요하면 크기도 줄임 | 92% → 60% (1%씩) | 0 → 256 → 128 → 64           | 화질 75% / 256색  |
| 크기는 그대로        | 92% → 10% (1%씩) | 0 → 256 → 128 → 64 → 32 → 16 | (줄이지 않음)     |

- 다음 배율 = 지금 배율 × clamp(√(목표 / 어림 용량) × 0.95, 0.25, 0.9)

### 결정과 이유

- **화질 먼저, 그다음 크기**: 화질을 아주 낮추면(20% 안팎) 네모 얼룩이 생긴다. 견본 사진을 30KB에 맞추면 화질만은 16%,
  크기도 줄이면 1044×783·74%가 되고 후자가 더 깨끗했다 (가이드 그림). 그래서 크기를 줄여도 되면 60%까지만 낮춘다
- **어림 화질 75%로 배율을 정한다**: 가장 낮은 화질(60%) 용량으로 정하면 줄인 크기에서도 60% 안팎으로 맞아 화질이 낮게 끝난다.
  75%로 어림하면 줄인 크기에서 70%대 화질로 맞는다
- **1KB = 1,000바이트**: 제출 사이트가 1,000·1,024 중 어느 쪽으로 재는지 알 수 없어 엄격한 쪽으로 맞춘다.
  목록 표시(`formatSize`)는 다른 도구와 같이 1,024로 세어 두고, FAQ·가이드에 "조금 작게 보인다"를 밝혔다
- **원본 유지**: 이미 목표 이하인 원본을 다시 저장하면 화질만 나빠져 그대로 둔다. 단 JPG로 저장을 골랐는데 원본이 PNG·WebP면 바꿔 저장한다
- **기본 형식 JPG**: 관공서·지원서 제출은 대부분 JPG를 받고, 사진은 JPG가 훨씬 작다. 투명 PNG는 흰 바탕이 되므로 줄마다 알린다
- **처리 위치**: 화질 탐색(이미지 한 장에 저장 5~10번)도 워커 안에서 한다. 새 워커를 만들지 않고 `process.worker.ts`에
  `limit` 경로를 더해 압축·크기 조절과 같은 워커 풀·EXIF 방향·UPNG를 그대로 쓴다. 크기마다 한 번만 그리고 화질만 바꿔 저장한다
- **목표 고르기 모양**: 버튼 6개가 붙은 고르기(`.choice`)는 휴대폰 폭을 넘어 하나씩 떨어진 버튼(`.targets`)으로 줄을 넘기게 했다

### 주의할 점

- 뺀 이미지의 결과는 `onremove`에서 지운다 (이미지 공통 규칙)
- 결과 형식이 원래 형식일 때 `saveType(item)`을 쓴다 (형식을 모르면 JPG). HEIC는 `item.type`이 없어 `kept` 조건(형식이 같음)에 들지 않는다.
  `anyFormat`을 켜면 GIF·BMP도 같은 길을 타니 켜지 않는다
- `scaleDown()`은 받은 원본(`ImageBitmap`)을 닫지 않는다. `fit()`이 같은 원본을 여러 크기로 다시 그리기 때문이다 (닫기는 메시지 처리 끝에서)
- 탐색은 "화질을 낮추면 용량이 준다"고 보고 이분 탐색한다. 아주 드물게 더 높은 화질이 맞는 값을 놓칠 수 있지만 결과는 늘 상한 이하다
- 버튼·고르기 이름("용량 맞추기", "직접 입력", "크기는 그대로, 화질만", "JPG로 저장")을 바꾸면 `content.ts`·가이드·E2E·`scripts/guide-images/run-tools.mjs`도 맞춘다

## 4. 검증

### 자동 테스트

`tests/e2e/image-target-size.spec.ts` (받은 파일을 브라우저로 다시 열어 크기·형식·모서리 색을 본다)

- `photo.jpg`(1200×900, 약 537KB)를 100KB에: JPG, `photo_100KB.jpg`, 100,000바이트 이하, 가로가 줄고 비율 유지, "(줄임)" 표시, 로컬 처리
- "크기는 그대로, 화질만" 200KB: 1200×900 그대로 200,000바이트 이하. 직접 입력 10KB: "맞추지 못함" + 막대 안내, 다운로드 없음.
  크기도 줄이기로 바꾸면 `photo_10KB.jpg` 10,000바이트 이하
- `photo.jpg`·`screen.png`(투명)·`small.jpg`를 100KB에: `이미지_100KB.zip`에 `photo_100KB.jpg`·`screen_100KB.jpg`·`small.jpg`(원본과 같은 바이트),
  모두 100,000바이트 이하, PNG를 바꾼 JPG의 투명했던 모서리는 흰색, "투명한 곳은 흰색"·"원본 그대로" 표시
- `small.jpg`를 500KB에: "모두 이미 500KB 이하라 원본 그대로 둡니다.", 다운로드 없음
- 원래 형식 그대로 + 10KB: `noise.png`(80×60) → `noise_10KB.png` PNG, 10,000바이트 이하, 80×60
- `iphone.heic`(약 3.5KB, 크롬은 libheif 경로)를 원래 형식 그대로 + 100KB: 목표 이하여도 `iphone_100KB.jpg`(JPG, 300×400), HEIC 안내 표시, 로컬 처리
- 목표 5KB는 막고(안내·버튼 꺼짐) 5MB로 바꾸면 풀린다. 깨진 `broken.png`는 "열 수 없는 이미지"로 알리고 장수에서 뺀다

### 직접 확인

- 2026-10-23 Chrome(wrangler 미리보기, 1280·390 폭): 견본 사진·화면 캡처 200KB, 3200×2400 사진 100KB(1351×1013·화질 73%),
  투명 PNG 1600×1200을 JPG(흰 바탕 알림)·원래 형식(484×363·128색)으로. 네 장 100KB가 0.6초, PNG 원래 형식 세 장이 2.2초
- 견본 사진 30KB: 크기도 줄이기 1044×783·화질 74%, 화질만 2000×1500·화질 16%. 20KB 화질만은 23KB까지만 줄어 못 맞춤
