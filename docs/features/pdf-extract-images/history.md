# pdf-extract-images — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-15 처음부터 정한 것: JPG는 원본 바이트 그대로, Flate·색 목록은 화소를 풀어 PNG로, JPEG 2000은 그대로 낸다.
  다룰 수 없는 형식은 꺼내지 못한 수로 알리고 "PDF를 이미지로"를 권한다. 화소 풀기는 압축 도구와 같이 쓰도록
  `image-pixels.ts`로 옮겼다.
- 2026-10-15~16 Codex 리뷰가 #59에 37개를 지적했다. 종류로 나누면:
  - 색이 PDF와 달라지는 경우 (가장 많음): `/Decode`, ICC `/Range`, `/Matte`, `ColorTransform`, `/Default*` 색공간,
    이름 색공간, 색 목록 `hival`, JPG 안 ICC가 PDF 색공간을 이기는 것, JPEG 2000 `colr` 상자, 회색 ICC
  - 투명도를 잃는 경우: `/Mask` 색 키, 다룰 수 없는 SMask, SMask가 있을 때 색 키 무시, 투명 JPG·JPEG 2000
  - 찾는 범위: 바로 써 넣은 그림 세기, 그리지 않는 사진, 물려받는 묶음 그림, 무늬, 주석 모양, Type3 글자 모양,
    꺼진 층·NoView
  - 그 밖: JPEG 2000 확장자, 8바이트 상자 길이, 번호 매기기, 파일을 닫을 때 정리, `canUse()`
- 2026-10-15~16 원칙: PDF에서 보이는 색·투명도와 같게 낼 수 없으면 틀린 파일을 내지 않고 못 꺼낸 것으로 센다.
  그래서 JPG를 "늘 원본 그대로"라고 쓴 FAQ·가이드도 프로필을 넣는 경우와 PNG로 바꾸는 경우를 밝히도록 고쳤다 (`ca129ac`).
- 2026-10-16 회색 ICC 프로필은 canvas가 늘 RGB PNG로 저장해 넣을 수 없어, 회색 PNG를 직접 만든다 (`2016a5c`).
- 2026-10-16 배운 점: 찾는 길(쪽·묶음 그림·무늬·주석·글자 모양)마다 따로 고치다 보이지 않는 사진이 섞였다.
  "화면에 보이는 것만"이라는 기준 하나로 모든 길을 맞췄다 (`1afdab4`). 내용 읽기는 가리기의 토큰 나누기를 같이 쓴다.
- 고칠 때마다 "예전 코드에서는 실패하는" E2E를 같이 넣었다.
