# pdf-to-image — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-14 쪽 전체를 canvas에 그려 JPG·PNG로 저장하는 방식으로 만들었다. 전체 추출 / 선택 추출, 150·300 DPI. 여러 장은 ZIP 하나로 받는다.
- 2026-10-14 **화면 멈춤의 원인은 그리기가 아니라 저장(인코딩)**이었다. 300 DPI 스캔 PDF에서 쪽마다 JPG 약 80ms, PNG 약 200ms.
  그린 화소를 `ImageBitmap`으로 워커에 넘겨 `OffscreenCanvas`에서 저장하자 long task가 0, 5쪽 12.8초 → 3.9초가 됐다.
  쪽 그리기는 pdf.js가 잘게 나눠 하므로 화면에 두었다. 배운 점: 옮기기 전에 어디서 멈추는지 먼저 잰다.
- 2026-10-14 ZIP 묶기도 워커로 옮겼다 (`src/lib/zip.ts`, 나누기도 같이 바뀜).
- 2026-10-14 변환 중에 형식을 바꿨다 되돌리면 ZIP 안에 다른 형식이 섞일 수 있었다. 시작할 때 형식·화질·쪽 목록을 지역 변수로 잡아 끝까지 쓴다.
- 2026-10-14 면적 한계(1,600만 화소)만 두면 아주 길쭉한 쪽이 한 변 한계를 넘어 빈 이미지가 나올 수 있었다. 가장 작은 Safari의 한 변 16,384에도 맞춘다.
- 2026-10-15 쪽 그리기 부분을 `renderPageBitmap()`으로 나눠 OCR이 같이 쓴다.
