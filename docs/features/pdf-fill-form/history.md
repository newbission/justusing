# pdf-fill-form — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-15: 입력 칸을 목록이 아니라 쪽 위 그 자리에서 채우게 했다. 원래 칸 모양은 `PageSheet`의 `hideForms`로 뺀다
- pdf-lib는 칸 기본 글꼴(Helvetica)에 없는 한글을 오류 없이 빼 버린다 → 글자 넣기 워커에서 고른 글꼴로 모양을 만들고,
  글꼴 없이 빠질 글자가 있으면 미리 알린다
- 리뷰 P1: 선택 상자가 보이는 글자(대한민국)를 값으로 저장해 내보내는 값(KR)을 읽는 처리가 틀어졌다
  → 모양은 보이는 글자로, `/V`(목록은 `/I`도)는 내보내는 값으로 직접 적는다. 바꾸지 않은 칸·읽기 전용 칸도 같게
- 리뷰 P1: 같은 이름에 켜는 값이 다른 체크 상자가 함께 켜졌다 → 값을 "켠 상자의 값"으로 바꾸고 `/V`·`/AS`를 직접 적는다
- 리뷰 P1: 암호 칸은 화면만 가리고 저장 모양에 평문을 그려, 굳히면 PIN이 쪽에 남았다 → 모양에는 `*`, 값은 그대로
- 직접 적는 선택 상자(`/Ff` Edit), 끌 수 있는 라디오(`NoToggleToOff` 없음)를 pdf.js `fieldFlags`로 읽어 지원했다
- 모양을 다시 만들 기존 칸의 한글도 글꼴 검사에 넣고, 암호 칸 값은 검사에서 뺐다
- 이름이 `__proto__`·`constructor`인 칸이 일반 객체에서 깨졌다 → 화면은 `SvelteMap`, 넘길 때 `structuredClone`, 워커는 `Object.hasOwn`
- 배운 점: 양식은 "보이는 글자 / 저장되는 값 / 위젯별 켜짐"이 따로 있다. pdf-lib 고수준 API가 이것을 하나로 뭉개는 곳은
  사전(`/V`·`/AS`·`/I`)을 직접 적어야 한다. 리뷰 지적을 고칠 때마다 예전 코드에서 실패하는 E2E를 더했다
- 2026-10-16: PR #60 dev 병합 (main 배포 전)
