## 1. 어떤 기능인지

- 사진·화면 캡처·스캔 이미지 속 한국어·영어 글자를 읽어 복사하거나 TXT로 받는다
- 입력: 브라우저가 여는 이미지 여러 장 (JPG·PNG·WebP·GIF·BMP, HEIC는 Safari만). 못 여는 파일은 목록에 "열 수 없는 이미지"로 두고 빼고 읽는다
- 고르는 것: 인식할 언어(한국어·영어, PDF 글자 인식과 같은 부품), "읽은 줄 표시"(이미지 위 줄 상자, 기본 켜짐)
- 출력
  - 이미지마다 읽은 글자 칸. **고쳐 쓸 수 있고**, 복사·TXT에 고친 글자가 들어간다
  - "모두 복사"·"TXT 다운로드": 여러 장이면 장마다 `--- 파일 이름 ---` 머리 줄을 붙여 하나로. TXT는 CRLF·UTF-8 BOM
    - 한 장: `원래이름_글자인식.txt` (영어 `_ocr.txt`), 여러 장: `이미지_글자인식.txt` (영어 `images_ocr.txt`)
  - 이미지마다 "복사" (그 이미지 글자만)
- 처음 쓸 때 인식 데이터를 받는다 (PDF 글자 인식과 같은 묶음·동의 이름 `ocr`이라 한쪽에서 받았으면 다시 받지 않는다)
- 한계 (FAQ·가이드와 같음)
  - 손글씨는 거의 못 읽는다. 세로쓰기·한자·일본어 등은 지원하지 않는다
  - 흐림·그림자·반사, 아주 작은 글자, 꾸민 글꼴, 촘촘한 표는 틀릴 수 있다. 틀린 글자는 따로 표시하지 않는다
  - 기울기는 ±20° 안만 바로잡는다. 비스듬히 찍은 원근(사다리꼴)은 바로잡지 않는다
  - 한국어+영어를 함께 고르면 한글 낱말이 영문자로 읽히는 실수가 가끔 있다 (예: 견본 대화의 "맞췄죠?" → "SHEA?")
  - 검색 가능한 PDF는 만들지 않는다. "이미지를 PDF로" → "PDF 글자 인식"으로 안내한다 (FAQ·가이드)

## 2. 어떻게 만드는지

| `src/lib/ocr/ocr-data.svelte.ts`  | `OcrData`: 고른 언어, 보관 확인, 받기, 엔진에 넘길 바이트 (PDF 글자 인식과 같이 씀)                            |
| `src/lib/ocr/OcrSetup.svelte`     | 언어 고르기 + 데이터 받기 칸 (PDF 글자 인식과 같이 씀)                                                         |
| `src/lib/ocr/ocr.ts`              | `OcrPool.images()`: 이미지를 워커에 나눠 맡긴다                                                                |
| `src/lib/ocr/ocr.worker.ts`       | `readPicture()`: 바로 세워 열기 → 회색 → `readImage()`, `recognizeLines()`: 줄마다 글자·자리·확실한 정도       |
| `src/lib/ocr/image-read.ts`       | 읽는 순서 (크기·기울기·방향·작은 글자·바탕 섞임), 줄 다듬기, 줄 자리를 원래 이미지 기준으로                    |
| `src/lib/ocr/image-prep.ts`       | 회색 화소 계산: 줄이기·돌리기(`transform`), 중간값(`median`), `contrastMap`, `mixedBackground`, `estimateSkew` |
| `src/frame/clipboard.ts`          | `copyText()`: 클립보드 쓰기, 막히면 옛 방식(`execCommand('copy')`)                                             |
| `src/components/ToolFrame.astro`  | iframe `allow="fullscreen; clipboard-write"`                                                                   |

### 처리 흐름

1. 이미지 넣기 → `ImageBatch({ anyFormat: true })`가 크기·썸네일을 읽는다
2. `OcrData`가 고른 언어의 데이터 보관 여부를 묻는다. 없으면 크기를 밝히고 "데이터 받기"를 기다린다
3. "글자 인식" → `canUse('image/ocr')` → 아직 읽지 않았거나 실패한 이미지만 `OcrPool.create()` + `pool.images()`
   - 워커 수는 PDF와 같다: `min(CPU − 1, 3, 장 수)`, 메모리 4GB 이하면 1개
4. 워커(`readPicture`)
   - `createImageBitmap(..., { imageOrientation: 'from-image' })`로 바로 세워 연다. 1,200만 화소를 넘으면 열 때 줄인다
   - 흰 바탕에 그려(투명 PNG) 회색으로 바꾼다
5. `readImage()` (모든 단계가 같은 회색 원본에서 크기·각도만 바꿔 다시 그린다)
   1. 크기: 800만 화소 안으로 줄이고, 긴 쪽이 1,000화소 미만이면 키운다(최대 2.5배)
   2. 기울기: `estimateSkew()` — 바탕(중간값)과 다른 화소를 ±20°에서 0.5°씩 옆으로 비춰 줄 사이가 가장 또렷한 각도. 3° 이상일 때만 돌린다
   3. 읽기: 엔진 `Recognize` 후 줄 단위 반복자(`GetIterator`, `RIL_TEXTLINE`)로 글자·상자·확실한 정도·문단 시작
   4. 방향: 평균 확실한 정도 60 미만이거나 믿을 만한 글자가 10개 미만이면 긴 쪽 1,200화소로 줄여 0·90·180·270°를 읽어 보고,
      나은 방향이 1.5배+5 넘게 좋으면 그 방향으로 다시 잰 기울기와 함께 다시 읽는다
   5. 작은 글자: 줄 높이 중간값이 20화소 미만이면 32화소가 되게(최대 3배, 800만 화소 안) 키워 다시 읽고 나으면 쓴다
   6. 줄 다듬기(`clean`): 더 확실한 줄과 겹치는 흐릿한 줄 빼기, 줄 앞뒤에 홀로 붙은 모양 조각(괄호·세로줄·따옴표·쉼표 등, `NOISE`) 떼기 — `$ ₩ % #` 같은 뜻 있는 기호는 남긴다, 글자 두 개 이하인 흐릿한 줄 빼기,
      영어 낱말 앞의 홀로 선 `|`를 `I`로
   7. 바탕 섞임: `mixedBackground()`(줄인 그림의 바탕 밝기에서 어두운 곳·밝은 곳이 각각 3% 이상)면 `contrastMap()`으로
      다시 그려 한 번 더 읽고, 확실한 정도 60 이상·글자 2개 이상인 줄을 **6에서 남은 줄**과 견준다. 30% 넘게 겹치는 남은 줄이 없으면 위에서부터의 자리에 끼우고,
      겹치는 줄이 모두 흐릿하면(50 미만) 그 줄들을 이 줄로 바꾼다. 이 줄들도 `tidy`로 다듬는다(말풍선 모서리가 읽힌 `i` `:` 조각도 뗀다)
   8. 글: 문단 사이 빈 줄, 셋 이상 이어진 공백은 둘로
6. 줄 상자의 네 꼭짓점을 읽은 그림 → 원래 이미지 기준으로 되돌려(돌린 각도·크기 거꾸로) 화면이 SVG 다각형으로 겹친다

### 결정과 이유

- **PDF 글자 인식과 엔진·데이터·워커를 같이 쓴다**: 같은 Tesseract에 같은 데이터. 동의 이름도 같아(`ocr`) 한 번 받은 사람은 두 도구 어디서든 다시 받지 않는다.
  언어·받기 화면은 `OcrSetup`·`OcrData`로 묶어 두 도구가 같이 쓴다 (`refactor(pdf-ocr)` 커밋)
- **전처리를 직접 한다**: 견본으로 재어 보니 엔진에 그대로 넣으면 10° 남짓 기운 사진·누운 이미지는 거의 읽지 못했다(확실한 정도 55 안팎, 글자 대부분 틀림).
  기울기를 재어 바로 세우자 12°·−15°·90°·180° 모두 견본 글자를 읽었다
- **OSD(엔진의 방향 찾기)를 쓰지 않는다**: `osd.traineddata`(옛 방식 모델, 수 MB)가 더 필요하고 지금 데이터 묶음에 없다. 대신 거의 못 읽었을 때만 네 방향을 작게 읽어 본다(잘 읽힌 이미지는 시간이 늘지 않는다)
- **3° 미만은 돌리지 않는다**: 엔진이 작은 기울기는 스스로 견디고, 돌리면 다시 그리며 글자가 조금 흐려져 견본에서 오히려 틀린 글자가 생겼다
- **어두운 말풍선은 두 번째 읽기로 더한다**: 엔진은 초록 말풍선 속 흰 글자를 줄째 건너뛰었다(밝기를 뒤집어도, 이진화 방식(Sauvola)을 바꿔도 같았다).
  바탕과의 차이로 다시 그리면(넓은 창 중간값과 좁은 창 중간값 중 가까운 쪽) 말풍선 글자는 읽지만 굵고 큰 글자는 속이 비어 틀린다.
  그래서 처음 읽기는 그대로 두고 놓친 줄만 더한다. 말풍선 모서리가 `( ' i` 처럼 붙는 것은 줄 끝 조각을 떼어 없앤다
- **전처리를 Node에서 시험할 수 있게**: `image-prep.ts`·`image-read.ts`는 canvas·화면에 기대지 않고 엔진을 넘겨받는다. 견본을 Node + `tesseract.js-core`로 돌려 정했다
- **여러 장은 TXT 하나로**: 글자만 필요한 사람이 ZIP을 풀어 다시 모을 일을 없앤다. 장마다 파일 이름 머리 줄로 구분한다
- **실행 막대**: 읽은 것이 있으면 "모두 복사"·"TXT 다운로드"를 두고, 읽지 못했거나 새로 더한 이미지가 있으면 "글자 인식"도 함께 둬 그것만 다시 읽는다 (읽은 결과·고친 글자는 그대로)
- **글자 칸을 고칠 수 있게**: 인식은 틀릴 수 있어, 복사·TXT 전에 바로 고치게 했다. 언어를 바꾸면 결과(고친 것 포함)는 버리고 다시 읽는다
- **클립보드**: 격리 frame은 다른 출처라 바깥 iframe에 `clipboard-write`를 허용해야 쓰기가 된다. 읽기는 허용하지 않는다
- **줄 상자**: 엔진이 읽은 줄을 보여 줘 빠진 줄을 바로 알게 한다. SVG `viewBox`를 바로 세운 이미지 크기로 두어 화면 크기와 상관없이 맞는다

### 주의할 점

- 워커가 메모리 부족으로 죽으면 답이 오지 않는다. `OcrPool.each()`는 죽은 워커에 더 맡기지 않고, 모두 죽어 남은 이미지는 실패로 알린다
- `readImage()`의 모든 읽기는 같은 회색 원본에서 `transform(source, scale, angle)`로 다시 그린다. 줄 자리를 되돌리는 `toSource()`가 이 두 값만 쓰므로, 다른 단계(잘라 읽기 등)를 더하면 되돌리기도 고친다
- 바탕을 다시 그려 읽은 줄은 처음 읽기와 **같은 크기·각도**라 겹침 비교를 그대로 한다. 크기를 다르게 하면 상자를 맞춰야 한다
- 엔진 반복자(`GetIterator`)는 `tess.destroy()`로 해제한다
- PDF 글자 인식의 문구·상태를 바꾸면 `OcrSetup`·`OcrData`가 두 도구에 함께 적용된다
- Safari 확인은 배포 뒤 (로컬에서는 frame CSP가 배포 도메인만 허용, 모든 도구 공통)

## 4. 검증

### 자동 테스트

`tests/e2e/image-ocr.spec.ts`

- 서류 사진과 대화 캡처: 데이터를 받기 전엔 "글자 인식"이 꺼져 있고, 받은 뒤 읽으면 "재직 증명서"·"홍길동"·"2020년 3월 2일",
  대화의 흰 말풍선과 초록 말풍선 속 흰 글자("오늘 저녁까지 올릴게요")를 위에서부터의 순서로 읽는다. 줄 상자가 5개 이상.
  글자를 고쳐 쓰면 "모두 복사"(파일 이름 머리 줄)·TXT(`이미지_글자인식.txt`, BOM·CRLF)에 들어간다. 장마다 "복사"는 그 이미지 글자만.
  이미지를 더하면 받기 버튼은 그대로이고 "글자 인식"으로 새 이미지만 읽는다 (고친 글자는 남음)
- 옆으로 누운(90°)·기운(12°) 이미지(브라우저에서 견본을 돌려 만든다)를 바로 세워 읽고, 못 여는 파일은 빼고 읽는다. 한 장만 남으면 TXT 이름이 `원래이름_글자인식.txt`
- PDF 글자 인식에서 받은 데이터를 다시 받지 않는다 (`/data/ocr/` 요청 없음)
- 모든 테스트에서 요청은 우리 사이트로만 (`test.ts`의 `expectLocalOnly`)
