## 1. 어떤 기능인지

- 사진 한 장을 90°씩 돌리고, 좌우·상하로 뒤집고, 기울기(±45°, 0.1° 단위)를 바로잡고, 남길 영역을 골라 다시 저장한다
- 입력: 브라우저가 읽는 이미지 한 장 (HEIC는 Safari만). EXIF 방향은 적용해 바로 세워 연다
- 자를 영역
  - 끌기(가운데 옮기기, 모서리·변 크기 바꾸기), 방향키(판 긴 변의 1%, Shift는 10배), 숫자 칸(왼쪽·위·폭·높이 px)
  - 비율: 자유·원래 비율·1:1·4:5·5:4·3:4·4:3·2:3·3:2·9:16·16:9. 비율을 고르면 판 안의 가장 큰 그 비율 사각형(지금 영역 가운데 기준)으로 바꾸고, 모서리만 끌 수 있다
  - "자르지 않기"는 판 전체로 되돌린다
- 형식: JPG·PNG·WebP. 처음에는 원래 형식(그 밖의 형식은 JPG). JPG·WebP 화질 0.92
- 출력: `<원래 이름>_편집.<jpg|png|webp>`
- 하지 않는 것·한계
  - 한 번에 한 장. 여러 장에 같은 회전을 거는 기능은 없다
  - 다시 그려 저장하므로 EXIF는 남지 않는다 (방향 정보 없이 바로 선 화소로 저장)
  - JPG 무손실 회전(다시 압축하지 않고 돌리기)은 하지 않는다
  - 결과 크기는 고른 영역의 화소 수다. 정확한 크기로 늘리거나 줄이는 것은 크기 조절 도구가 한다

### 처리 흐름

1. 파일을 고르면 워커가 바로 세워 읽고(`imageOrientation: 'from-image'`) 원본 `ImageBitmap`을 들고 있는다. 화면에는 긴 변 1,600px 미리보기만 넘긴다
2. 판 = 원본을 90°씩 돌린 크기. 자를 영역은 판 위의 정수 화소 사각형(`Rect`)이다
3. 미리보기는 판 전체를 칸(최대 높이 420px)에 맞춰 그리고, 그 위에 영역 버튼과 손잡이를 % 자리로 겹친다
4. "자른 이미지 받기" → 워커가 영역 크기의 canvas에 `applyTurn(ctx, 원본, turn, 1, rect.x, rect.y)`로 그려 저장한다
   - canvas를 만들 수 없는 크기면(맨 끝 화소로 확인) PNG는 줄 묶음씩 그려 `PngStream`으로 이어 쓰고, JPG·WebP는 `tooLarge`

### 변환 순서 (`applyTurn`)

원본 가운데를 원점으로 → 90° 회전 → 뒤집기(판 기준) → 기울기 배율 → 기울기 회전 → 판 가운데로 → 영역 왼쪽 위만큼 빼기.
미리보기와 워커가 같은 함수를 써서 미리보기와 결과가 같다.

### 결정과 이유

- **기울기를 바꾸면 사진을 키워 판을 채운다**: 귀퉁이를 흰색으로 채우면 티가 난다. 휴대폰 사진 편집과 같은 방식이고, 판 크기가 바뀌지 않아 자를 영역을 다시 잡지 않아도 된다. 가장자리가 반쯤 비치지 않게 한 화소만큼 더 키운다
- **돌리고 뒤집으면 영역도 같이**: 먼저 잘라 둔 영역이 사진의 같은 곳을 가리킨다. 90° 돌리면 고른 비율도 4:5 ↔ 5:4처럼 바꾼다 (목록에 짝을 모두 두었다)
- **뒤집으면 기울기 부호를 바꾼다**: 뒤집기가 기울기 회전 안쪽에 있어, 그대로 두면 바로잡은 수평선이 반대로 기운다
- **원본은 워커에**: 수천만 화소 사진을 화면 스레드에서 그리면 멈춘다 (증명사진과 같은 방식)
- **한 장씩**: 사진마다 남길 곳이 달라 여러 장 목록 화면(`ImageBatchTool`)을 쓰지 않았다

### 주의할 점

- 워커가 죽으면 원본도 없어진다. 다음 저장은 `decode`로 "다시 열어 주세요"를 띄운다
- 숫자 칸은 `onchange`에서 반영하고 칸 값을 반올림·제한된 값으로 되돌린다 (판 밖·최소 8px)
- 격리 frame 규칙(워커는 `createWorker`, `style=""` 금지, form 금지)은 [격리 frame](../../foundations/frame-isolation/README.md)을 따른다

  - 견본 사진의 기울기를 4°로 바꿔도 결과가 1,600 × 1,200
