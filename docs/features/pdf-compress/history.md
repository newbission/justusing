# pdf-compress — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-14 글자는 두고 PDF 안의 사진만 다시 저장하는 방식으로 정했다. PDF 용량 대부분이 사진이고, 검색·복사를 잃지 않는다.
  PDF 워커 하나(pdf-lib)가 사진을 꺼내고 다시 넣고, 사진 워커 여러 개(CPU 수 − 1, 최대 4)가 나눠 줄인다. 원본보다 10% 이상 작아질 때만 바꾼다.
- 2026-10-14 손실 없는 정리를 더했다: 쓰지 않는 옛 객체 지우기, 압축 안 된 스트림 Flate 압축. 원본보다 작아지지 않으면 받을 파일을 만들지 않는다.
- 2026-10-14 리뷰에서 **색·모양이 바뀌는 경우**가 여럿 나왔다. 원칙은 "브라우저가 확실히 다루는 사진만 바꾸고 나머지는 그대로"다.
  - 다시 저장한 사진의 색공간을 늘 DeviceRGB로 덮어써 CalRGB·ICC 사진의 색이 바뀔 수 있었다 → 3색은 색공간을 남기고 JPG를 ICC 변환 없이 읽는다. 회색은 보정 없는 DeviceGray만
  - PDF 안 JPG를 EXIF 방향으로 돌려 읽었다 → `imageOrientation: 'none'`
  - PNG 예측의 줄 길이(Columns·Colors)가 사진과 다를 수 있었다 → 같을 때만, Flate일 때만
  - Matte 투명도, DefaultGray·DefaultRGB, 색 변환 설정(DecodeParms) JPG는 뺀다
  - 필터 없는 스트림에 Flate를 붙일 때 남은 DecodeParms가 새로 쓰이게 됐다 → 지운다
- 2026-10-14 다른 파일을 열거나 닫아도 압축이 계속 돌아 새 작업과 겹쳤다. `AbortController`로 그만두고, pdf-lib 열기·저장은 중간에 멈출 수 없어
  PDF 워커와 사진 워커 풀을 `terminate`한 뒤 다음 압축은 새 워커로 한다. `SinglePdfTool`에 `onclose`를 더해 닫을 때도 그만두고 결과를 버린다.
- 배운 점: PDF 안 사진은 색공간·마스크·필터 조합이 많다. 다룰 수 있는 경우만 좁게 허용하는 쪽이 안전하다.
