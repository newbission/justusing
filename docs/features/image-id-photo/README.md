## 1. 어떤 기능인지

- 찍어 둔 사진을 여권 사진 규격에 맞게 자른다. 여권 온라인 신청, 사진관 파일 다시 맞추기, 지원서 사진에 쓴다
- 입력: 사진 한 장 (브라우저가 읽는 형식. HEIC는 Safari에서만)
- 출력: `<원래 이름>_증명사진.jpg` (영어 `_id-photo.jpg`), 413×531 픽셀, 500KB 이하
- 할 수 있는 것: 얼굴을 찾아 자르기·크기·기울기를 맞춘다. 끌기·버튼·키보드로 직접 고친다. 좌우 반전. 고르면 배경을
  흰색·연한 회색·하늘색·다른 색으로 바꾼다. 참고용 확인(얼굴 여럿, 옆을 봄, 흰 배경 아님, 정수리 어림, 머리 길이 벗어남,
  원본이 작음, 칸이 사진 밖, 배경을 바꿈, 흰색 아닌 배경)
- 배경 바꾸기 (2026-10-20 사용자 요청): 여권 규정은 배경 합성을 금지하지만, 집 벽 앞에서 찍은 지원서용 사진에는 필요하다.
  기본은 "원래대로"이고, 바꾸면 '확인할 것'에 여권에는 원래 사진을 쓰라고 알린다
- **하지 않는 것**: 얼굴 보정 (여권 규정이 금지). 받아 주는지는 접수하는 곳이 정한다고 화면·FAQ에 밝힌다.
  인화용 여러 장 배치는 아직 없다

### 규격 (2026-10-19·20에 확인)

- 여권 (외교부 여권안내 passport.go.kr): 3.5×4.5cm, 머리(정수리~턱) 3.2~3.6cm, 흰 배경, 온라인 413×531 픽셀·500KB 이하
  JPG/PNG, 배경 지우기·합성·과도한 보정 금지
- 주민등록증 (행정안전부, 주민등록법 시행규칙 제9조): 3.5×4.5cm, 6개월 안, 정면 상반신, 모자 없음, 보정·복사 사진 안 됨.
  머리 길이 기준은 없다 (귀·눈썹 요건은 2019-02 삭제). 여권 규격 사진을 받으므로 여권 규격 하나로 맞춘다

## 2. 어떻게 만드는지

### 파일

| 파일                                       | 역할                                                                             |
| ------------------------------------------ | -------------------------------------------------------------------------------- |
| `src/tools/image/id-photo/App.svelte`      | 화면: 데이터 받기, 미리보기(끌기·키보드), 맞추기 버튼, 확인, 다운로드            |
| `src/lib/face/face.ts`                     | 얼굴 찾기 워커를 띄우고 부른다, 데이터 목록·동의 이름                            |
| `src/lib/face/face.worker.ts`              | MediaPipe Face Landmarker (점 478개), Image Segmenter (사람·배경)                |
| `src/lib/face/photo.ts`, `photo.worker.ts` | 사진 읽기·줄이기·결과 JPG 만들기 워커 (원본은 워커가 들고 있다)                  |
| `src/lib/face/id-photo.ts`                 | 규격, 기울기·정수리 읽기, 자동 칸, 배경 나눌 영역·사람만 남기기, 그리기·JPG 저장 |
| `scripts/copy-face-data.mjs`               | 엔진(wasm)·모델을 `public/data/face/`로 복사하고 크기·SHA-256 목록               |
| `vendor/mediapipe/`                        | 얼굴 점 모델·사람 영역 모델 (npm에 없어 그대로 커밋, Apache-2.0)                 |
| `scripts/samples/face.jpg`                 | 견본 얼굴 (이미지 생성 AI로 만든 가상 인물, `make_samples.py`가 복사)            |

### 처리 흐름

1. 사진 고르기 → 사진 워커가 `createImageBitmap`(EXIF 방향 적용)으로 읽고, 미리보기용(긴 변 1600)과 살피기용(긴 변 600 픽셀)
   사본을 화면에 넘긴다. 큰 사진도 화면 스레드를 막지 않는다
2. 데이터가 보관돼 있으면 바로, 없으면 "데이터 받기"(엔진 13.5MB + 모델 3.7MB + 사람 영역 모델 0.25MB) 뒤에 얼굴을 찾는다.
   그동안은 사진 가운데 칸
3. `readFace`: 두 눈동자(468·473)로 기울기, 152번이 턱, 10번(이마 꼭대기)에서 위로 올라가며 정수리를 찾는다
4. `autoPlace`: 머리 길이 3.4cm(범위 가운데), 정수리가 위에서 0.4cm, 두 눈 가운데가 좌우 가운데인 칸
5. 배경을 고르면 `matteRegion`(칸 둘레를 칸 높이의 15%씩 넓힌 네모)을 미리보기 사진에서 긴 변 512로 잘라 나누고,
   사진 워커가 원본에서 `cutout`으로 사람만 남긴 그림(미리보기 크기)을 넘기면 그 색 위에 그린다. 칸을 그 영역 밖으로 옮기면(`matteCovers`) 다시 나눈다
6. 사용자가 고친 칸으로 원본에서 413×531을 그려 JPG로 저장 (500KB를 넘으면 화질을 낮춤). 배경을 바꿨으면 같은 마스크를
   원본 크기로 늘려 쓴다

### 결정과 이유

- MediaPipe를 격리 frame에서 띄우는 법: `FilesetResolver`는 글루 JS를 `importScripts`로, wasm을 `fetch`로 받는다.
  대신 ES 모듈 글루(`vision_wasm_module_internal.js`)를 워커에 번들해 `self.ModuleFactory`로 두고 `wasmLoaderPath`를
  비운다. wasm 바이트는 `Module.instantiateWasm`으로 넘긴다 (`Module.wasmBinary`는 이 빌드가 읽지 않아 안 됐다)
- MediaPipe는 60초마다 사용 통계를 `odml.pa.googleapis.com`으로 보내는 코드를 품고 있다. CSP가 막지만, 워커의 `fetch`를
  없애 시도도 하지 않게 했다 (워커는 fetch가 필요 없다). 안전 페이지에 밝혔다
- 정수리: 처음에는 사진 귀퉁이 색을 배경으로 봤는데, 스튜디오 사진은 귀퉁이가 그늘져 4장 중 3장에서 실패했다.
  머리 바로 위(이마에서 얼굴 길이 0.9배 위) 띠의 색을 배경으로 보고, 위에서 내려오며 배경과 다른 점이 3할을 넘는 곳으로
  바꿨다. 무늬 배경에서 다른 무늬를 정수리로 잡는 것을 막으려고 이마~정수리 사이에 배경 같은 줄이 1할을 넘으면 버린다
- 찾지 못하면 이마 꼭대기 위로 이마~턱 길이의 0.35배로 어림한다 (흰 배경 사진 4장에서 0.30~0.45)
- 모델은 블렌드셰이프까지 든 원본 그대로 쓴다 (빼면 0.9MB 줄지만 고친 파일은 확인할 출처가 없어진다)
- 사람 영역 모델: `selfie_segmenter`(250KB)와 `selfie_multiclass_256x256`(16MB)을 비교했다. 성조기 배경 공개 초상 3장에서
  큰 모델은 깃발이 흐릿하게 남았고 작은 모델은 깨끗했다. 흰 배경 사진의 머리카락 가장자리는 비슷했다. 그래서 작은 것을 얼굴
  데이터에 함께 넣어 받기 한 번으로 끝낸다. 사진 전체가 아니라 칸 둘레만 넣어야 머리 가장자리가 덜 뭉개진다
- 마스크 가장자리는 넓게 번져 원래 배경이 비친다. 확신 15% 아래는 버리고 85% 위는 다 채우도록 늘린다.
  색이 강한 배경(빨간 깃발)은 머리카락 끝에 조금 남는다
- 엔진은 한 번 컴파일해 두 작업이 같이 쓴다. 나누기 작업은 배경을 고를 때 처음 띄운다 (엔진 메모리를 하나 더 쓴다)
- 좌우 반전은 칸의 성질(`flip`)로 두고 그릴 때 가로로 뒤집는다. 뒤집으면 옮기기·기울이기의 원본 방향이 반대라
  화면에 보이는 방향대로 움직이게 부호를 바꾼다. "자동으로 다시 맞추기"는 반전을 그대로 둔다

### 주의할 점

- "데이터 받기"가 돌려준 바이트로 바로 엔진을 띄운다. 버리고 다시 `loadData`를 부르면 보관소가 없는 창(시크릿 모드)에서 두 번 받는다

- 기울기 부호: `angle`은 눈을 잇는 선의 각도(화면 기준 시계 방향 +), 그릴 때 `rotate(-angle)`. `inCrop`·`outside`·
  `headLength`가 같은 축(u: 눈 방향, v: 아래)을 쓴다
- 데이터 받기 버튼 이름에 크기가 붙는다. 가이드·사용법에는 "데이터 받기"로 적는다 (따라 하기가 앞부분으로 찾는다)
- 견본은 이미지 생성 AI로 만든 가상 인물이다 (`scripts/samples/face.jpg`). E2E의 `tests/fixtures/face.jpg`는 NASA 공개 사진이라 견본으로 쓰지 않는다
- 배경을 나누는 동안에는 다운로드를 막는다. 막지 않으면 원래 배경으로 저장된다
