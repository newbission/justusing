## 1. 어떤 기능인지

- 동영상 앞뒤를 잘라 원하는 구간만 남긴다
- 입력: 동영상 하나 (MP4·MOV·WebM·MKV). 화면 트랙이 있고 코덱을 알아야 한다
- 출력: 같은 그릇의 동영상 `<이름>_자름.<원래 확장자>` (영어 `_trimmed`)
- 빠르게(기본): 다시 인코딩 없이 옮긴다. 시작 앞의 가장 가까운 키프레임부터 담고 MP4·MOV는 편집 목록으로 고른 시점부터 재생되게 한다.
  WebCodecs가 없어도 된다
- 정확하게: 화면을 다시 인코딩해 고른 장면이 첫 장면이 된다(MP4·MOV·MKV는 H.264, WebM은 VP9, 못 하면 mediabunny가 그릇에 맞는 다른 코덱). 소리는 옮긴다

하지 않는 것·한계 (화면·FAQ·가이드에 밝힘)

- 빠르게 자른 파일을 편집 목록을 읽지 않는 프로그램은 앞 키프레임부터(몇 초 안) 보여 줄 수 있다. WebM·MKV는 음수 시각으로 적어 프로그램마다 다를 수 있다
- 구간은 하나만. 중간을 들어내거나 여러 구간을 잇지 않는다
- 빠르게는 시작 앞 10초 안에 키프레임이 있을 때만 (`FAST_TRIM_MAX_LEAD`). 넘으면 실패('copy')로 '정확하게'를 권한다.
  WebM·MKV는 32.767초 넘게 앞선 블록을 mediabunny가 말없이 버려 풀 수 없는 파일이 되고, MP4·MOV는 숨긴 앞부분이 길게 남기 때문 (2026-10-23 리뷰)
- 미리보기는 브라우저 `<video>`가 재생할 수 있을 때만 (Safari의 MKV 등은 미리보기 없이 숫자로 고른다)

### 처리 흐름

1. 열면 처음부터 끝까지가 고른 구간. 손잡이·시간 칸·'지금 위치를'으로 바꾼다 (가장 짧게 0.1초, 시작은 끝 - 0.1초를 넘지 않음)
2. "자르기" → `{ kind: 'trim', start, end, exact }` → 결과 길이·크기 → "받기"
3. 설정(시작·끝·방법)을 바꾸면 지난 결과는 가린다 (key)

### 결정과 이유

- 빠르게를 기본으로: 대부분의 쓰임(보내기·올리기)에 충분하고 몇 초면 끝나며 WebCodecs 없이도 된다. mediabunny의 `expand` 정책이
  MP4에 편집 목록을 써 앞 키프레임 부분을 숨긴다 (ffprobe로 51장=1.7초가 보이는 것을 확인). `shrink`는 다음 키프레임부터라 고른 장면을 잃어 쓰지 않는다
- 결과 길이는 고른 길이로 보인다: 다시 읽으면 숨긴 장면까지 세어 1.8초처럼 보였다
- 오래 걸린 뒤에는 sandbox frame에서 사용자 동작 없는 다운로드가 막힐 수 있어 '받기'를 따로 누르게 한다 (PDF 압축과 같음)

### 주의할 점

- 정확하게는 이 브라우저가 화면 코덱을 풀고 **원래 크기로** 저장할 수 있을 때만 고를 수 있다 (`originalCodecs`, WebM은 VP9). 못 하면 까닭을 보인다
- 사용법의 버튼 이름("동영상 파일 선택"·"지금 위치를 시작으로"·"지금 위치를 끝으로"·"고른 구간 재생"·"자르기"·"받기")은 따라 하기가 찾는다. 바꾸면 같이 고친다

## 4. 검증

### 자동 테스트

- `tests/e2e/video-trim.spec.ts`
  - 빠르게: 2.5~4.2초 → 이름 `clip_자름.mp4`, H.264 1280×720·AAC, 첫 화면 시각 -0.5초(2초 키프레임부터 담김), 0.05초 장면 파랑·1초 장면 노랑
  - 정확하게: 1.5~3.5초 → 길이 2초, 첫 시각 0 이상, 첫 장면 초록
  - 손잡이 방향키(Shift 1초), 시간 칸·aria-valuetext, 지금 위치를 시작으로(끝 - 0.1초까지)
  - 키프레임이 0초 하나뿐인 16초 WebM·MP4: 12초부터 빠르게는 막고 '정확하게' 권함 → 정확하게는 됨, 8초부터 빠르게는 됨(첫 시각 -8초)
  - WebM은 WebM(VP9·Opus)으로, WebCodecs가 없으면 정확하게를 막고 빠르게만, 못 여는 파일·MPEG-4 Part 2 코덱 안내, 영어 화면
