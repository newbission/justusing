# pdf-ocr — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-15 엔진으로 Tesseract(`tesseract.js-core` SIMD LSTM)와 `tessdata_best` 정수판 한국어·영어를 골랐다 (모두 Apache-2.0).
  CDN에서 받지 않고 빌드 전에 `public/data/ocr/`로 복사하며, 크기·SHA-256 목록(`catalog.json`)을 남긴다.
- 2026-10-15 데이터(한국어+영어 약 7MB)는 받기 전에 크기를 밝히고 묻는다. 바깥 페이지 보관소(Cache API)에 두고, frame은 SHA-256·크기가 맞는 바이트만 쓴다.
  보관본이 지워지면 몰래 다시 받지 않고 다시 묻는다.
- 2026-10-15 인식 워커는 CPU 수에 맞추되 엔진 하나가 100MB 안팎을 써서 3개까지(메모리 4GB 이하 기기는 1개). 워커는 아무 데서도 받지 않고 `wasmBinary`를 직접 받는다.
- 2026-10-15 결과는 Tesseract가 만든 글자만 든 PDF를 원래 쪽 위에 겹친다. 그림은 화면에 보이는 모습대로 그렸으므로 겹칠 때 보이는 영역에 맞추고 쪽 회전만큼 거꾸로 돌린다. 회전한 스캔 쪽으로 E2E를 만들어 확인했다.
- 2026-10-16 (Codex P1) 300 DPI 그리기를 워커로 옮기라는 지적: 그리기는 화면에 두고 **한 번에 한 쪽씩 줄 세웠다**. pdf.js 화면 그리기는 프레임마다 쉬고, 워커에서 그리면 PDF를 한 번 더 열어 메모리가 두 배가 된다.
- 2026-10-16 데이터를 받는 동안 언어를 바꾸면 이전 진행률이 섞였다 → 받는 동안 언어 선택을 잠그고, 진행 콜백은 지금 고른 묶음일 때만 반영한다.
- 2026-10-16 글자가 하나라도 있으면 건너뛰어, 쪽 번호만 글자인 스캔 쪽을 읽지 않았다 → 본문 글자 50자 이상인 쪽만 건너뛴다.
- 남은 일: 배포 뒤 Safari 확인, (영어 FAQ의 데이터 크기 4MB → 약 6MB는 2026-10-16에 고쳤다).
