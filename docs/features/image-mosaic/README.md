## 1. 어떤 기능인지

- 사진에 찍힌 얼굴·번호판·전화번호 같은 개인정보를 가린 뒤 올리려고 쓴다
- 입력: 브라우저가 읽는 이미지 한 장 (브라우저가 못 읽는 HEIC는 libheif로 연다 ([HEIC 변환](../image-heic-to-jpg/README.md)): `openImage`가 `readable()`로 풀어 워커에 넘긴다). EXIF 방향은 적용해 바로 세워 연다
- 가릴 곳
  - 사진 위를 끌어 여러 개 그린다. 키보드로는 "가릴 곳 추가"(사진 가운데, 짧은 변의 30% 정사각형)
  - 모양: 사각형·타원. 가리는 방법: 모자이크·흐리게·검게 칠하기. 세기 1~10 (모자이크·흐림만)
  - 곳마다 따로 고른다. 고른 곳이 없으면 설정은 '새로 그릴 곳'의 것이고, 고른 곳의 설정을 바꾸면 새로 그릴 곳도 따라간다
  - 옮기기·크기 바꾸기: 끌기, 손잡이 8개, 방향키(사진 긴 변의 1%, Shift는 10배), 숫자 칸(왼쪽·위·폭·높이 px). 지우기는 Delete·Backspace 또는 버튼
  - 겹치면 뒤에 그린 곳이 앞의 결과 위에 걸린다
- 얼굴 찾기 (2026-10-24)
  - "얼굴 찾기"를 누르면 사진 속 얼굴들(단체 사진의 작은 얼굴 포함)을 찾아 가릴 곳으로 한꺼번에 넣는다. 왼쪽 얼굴부터 번호를 붙이고, 화면 읽기 프로그램에는 "(찾은 얼굴)"을 붙여 알린다
  - 넣는 모양: 얼굴 사각형보다 넉넉한 타원(머리카락·귀·턱까지). 사진 끝에 걸려 잘리면 사각형
  - 넣는 효과: 굵은 모자이크(세기 8 이상, 새로 그릴 곳의 세기가 더 높으면 그것). 새로 그릴 곳이 '검게 칠하기'면 검게 칠하기. 흐림은 되살릴 수 있어 얼굴에 쓰지 않는다
  - 이미 가린 곳 안에 가운데가 있는 얼굴은 넣지 않는다 (여러 번 눌러도 쌓이지 않는다)
  - 찾은 뒤에는 늘 "옆모습·아래를 보는 얼굴·가려지거나 아주 작은 얼굴을 놓칠 수 있으니 직접 더하라"고 알린다. 하나씩 빼기·고치기는 그린 곳과 같다
  - 데이터: 처음 누를 때 크기를 밝히고 묻는다(엔진 13.5MB + 모델 1.1MB, 증명사진·배경 제거에서 엔진을 받았으면 모델만). 받은 데이터는 바깥 보관소가 보관하고, 보관본이 모두 지워졌으면 "지워졌다"고 알리며 다시 묻는다. 취소하면 아무것도 받지 않는다
  - 한 번에 한 장이라 '모든 사진에서 찾기'는 없다 (여러 장을 다루게 되면 장마다 찾기와 함께 더한다)
- 형식: JPG·PNG·WebP. 처음에는 원래 형식(그 밖의 형식은 JPG). JPG·WebP 화질 0.92
- 출력: `<원래 이름>_모자이크.<jpg|png|webp>` (영어 `_mosaic`)
- 정보 보안 (화면·FAQ·가이드에 같은 내용)
  - 흐림과 칸이 작은 모자이크는 되살려질 수 있다고 밝히고, 꼭 감출 정보에는 검게 칠하기를 권한다 (화면의 강조 안내, 방법마다 설명)
  - 저장은 원래 크기로 다시 그려 한다. 가린 곳에는 바꾼 화소만 있고, 원본의 EXIF·미리보기 그림·덧붙은 자료는 옮기지 않는다
  - 바꾼 화소는 가린 곳 안의 화소로만 계산한다 (검게 칠하기는 원래 화소를 쓰지 않는다)
- 하지 않는 것·한계
  - 번호판·글자 자동 찾기는 하지 않는다 (얼굴만 찾는다)
  - 얼굴 찾기는 화면의 미리보기(긴 변 1,600px)에서 한다. 긴 변의 1%쯤보다 작은 얼굴, 옆모습·아래를 보는 얼굴·가려진 얼굴은 놓칠 수 있다 (모델 카드도 "카메라를 보지 않는 얼굴, 5m보다 먼 사람"을 범위 밖으로 적는다)
  - 자유 붓(손으로 칠하기)은 없다. 사각형·타원으로 대부분을 덮을 수 있어 뺐다
  - 한 번에 한 장
  - 휴대폰에서 사진 위를 쓸면 그리기가 되어 화면이 스크롤되지 않는다 (사진 칸은 높이 480px까지라 그 밖에서 스크롤한다)
  - canvas 한계(아이폰 약 1,670만 화소)를 넘는 사진은 PNG·JPG만 저장된다(JPG는 2026-10-23부터). WebP는 "PNG나 JPG로 저장해 보세요"를 띄운다 (자르기·회전과 같음)

### 처리 흐름

1. 파일을 고르면 워커가 바로 세워 읽고 원본 `ImageBitmap`을 들고 있는다. 화면에는 긴 변 1,600px 미리보기만 넘긴다
2. 가릴 곳은 원본 화소 기준 정수 사각형(`Region`: 자리·모양·방법·세기)이다
3. 미리보기: 가릴 곳이 바뀌면 `previewImage(regions)`를 부른다. 워커가 따로 들고 있는 미리보기 사진에 가릴 곳마다 줄인 자리(실수)의 화소를 읽어 `paint()`(칸 크기·흐리는 거리도 줄인 만큼)로 고치고 그림(`ImageBitmap`)으로 돌려준다. 화면은 그 그림을 미리보기 크기 canvas에 그리고 CSS로 칸(최대 높이 480px)에 맞춰 늘인다. 위에 가릴 곳 버튼과 손잡이를 % 자리로 겹친다
   - 요청은 한 번에 하나만 보낸다. 그사이 바뀌면 끝난 뒤 가장 최근 것 하나만 다시 보내고, 사진이 바뀌었으면(`generation`) 늦게 온 그림을 버린다. 테두리·손잡이는 바로 따라오고 효과만 조금 늦게 바뀐다
4. "가린 이미지 받기" → 워커가 원본 크기 canvas에 그리고(JPG는 흰 바탕), 가릴 곳마다 그 자리 화소만 `getImageData` → `paint()` → `putImageData`, 저장
   - 저장은 `saveDrawing()`([이미지 공통](../../foundations/image-common/README.md)의 "큰 결과 저장"). canvas를 만들 수 없는 크기면(맨 끝 화소로 확인) 가릴 곳마다 먼저 고쳐 두고(앞의 결과를 겹친 곳에 반영) 사진을 줄 묶음씩 그려 고친 화소를 덮어 PNG는 `PngStream`, JPG는 `JpegStream`(2026-10-23)으로 이어 쓴다. JPG면 가릴 곳·줄 묶음 모두 흰 바탕 위에 그려 한 번에 그린 결과와 같게 한다. WebP는 `tooLarge`

### 얼굴 찾기 흐름 (2026-10-24)

1. "얼굴 찾기" → `import('find-faces')`·`import('frame/data')`(처음 한 번) → `dataStatus`로 보관 여부를 바깥 보관소에 묻는다 (네트워크 없음)
2. 모자란 것이 있으면 크기를 밝힌 받기 칸("데이터 받기 (n MB)"·"취소")을 띄우고 초점을 받기 버튼으로 옮긴다. 받으면 그 바이트로 바로 엔진을 띄운다 (보관소가 없는 창에서 두 번 받지 않게)
3. 보관돼 있으면 `loadData`로 보관본을 받아(확인 뒤) 엔진을 띄운다. 엔진은 사진을 바꿔도 다시 쓴다
4. 미리보기 그림을 복사해 워커에 넘긴다. 워커는 사진 전체 + 긴 변을 3·6·10등분(30% 겹침, 가장 작게 160px)한 조각마다 192px로 줄여 찾고, 조각 경계에 닿은 얼굴은 버리고(잘려 치우친 사각형), 같은 얼굴을 합친다. 조각마다 진행률을 알린다
5. 화면이 미리보기 → 원본 배율로 돌려 가릴 곳을 만든다 (`coverOf`: 가운데를 얼굴 높이의 1/4 위로, 반지름 가로 0.75·세로 1.0배)

### 얼굴 찾기 결정과 이유

- **모델은 BlazeFace full range (1.1MB)**: 같은 엔진(`@mediapipe/tasks-vision` 1.1.1)의 Face Detector로 돈다. 비교(2026-10-24, 가상 인물 6명 단체 사진 2000×1200, 얼굴 폭 22~200px):

  | 모델                                      | 크기  | 사진 전체 한 번 | 조각 3·6·10등분까지 | 얼굴 없는 사진 4장 |
  | ----------------------------------------- | ----- | --------------- | ------------------- | ------------------ |
  | `blaze_face_short_range` (앞 카메라용)    | 230KB | 0명             | 5명 (폭 22px 놓침)  | 확인 안 함         |
  | **`blaze_face_full_range` (뒤 카메라용)** | 1.1MB | 3명             | **6명**             | **0곳**            |
  - Face Landmarker(증명사진, 3.7MB)는 얼굴 점 478개까지 구해 무겁고, 안의 얼굴 찾기도 앞 카메라용이라 고르지 않았다
  - 허가: 모델 카드 "LICENSED UNDER Apache License, Version 2.0" (`vendor/mediapipe/README.md`에 주소·SHA-256)

- **조각으로 나눠 본다**: 모델은 192×192로 줄여 보므로 1,600px 사진 전체에서는 폭 80px보다 작은 얼굴을 놓친다. 10등분 조각까지 보면 폭 12px쯤까지 찾는다. 데스크톱 크롬에서 1,600×1,200 사진이 조각 117개, 1.3초 안팎
- **조각 경계에 닿은 얼굴은 버린다**: 잘린 얼굴의 사각형이 한쪽으로 치우쳐 합칠 때 칸이 어긋났다. 조각이 30% 겹치고 큰 조각도 보므로 그 얼굴은 다른 조각에서 통째로 보인다
- **타원으로 넉넉하게**: 모델의 사각형은 눈썹~턱이라 머리카락·귀가 밖에 남는다. 견본에서 머리 꼭대기·귀·턱이 들어오도록 키웠다
- **굵은 모자이크가 기본**: 화면의 권장(꼭 감출 것은 검게 칠하기, 모자이크는 세기를 높여)을 따른다. 흐림은 되살릴 수 있어 쓰지 않는다
- **코드도 누를 때 받는다**: 모자이크만 쓰는 사람의 첫 화면·사진 열기에 얼굴 찾기 코드·워커·데이터가 하나도 오지 않는다 (E2E가 요청으로 확인, `perf-budget`의 `LAZY_TOOLS`)
- **동의 이름을 따로 둔다**(`find-faces`): 증명사진(`face`)·배경 제거(`cutout`)와 받는 파일이 달라, 한 도구의 동의로 다른 도구의 "지워졌다"를 판단하지 않게 했다. 엔진은 경로가 같아 보관본을 같이 쓴다

### 가리는 계산 (`paint`)

- 가릴 곳 안: 화소 가운데가 사각형 안, 또는 타원 식 안. 경계는 반쯤 섞지 않는다(가린 곳 밖은 원본 그대로, 안은 바꾼 화소만)
- 세기: `amountOf = round(짧은 변 × 세기 / 40)` (모자이크 최소 2px, 흐림 최소 1px). 세기 5면 짧은 변의 1/8
- 모자이크: 가릴 곳 왼쪽 위부터 칸으로 나눠, 칸 안이면서 가릴 곳 안인 화소의 평균(투명도로 가중)으로 칠한다. 칸 크기가 실수여도 된다(미리보기)
- 흐림: 가릴 곳을 감싼 사각형의 화소만 써서 상자 흐림을 가로·세로로 세 번(반지름 ≈ 세기 값 / 1.7, 끝은 끝 화소를 늘임). 투명도를 곱한 색으로 흐려 투명한 곳 색이 번지지 않는다
- 검게 칠하기: (0, 0, 0, 255)

### 결정과 이유

- **세기는 가릴 곳 크기에 비례**: 고정 화소면 작은 글자에는 너무 크고 큰 얼굴에는 너무 작다. 칸 수가 알아보기 정도를 정하므로 짧은 변에 맞췄다. 실제 칸 크기는 막대 옆에 보인다
- **평균을 직접 계산**: canvas로 줄였다 늘이면 브라우저가 칸마다 몇 화소만 골라 쓸 수 있어(원래 화소 하나가 그대로 남음) 직접 평균한다
- **흐림을 직접 계산**: canvas `filter`는 Safari에서 지원이 늦었고, 미리보기와 결과가 같아야 해서 같은 함수로 계산한다
- **원본도 미리보기 효과도 워커에서**: 수천만 화소를 화면 스레드에서 고치면 멈춘다. 1,600px 미리보기라도 큰 곳을 흐리면 한 번에 1초가 넘어, 처음에 화면 스레드에서 그렸다가 끄는 동안 멈춘다는 리뷰 지적으로 옮겼다. 화면 스레드에서 화소를 읽고 고치는 곳은 없다
- **고른 곳의 설정 = 새로 그릴 곳의 설정**: 같은 방법으로 여러 곳을 가리는 일이 많아, 하나를 바꾸면 다음에 그릴 곳도 따라가게 했다
- **한 장씩**: 사진마다 가릴 곳이 달라 여러 장 목록 화면(`ImageBatchTool`)을 쓰지 않았다
- **견본은 그린 차 사진**: 실제 사람 얼굴을 쓰지 않으려고 지어낸 번호판(00가 0000)과 앞 유리 안 연락처 카드를 그렸다

### 주의할 점

- 미리보기와 저장이 같은 `paint()`(같은 워커의 `applyRegion`, 미리보기는 `scale`만 다름)를 쓴다. 계산을 바꾸면 둘 다 바뀌므로 E2E의 화소 비교로 확인한다
- 미리보기 요청은 저장과 같은 워커 줄에 선다. 큰 사진을 저장하는 동안에는 미리보기가 저장이 끝난 뒤 바뀐다
- 워커는 요청을 온 순서대로 하나씩 처리한다 (자르기·회전과 같은 까닭). 워커가 죽으면 원본도 없어져 다음 저장은 `decode`로 "다시 열어 주세요"
- 숫자 칸은 `onchange`에서 반영하고 칸 값을 맞춘 값으로 되돌린다 (사진 밖·최소 8px은 `clampRect`)
- 가릴 곳을 지우면 초점을 다음 곳(없으면 "가릴 곳 추가")으로 옮긴다
- E2E에서 사진을 연 직후 누르기 전에 바깥 페이지 스크롤(`requestShowTool`)이 끝나기를 기다린다. 누르는 사이 버튼이 옮겨지면 사진 위를 눌러 그리기로 처리된다
- 격리 frame 규칙(워커는 `createWorker`, `style=""` 금지, form 금지)은 [격리 frame](../../foundations/frame-isolation/README.md)을 따른다
- 얼굴 찾기 워커는 `mediapipe-engine.ts`를 불러 fetch를 없앤다 (엔진에 든 사용 통계 전송을 시도하지도 않게). 엔진·모델은 화면이 넘긴 바이트만 쓴다
- 데이터를 확인하는 사이 사진을 바꾸면 찾지 않고 처음으로 돌아간다 (`generation`). 받는 중에 사진을 바꾸면 받기는 이어 하고 다 받은 뒤 새 사진에서 찾는다
- `frame/data`는 그냥 불러 둔다(작다). 처음에 `import()`로 불렀더니 번들러가 이름 묶음 도우미를 동영상 엔진 조각(120KB)에서 가져와, 그 모듈을 쓰는 다른 도구(OCR·증명사진·워터마크) 첫 화면이 그 조각까지 받았다 (perf-budget이 잡음). 누를 때 부르는 것은 `find-faces`뿐이다
- 실제 사람 사진은 견본·테스트에 쓰지 않는다. 얼굴 견본은 이미지 생성 AI로 만든 가상 인물(`scripts/samples/face.jpg`)뿐이다

### 자동 테스트

- `tests/e2e/image-mosaic.spec.ts` (시험 그림 `noise.png`: 80×60 화소마다 다른 색, 가릴 곳 왼쪽 10·위 10·40×30)
  - 미리보기: 검게 칠하기를 고르면 미리보기의 가린 곳이 검게 되고 밖은 그대로, 모두 지우면 원래 사진으로
  - 모자이크: 가린 곳 밖은 원본과 같고, 안은 90% 넘게 바뀌고 4×4 칸마다 같은 색 (세기 5 → 칸 4px). 파일 이름 `noise_모자이크.png`
  - 검게 칠하기: 밖은 그대로, 안은 모두 (0, 0, 0, 255). 세기 막대가 없다
  - 흐림: 밖은 그대로, 안은 90% 넘게 바뀐다
  - 타원: 네 귀퉁이는 원본 그대로, 가운데는 검다
  - 키보드: "가릴 곳 추가"로 넣으면 초점이 가고, 방향키로 옮기고, 모서리로 줄이고, Delete로 지우면 초점이 추가 버튼으로 가고 받기가 꺼진다
  - 끌어 그리기: 고른 방법(검게 칠하기)으로 그려지고, 빈 곳을 누르면 고른 것을 놓는다
  - EXIF 방향 6 사진은 300 × 400으로 열고 받는다
  - 견본으로 1,600 × 1,200 JPG를 받는다
  - canvas 한계를 낮추면(`canvas-limit.ts`) 가린 견본을 줄 묶음 JPG로 저장하고, canvas로 저장한 것과 평균 화소 차이 2 미만. WebP는 PNG·JPG를 권한다
  - 열 수 없는 파일은 알린다
  - 얼굴 찾기 (`faces.jpg`, 1600×1000, 얼굴 폭 29~180px 다섯 명)
    - 누르기 전에는 얼굴 찾기 코드·데이터 요청이 없다. 처음 누르면 크기를 밝히고 묻고, 취소하면 받지 않고 초점이 돌아온다
    - 받으면 5곳을 넣는다. 얼굴마다 한 곳이 그 얼굴 가운데를 덮고, 얼굴이 아닌 곳은 없다. 가장 큰 얼굴의 칸은 얼굴보다 넓다. 세기 8
    - 한 곳을 Delete로 빼고 PNG로 받으면, 넣은 얼굴 가운데 20×20은 80% 넘게 바뀌고 뺀 얼굴은 원본 그대로
    - 받은 데이터는 엔진·얼굴 찾기 모델 한 번씩뿐 (얼굴 점 모델 없음), 구글 주소 요청 없음
    - 다시 들어오면 묻지 않고 보관본으로 찾는다(데이터 요청 없음). 얼굴 없는 사진은 못 찾았다고 알린다. 한 번 더 누르면 겹치는 얼굴은 넣지 않는다
    - 모델만 지우면 "데이터 받기 (1.0MB)"(지워졌다고 하지 않음), 모두 지우면 "지워졌습니다"와 함께 다시 묻는다
