# PDF 나누기 (`pdf/split`)

- 주소: `/pdf/split/` (영어 `/en/pdf/split/`)
- 상태: live (2026-10-11 `e8f1050`에서 공개로 바꿈)
- 관련 문서: [히스토리](./history.md), [PDF 공통](../../foundations/pdf-common/README.md),
  [격리 frame](../../foundations/frame-isolation/README.md)
- 5-1단계. 여러 파일을 ZIP 하나로 받는 `src/lib/zip.ts`가 이 도구와 함께 생겼다 (뒤에 PDF를 이미지로도 쓴다)

## 1. 어떤 기능인지

- PDF 하나를 여러 파일로 나누거나, 고른 페이지만 뽑는다
- 입력: PDF 하나 (암호 PDF는 열 때 암호 입력)
- 나누는 방법 3가지 (좁은 화면에서는 짧은 이름)

| 방법           | 짧은 이름 | 결과                                                          |
| -------------- | --------- | ------------------------------------------------------------- |
| 범위로 나누기  | 범위      | 쉼표로 구분한 범위마다 파일 하나 (`1-3, 4-6, 7`)              |
| 한 장씩 나누기 | 한 장씩   | 쪽마다 파일 하나                                              |
| 고른 페이지만  | 고른 쪽   | 썸네일에서 누른 쪽을 모아 파일 하나 ("전체 선택"·"선택 해제") |

- 출력 이름
  - 결과가 하나면 PDF로 바로 받는다. 여러 개면 ZIP 하나: `<이름>_나눔.zip`
  - ZIP 안: 범위 `<이름>_1-3.pdf`, 한 장씩 `<이름>_01.pdf`(쪽수 자릿수만큼 앞에 0), 고른 페이지 `<이름>_발췌.pdf`
  - 영어 화면은 `_split.zip`, `_extracted.pdf`
- 범위 문법 (`src/lib/pdf/ranges.ts`, FAQ와 같음)
  - 구분: 쉼표·세미콜론·줄바꿈. 범위 `1-3` 또는 `1~3`, 끝까지 `5-`, 처음부터 `-3`, 한 쪽 `7`
  - 범위끼리 겹쳐도 된다 (각각 다른 파일)
  - 틀리면 이유를 바로 보여 준다: 알 수 없는 범위, 1부터 시작, 없는 쪽, 앞 번호가 더 큼
- 한계: 나눈 파일에는 암호가 걸리지 않는다 (FAQ)

## 2. 어떻게 만드는지

### 파일

| 파일                                | 역할                                                                            |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| `src/tools/pdf/split/meta.ts`       | 이름·설명·아이콘, 묶음 `pages`, 관련 도구(합치기·정리)                          |
| `src/tools/pdf/split/content.ts`    | 사용법 4단계(휴대폰의 짧은 버튼 이름 포함)·FAQ 4개                              |
| `src/tools/pdf/split/messages.ts`   | 방법 이름(긴·짧은), 막대 안내, 결과 이름 뒤에 붙는 말                           |
| `src/tools/pdf/split/App.svelte`    | 방법 고르기, 범위 입력, 쪽 격자, 실행 막대                                      |
| `src/lib/pdf/ranges.ts`             | `parseRanges(text, pageCount, locale)`, `rangeLabel(pages)` (`[1,2,3]` → `1-3`) |
| `src/lib/pdf/PageSelectGrid.svelte` | 쪽 격자. `selected`를 주면 고르기, 안 주면 보기 전용 + 쪽마다 메모("파일 1·2")  |
| `src/lib/pdf/SinglePdfTool.svelte`  | PDF 하나 도구 공통 틀: 파일 고르기·여는 중·암호·파일 이름 막대                  |
| `src/lib/pdf/assemble.ts`           | `assemblePdfs(job, onProgress)`: 원본은 한 번만 읽고 결과 파일 여러 개를 만든다 |
| `src/lib/zip.ts` + `zip.worker.ts`  | `makeZip(files)`: 워커에서 ZIP으로 묶는다. 같은 이름은 ` (2)`를 붙인다          |

### 처리 흐름

1. `SinglePdfTool`이 파일을 열고 `onload`를 부른다 → 결과·범위 입력·선택을 처음으로
2. 방법에 따라 `outputs: number[][]`(결과 파일마다 쪽 번호)를 계산한다. 나눌 수 없으면 `problem`에 이유
3. 범위·한 장씩 모드에서는 쪽 격자 아래에 각 쪽이 몇 번째 파일로 가는지 보여 준다 (입력한 범위를 눈으로 확인)
4. "PDF 나누기" → `canUse('pdf/split')` → `assemblePdfs({ sources: [원본], outputs })`. 파일 하나를 만들 때마다 진행률(`나누는 중… 12/30`)
5. 결과가 둘 이상이면 `makeZip()`으로 묶는다
6. 결과는 만든 때의 `signature`(방법 + outputs)와 묶여 있어, 방법·범위·선택을 바꾸면 결과를 버리고 다시 나누게 한다

### 결정과 이유

- **원본을 한 번만 읽는다**: 조립 워커가 `outputs` 배열을 받아 원본을 한 번 열고 결과를 차례로 만든다 (`ec8088d`)
- **여러 결과는 ZIP 하나로**: 파일을 여러 번 내려받게 하지 않는다. 결과가 하나면 PDF 그대로
- **`makeZip`은 바이트를 복사하지 않고 워커로 넘긴다**: 메모리를 두 배로 쓰지 않으려고. 부른 뒤에는 그 바이트를 쓸 수 없다
- **처리 중 다른 파일을 열면 결과를 버린다**: `pdf !== source`면 진행률·결과를 반영하지 않는다
- **좁은 화면(520px 이하)에서는 짧은 이름**: 긴 이름은 두 줄로 깨졌다 (`d635a70`). 사용법에도 짧은 이름을 적었다 (`c2a4b06`)

### 주의할 점

- 범위 입력에 `inputmode="numeric"`을 쓰지 않는다. 아이폰 숫자 자판에는 쉼표·하이픈이 없어 `1-3, 5`를 칠 수 없었다 (`3a8e326`)
- 범위 오류 문구는 `ranges.ts` 안에 언어별로 있다 (`frameLocale`을 넘긴다). 화면 문구를 바꾸면 `tests/e2e/ranges.spec.ts`도 본다
- 버튼 이름을 바꾸면 `content.ts` 사용법의 긴·짧은 이름도 같이 고친다
