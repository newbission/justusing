# pdf-common — 검증·오류·수정 히스토리

쓴 날 2026-10-16 · 고친 날 2026-10-16

## 요약

- 2026-10-11 결정: 합치기·나누기·회전·정리를 조립 워커 하나(`assemble`)로 묶었다. 원본은 한 번만 열고 결과 여러 개와 진행률을 낸다
  (한 장씩 나누기에서 300쪽 문서를 300번 읽던 것을 막음). PDF 하나 틀(`SinglePdfTool`)도 이때 뺐다
- 2026-10-11 오류: 처리 중 다른 파일을 열면 늦게 온 이전 결과가 새 파일의 "완료"로 보였다 → 시작한 파일과 지금 파일이 다르면 결과를 버린다
- 2026-10-14 결정: PDF 하나를 고치는 일(암호·쪽 번호·이미지 찍기·자르기)을 고치기 워커 하나로. 자리는 보이는 쪽 기준 비율로 받고 워커가 회전·CropBox를 계산한다.
  제한만 걸린 PDF는 빈 암호로 열어야 풀린다
- 2026-10-14 압축: PDF 안 사진을 다시 저장하며 색공간·ICC·EXIF 방향·예측 설정·미리 섞은 투명도 등으로 사진이 망가지는 경우를 여럿 찾아,
  원래 색공간을 지키거나(CalRGB·ICC는 화소·색공간을 그대로), EXIF 방향을 무시하고 읽거나, 다루기 어려운 사진은 건너뛰도록 고쳤다. 그만두면 PDF 워커·사진 워커를 통째로 끝낸다 (pdf-lib는 중간에 못 멈춤)
- 2026-10-15 리뷰 #29·#32: 쪽 그림 저장, 사진 회전·다시 저장, ZIP 묶기, 넣을 이미지 준비를 모두 워커로 옮겼다.
  측정해 보니 멈춤은 그리기가 아니라 저장에서 났다 (300 DPI 쪽마다 JPG 약 80ms·PNG 약 200ms). 색은 토큰(`--shadow-page`, `--color-paper`)으로
- 2026-10-15 결정: 글자 넣기 워커를 따로 둔다 (fontkit이 커서). 쓴 글자만 넣고 글꼴에 없는 글자는 미리 알린다.
  넣을 글자가 없으면 글꼴 없이 저장한다 (표지를 뺀 한 쪽 문서가 'font required'로 실패했다)
- 2026-10-15 큰 오류: 모아찍기의 `embedPages`가 주석을 옮기지 못해 양식 입력값·서명·도장이 조용히 빠졌다.
  인쇄되는 주석 모양을 쪽 내용에 먼저 그려 넣고(`flatten-annotations.ts`), 모양이 없으면 만들고, 못 그리면 알린다. 링크는 건너뛴다
- 2026-10-15 구조: 쪽 좌표 계산(`page-geometry.ts`), 쪽 내용 감싸기(`page-content.ts`), 쪽 그림(`renderPageBitmap`)을 공통으로 뺐다 (워터마크·OCR이 같이 씀)
- 2026-10-15 양식: 입력 칸 기본 글꼴에 한글이 없어 pdf-lib가 한글을 오류 없이 뺐다 → 글자 넣기 워커에서 고른 글꼴로 칸 모양을 다시 만든다
- 배운 점: pdf-lib는 못 하는 것을 조용히 빼거나 넘어가는 일이 많다 (주석, 한글 칸 값). 결과에서 빠진 것이 없는지 E2E로 확인하고, 못 하면 알린다
