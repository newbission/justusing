## 요약

- 2026-10-15 결정: 압축·크기 조절·형식 변환이 같은 일(읽기 → 크기 바꾸기 → 저장)이라 처리 모듈 하나(`process.ts`)로 묶었다.
  여러 장은 CPU 수에 맞춘 워커 1~4개가 나눠 처리한다 (큰 사진의 메모리 때문에 4개까지)
- 2026-10-15 오류: UPNG.js가 `require`나 `window.pako`로 zlib을 찾는데 번들된 워커에는 둘 다 없어 PNG 저장 전에 워커가 죽었다.
  `upng-globals.ts`가 먼저 불려 fflate로 `pako`를 넣어 준다. import 순서가 중요하다
- 2026-10-15 오류: 워커가 오류로 죽으면 답이 오지 않아 "줄이는 중"에 멈췄다. 워커 `error` 이벤트에서 그 이미지를 실패로 끝내고 워커를 버린다
- 2026-10-15 결정: 색을 줄이지 않는 PNG는 UPNG보다 브라우저 저장이 훨씬 빨라 브라우저로 저장한다 (크기 조절·형식 변환)
- 2026-10-15 리뷰 #36: 목록에서 뺀 이미지의 결과(다시 저장한 이미지 전체)가 남아 휴대폰 메모리가 모자랄 수 있었다.
  목록 화면에 `onremove`를 두고 도구가 결과를 지운다. 읽는 중에 뺀 이미지는 썸네일 주소를 만들지 않는다
- 2026-10-15 결정: 형식 변환을 위해 `anyFormat` 설정을 더했다. 디코딩은 브라우저에 맡겨 브라우저가 읽는 형식은 모두 받는다.
  압축·크기 조절은 다시 저장할 수 있는 JPG·PNG·WebP만 받는다
- 배운 점: 브라우저는 저장하지 못하는 형식을 요청하면 오류 없이 PNG를 준다. 받은 Blob 형식을 꼭 확인한다
