# frame-isolation — 검증·오류·수정 히스토리

## 요약

- 2026-10-10 결정: 광고·통계 스크립트가 파일 내용을 읽지 못하게 도구 영역을 출처 없는 sandbox iframe(`allow-scripts allow-downloads`)에 둔다.
  frame CSP는 `default-src 'none'`, 워커는 `createWorker()`가 blob URL 클래식 워커로 띄운다 (일반 `new Worker()`는 막힘)
- 2026-10-10 오류: 개발 서버는 워커를 ES 모듈로 내려줘 클래식 워커가 `import`에서 실패했다 → 개발 중(격리 꺼짐)에만 모듈 워커로 띄운다
- 2026-10-10 결정: 파일을 끌면 frame을 화면 전체로 넓혀 어디에 놓든 frame이 받게 하고, 바깥에 놓이면 `DropGuard`가 가장 먼저 막는다.
  넓어질 때 화면이 늘어나 보이던 문제는 "frame이 크기 고정 → 응답 → 넓힘" 순서로, 늦게 돌아오던 문제는 덮개의 `dragleave`로 고쳤다
- 2026-10-11 오류: 부드러운 스크롤 중에 버튼이 손 아래에서 움직여 엉뚱한 것이 눌렸다 → 바로(instant) 옮긴다
- 2026-10-11 오류: Cloudflare로 옮기면 출처 null인 frame이 우리 스크립트·워커·CMap을 받지 못했다 (GitHub Pages는 CORS 헤더를 늘 붙였다).
  `public/_headers`로 `/_astro/*`·`/vendor/*`에 CORS를 붙이고, 미리보기·E2E를 `wrangler dev`로 바꿨다 (`astro preview`는 이 문제를 가린다)
- 2026-10-13 결정: 광고 차단 안내를 도구를 쓸 때마다 띄우려고 내용 없는 `activity` 신호를 더했다
- 2026-10-15 큰 오류 (PR #40): Safari(WebKit)는 출처 없는 sandbox 문서에서 CSP `'self'`를 우리 사이트로 보지 않아,
  아이폰·맥 Safari에서 모든 도구가 워커·스타일·글꼴을 받지 못했다. 크롬 E2E로는 보이지 않았다.
  사이트 주소(`www.` 포함)를 `'self'`와 함께 적는다. 리뷰(P1)로 `style-src`에도 더했다
- 2026-10-15 오류: Astro `insertStyleResource`로 주소를 넣자 기본값 `'self'`와 `<style>` 해시가 빠져 PDF 보기가 깨졌다 (CI E2E 실패) → `'self'`를 먼저 직접 넣는다
- 2026-10-15 결정: frame은 저장소를 못 쓰고 브라우저 캐시도 방문마다 비워져, 도구 데이터는 바깥 페이지가 보관하고 frame은 SHA-256으로 확인한 뒤에만 쓴다
- 배운 점: 격리·CSP 문제는 개발 서버와 크롬에서 보이지 않을 수 있다. 빌드 결과를 `wrangler dev`로, 가능하면 Safari에서도 확인한다
