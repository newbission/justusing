# 작업 방식 (브랜치·커밋·PR·리뷰·배포)

쓴 날 2026-10-16 · 고친 날 2026-10-16

- 규칙의 원본: [`CLAUDE.md`](../../../CLAUDE.md)의 "작업 방식 (Git)"·"커밋 메시지 규칙", 리뷰 기준 [`AGENTS.md`](../../../AGENTS.md)
- 이 문서는 그 규칙이 실제로 어떻게 돌아가는지, 그리고 그동안 겪은 문제와 배운 점을 적는다
- 관련 문서: [히스토리](./history.md), [문서 규칙](../../README.md)

## 1. 무엇인지

한 사람(사용자)이 커밋 단위로 리뷰하고, 에이전트가 기능을 만들고, Codex가 PR을 리뷰하는 흐름이다.
사용자는 코드를 직접 짜지 않고 커밋과 결과를 본다. 그래서 커밋이 작고 이유가 분명해야 한다.

## 2. 어떻게 하는지

### 브랜치와 병합

| 단계                  | 방법                                                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 기능                  | `dev`에서 `<타입>/<짧은-설명>` 브랜치 (예: `feat/pdf-redact`)                                                              |
| 기능 → `dev`          | PR + Codex 리뷰 + CI 통과 → **Rebase merge** (`gh pr merge N --rebase --delete-branch`). 작은 커밋이 그대로 남는다         |
| `dev` → `main` (배포) | PR → **Squash merge** (`gh pr merge N --squash --subject "<제목>" --body "<배포에 담긴 것>"`). 배포 한 번 = main 커밋 하나 |
| 배포 뒤               | `main` → `dev` PR을 병합 커밋으로 넣는다 (`--merge --subject "chore: main 병합 반영 추가"`). 안 하면 다음 배포 때 충돌     |
| 배포                  | `main`에 들어가면 Cloudflare가 빌드·배포. Cloudflare는 CI를 보지 않으니 main은 CI 통과한 PR로만                            |

`main`·`dev`에 직접 커밋하지 않는다 (브랜치 보호).

### 커밋

- 커밋 하나 = 변경 하나. 고친 것(`fix`)과 그 테스트(`test`)와 문구(`docs`)는 따로 커밋한다
- 제목: `<타입>(<영역>): <한국어 제목>` — "~ 추가/수정/제거/변경"으로 끝낸다. 본문은 **왜** 바꿨는지
- 마지막 줄 `Co-Authored-By: …`
- 한 파일에 여러 변경이 섞이면 중간 상태 파일을 만들어 차례로 커밋한다 (대화형 `git add -p`를 못 쓰는 환경)

### PR

- 제목은 커밋 제목과 같은 형식. 본문은 `## 왜` → `## 바뀐 것` → `## 확인` (필요하면 `## 병합 뒤 할 일`)
- 한 작업 단위에 PR 하나 (PR이 많으면 사용자 메일이 넘친다)
- 만든 직후 `@codex review` 댓글로 리뷰를 부른다 (자동 리뷰는 꺼 둠). `dev`→`main`, `main`→`dev` PR은 부르지 않는다

### Codex 리뷰를 받는 법

1. 지적을 읽고 **같은 종류의 다른 경우를 먼저 찾는다** (아래 "배운 점" 1)
2. 고치고, 그 상황을 재현하는 E2E를 더한다. **예전 코드에서 그 테스트가 실패하는지** 확인한다
   (`git stash push <고친 파일>` → 빌드 → 테스트 → `git stash pop`)
3. 작은 커밋으로 올리고, 지적마다 답글(고친 커밋 해시와 방법, 테스트)을 달고 대화를 해결(resolve)한다
4. `@codex review`를 다시 부른다. 지적이 없을 때까지 되풀이한다
5. 타당하지 않다고 본 지적은 고치지 않고 답글로 이유를 남기고, **사용자에게 알린다**

보조 스크립트(세션 스크래치에 두고 썼다): PR 번호를 받아 그 head 커밋의 Codex 리뷰 완료와 CI 결과를 기다려 한 줄씩 알려 준다.
Codex 상태는 PR 댓글의 `codex-review-state` 표시(`commit_sha`, `status`)로 알 수 있다. 사용량 한도에 걸리면 `status: failed`와
"usage limits" 댓글이 달린다 — 잠시 뒤 `@codex review`를 다시 부르면 된다.

### 확인 (CI와 같게)

```sh
npm run check   # 종료 코드로 판단한다 (astro check의 오류는 소문자 "error"라 grep으로 놓치기 쉽다)
npm run build
PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/<도구>.spec.ts
npx prettier --check <파일>
```

- 개발 서버는 격리·CSP가 꺼져 있어 배포에서만 깨지는 문제를 못 본다. E2E는 빌드 결과를 `wrangler dev`로 띄워 돌린다
- 로컬 WebKit(Playwright)은 frame CSP가 배포 도메인만 허용해 도구가 돌지 않는다. Safari 확인은 배포된 사이트에서 한다

### 문서

- 기능을 만들거나 고치면 그 기능의 `docs/features/<id>/README.md`를 같은 PR에서 고친다 ([문서 규칙](../../README.md))
- 병합 뒤 `node scripts/docs/history.mjs`로 히스토리 기록을 새로 만든다

## 3. 체크리스트 (기능 하나를 끝낼 때)

- [ ] 작은 커밋들 + 각 수정마다 예전 코드에서 실패하는 E2E
- [ ] `npm run check`(종료 코드 0)·`npm run build`·해당 E2E·`prettier --check`
- [ ] PR 본문(왜·바뀐 것·확인), `@codex review`
- [ ] 지적마다 같은 종류까지 고치고 답글·해결, 지적이 없을 때까지
- [ ] CI 통과 → rebase merge → (배포 때) squash merge + main→dev 병합
- [ ] 배포 뒤 실제 사이트에서 확인 (Chrome·Safari·휴대폰 390×844)
- [ ] 기능 문서·`CLAUDE.md` 진행 상황 갱신, `history.mjs` 실행

## 4. 겪은 문제와 배운 점

| 날짜       | 무엇이 있었나                                                                                                                                       | 배운 점·바꾼 방식                                                                                                                                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-10-15 | 타입 오류가 있는데 `grep "error"`로 확인해 놓쳤다 (astro check는 소문자 `error`)                                                                    | `npm run check`의 **종료 코드**로 판단한다                                                                                                                                                                                             |
| 2026-10-15 | 크롬 E2E는 통과했는데 Safari에서 도구가 하나도 안 됐다. Safari는 출처 없는 sandbox 문서에서 CSP `'self'`를 우리 사이트로 보지 않는다                | frame CSP에 사이트 주소를 함께 적는다. 배포 뒤 Safari를 실제로 확인한다 ([frame-isolation](../frame-isolation/README.md))                                                                                                              |
| 2026-10-16 | 가리기·사진 꺼내기·문서 정보 PR에서 Codex 리뷰가 10번 넘게 돌며 매번 2~4개씩 새 지적이 나왔다. 지적된 한 줄만 고쳐, 리뷰 한 번에 한 칸씩만 나아갔다 | **지적은 한 종류의 예시로 보고, 같은 종류를 먼저 모두 찾아 한 번에 고친다.** 같은 모양의 지적이 되풀이되면(예: "이 항목도 빼라") 설계를 바꾼다 — 빼는 목록(블랙리스트) 대신 **남기는 목록(화이트리스트)** (가리기 `rendering-only.ts`) |
| 2026-10-16 | 리뷰가 끝나지 않자 "언제 병합할지"를 물었다                                                                                                         | 사용자 결정: 타당한 지적은 끝까지 고친다. 타당하지 않다고 본 것만 이유와 함께 알린다                                                                                                                                                   |
| 2026-10-16 | Codex 사용량 한도로 리뷰가 실패했는데 모니터가 "완료"만 기다렸다                                                                                    | 리뷰 상태의 `failed`도 확인하고 다시 부른다                                                                                                                                                                                            |
| 2026-10-16 | 문서가 `CLAUDE.md`와 커밋에만 흩어져 있어 다른 세션이 이어 가기 어려웠다                                                                            | `docs/` 기능별 문서와 자동 히스토리(`scripts/docs/history.mjs`)를 만들었다                                                                                                                                                             |
