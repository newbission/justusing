## 요약

- 2026-10-14: 8단계(무거운 PDF 도구) 방향을 정함. 큰 데이터는 그 도구에서만 받고, 받기 전에 크기를 밝힌다
- 2026-10-15: 한글 글꼴 8종(OFL)을 직접 호스팅하기로 함. 한자를 빼고 한글 음절·영문·숫자·문장부호만 남겨 WOFF2로 만든다
- 2026-10-15: WOFF2 글리프 변환을 켜면 fontkit이 `loca` 표를 찾지 못해 PDF에 넣지 못했다 → 변환을 끄고 만든다
- 2026-10-15: 격리 frame은 저장소를 못 쓰고 브라우저 캐시도 방문마다 비워진다(크롬에서 확인) → 바깥 페이지가
  Cache API에 보관해 넘겨주고, frame은 빌드 때 적은 SHA-256·크기로 확인한 뒤에만 쓰는 구조를 만듦 (광고 스크립트가 끼어들어도 안전)
- 2026-10-15: 받기로 한 것을 `data-consent`에 적어, 보관본이 지워지면 조용히 다시 받지 않고 다시 묻는다
- 2026-10-15 (리뷰 P2): 해시가 다른 응답도 먼저 보관해서, 한 번 잘못 받으면 다시 받아도 손상본만 돌아왔다 →
  맞는 것만 보관하고 다른 보관본은 지우고 다시 받는다 (`bb426fe`)
- 2026-10-15 (리뷰 P1): 글자를 덜어 낸 글꼴은 OFL의 고친 판이라 Pretendard·Nanum의 예약 글꼴 이름을 쓸 수 없었다 →
  파일 안 이름과 화면 이름을 우리 이름(JUS …, 모던 고딕 등)으로 바꾸고 원본은 출처로만 밝힘. 글꼴을 더할 때 허가서부터 본다
- 2026-10-15~16 (리뷰 P2 여러 개): `FontPicker`의 비동기 경쟁 — 늦게 끝난 받기·올리기가 나중 선택을 덮음, 저절로 고르기가
  사용자 선택을 덮음, 다시 올린 글꼴이 같은 id라 이전 결과를 다시 내려받음 → 고르기·올리기마다 번호를 두고 마지막 것만 반영,
  올릴 때마다 다른 id. 배운 점: 기다리는 동안 사용자가 다른 것을 고를 수 있는 곳은 처음부터 번호로 막는다
- 2026-10-15: OCR 엔진·언어 데이터도 같은 보관소를 쓴다. 패키지 버전과 맞아야 해서 커밋하지 않고 dev/build 전에 복사한다
