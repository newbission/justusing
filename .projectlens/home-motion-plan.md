# 홈 주요 작업 장면 기획 — 2026-11-13

## 목표와 출처

사용자의 최신 요청은 “사진을 PDF로 만들었다면 한 PDF로 보이는 결과”, “핵심 기능의 주요 동작을 모션그래픽이나 이미지로 설명”, “구성·문구를 기획·구현·검증 에이전트가 분리해서 검토”다. 이전 카드 6개를 유지하는 것이 목표가 아니다. 초면 사용자가 **무엇을 넣고, 무엇을 하면, 어떤 파일을 받는지** 이해하고 맞는 도구로 시작하는 것이 목표다.

사용자가 자율 진행과 역할 분리를 명시했으므로 합리적 판단으로 실행한다. 본 문서는 기획 담당의 구현 기준이며 사용자 최종 수용을 대신하지 않는다. 이전 작업 기록은 보존하고 이번 요청의 변경 기준으로 추가한다.

## 관찰한 문제

- 기존 `HomeShowcase`는 동급 카드 6개에 합성 WebP 하나씩을 놓는다. 서로 다른 작업이 같은 사진 장식 방식으로 보이고, 어떤 조작이 차이를 만드는지 보이지 않는다.
- 이미지→PDF 그림은 실제 PDF의 두 쪽을 독립 종이처럼 떨어뜨려 보여 준다. 실제 출력은 3쪽짜리 PDF 한 파일인데 사진 두 개를 새로 만드는 것처럼 읽힌다.
- “사진도 문서가 됩니다”, “원하는 장면만, 딱” 같은 제목은 분위기는 있지만 구체적 작업을 늦게 알려 준다.
- 기존 E2E는 그림 로드와 링크 진입을 확인하지만 결과가 올바른 형식으로 인식되는지는 검증하지 않았다.

## 범위와 선택

사진 용량 줄이기 hero는 사용자가 좋아한 실제 사진/바이트 비교를 유지한다. 그 아래에는 대표 작업 **4개**를 넓은 이야기 구간으로 배치한다. 대표 선택은 이미지→PDF, 배경 제거, PDF 합치기, PDF 가리기다. 각각 형식 변환, 시각 편집, 문서 조립, 개인정보 제거라는 서로 다른 사용 목적을 보여 준다. 자르기·이어 붙이기는 이번 큰 장면에서 빼되 전체 도구 목록에서 계속 찾을 수 있다.

기존 42개 도구 디렉터리, 언어 전환, 광고 간격, 로컬 처리 안내, 관련 가이드 진입은 유지한다. 도구 자체 기능, iframe 격리/CSP, 계정/대시보드/통계 정책, 공개 배포는 이번 범위에 없다.

## 이미지→PDF 의미를 보장하는 구조

출력은 **하나의 뷰어/파일 외곽** 안에 넣는다. PDF 배지, “1개 파일 · 3쪽”, “1 / 3” 같은 페이지 단서를 HTML로 붙인다. 실제 `photo-page-0/1/2` 결과를 그 안에서 전환하거나 하나의 뷰어 안에서 쪽 썸네일로 함께 묶는다. 독립적으로 떠 있는 완성 사진 두 개를 결과라고 쓰지 않는다.

재생에서는 입력 사진3장에 순서 표시가 보이고, 사진이 문서 영역으로 모인 뒤 그 문서 안에서 쪽이 전환되는 흐름을 권장한다. 사진 순서를 실제 도구가 자동 결정한다거나 3장을 한 쪽에 콜라주하는 것처럼 보이지 않아야 한다. 페이지 이동 장식은 클릭 가능한 실버튼처럼 꾸미지 않는다. 실제 페이지 전환을 구현한다면 키보드·라벨도 제공한다.

## 모션과 정적 대체

- 초기 상태는 입력과 완결된 결과를 모두 설명하는 정적 장면이다. 사용자에게 재생을 강요하지 않는다.
- 사용자가 장면별 “동작 재생” 버튼을 누르면 한 번만 약 4~5초 재생한다. 무한 반복·여러 장면 동시 자동재생은 하지 않는다.
- 재생은 실제 처리시간을 의미하지 않는다. 가짜 퍼센트/다운로드 버튼/파일 선택 UI를 넣지 않는다. 실제 파일 처리나 모델 로드는 일어나지 않는다.
- CSS transform/opacity와 작은 페이지 전용 상태 코드로 충분하다. Lottie/영상/새 애니메이션 라이브러리 및 도구 모델을 홈에 추가하지 않는다.
- `prefers-reduced-motion`에서는 이동/반짝임을 제거하고 즉시 완결된 결과를 유지한다. 재생이 꺼져도 입력/동작/결과와 설명은 읽을 수 있다.
- 재생 버튼과 도구 시작 링크를 명확히 분리한다. 버튼은 버튼, 실제 도구는 링크이며 키보드·포커스·44px 정도 터치 목표를 확보한다.
- 실제 저장 출력에서 만든 축소 이미지 사용, 파일/쪽수와 출처 유지. 체커보드는 투명함의 설명이며 결과 PNG에 체크무늬를 구워 넣었다고 오해하지 않도록 표기한다.

## 관찰 가능한 수용기준

- **R-MOTION-STRUCTURE**: 기존 6개 동급 카드 대신 주요 작업4개가 각각 넓은 과정 장면으로 보이고, 사용자 선호 hero와 전체42개 도구 탐색이 유지된다. 390px/320px, 데스크톱에서 가로 넘침이나 잘린 결과가 없다.
- **R-MOTION-PDF**: 이미지→PDF 장면의 출력이 단일 PDF 문서로 인식된다. 3장 입력과 1파일3쪽이 일치하고, 페이지는 한 뷰어 내부에 묶인다. 실제 결과 PDF의 쪽수/화면에 사용한 쪽 순서를 확인한다.
- **R-MOTION-TRUTH**: 각 장면의 주요 조작과 실제 출력이 일치한다. 배경 제거가 대상 선택을 생략한 만능 자동처리처럼 보이지 않는다. 합치기의 입력4+2와 출력6이 일치한다. 가리기는 실제 삭제된 결과를 쓰고 가상의 정보를 사용한다.
- **R-MOTION-CONTROL**: 키보드로 재생과 실제 도구 이동을 구분해 실행할 수 있다. 한 번의 재생이 종료되고 필요시 재생 중 정지할 수 있다. reduced-motion, JS 없이도 의미 있는 정적 결과가 보인다.
- **R-MOTION-QUALITY**: 한국어/영어, 밝음/어두움에서 읽히고 포커스/라벨이 있다. 새 모션/자산 때문에 CSP 위반·외부 요청·파일 유출·레이아웃 밀림이 생기지 않는다. 기존 성능 예산 안으로 최적화하고 증가가 불가피하면 측정과 이유를 남긴다.
- **R-MOTION-REVIEW**: 기획 담당은 최종 화면의 정보구조·문구를 검토하고, 별도 검증 담당은 모바일 실화면·재생 중간/완료·감소 모션·실제 도구 진입을 독립 확인한다. 테스트 통과를 사용자 수용으로 기록하지 않는다.

## 역할 분담과 열린 사항

- 기획 담당: 본 문서/문구/최종 시각 리뷰. 구현 소스는 수정하지 않는다.
- 구현 담당: 컴포넌트/이미지 재료/모션/한영 적용 및 자체 검증. 필요하면 실제 결과 자산을 다시 내보낸다.
- 검증 담당: 수용기준과 독립 검증, 결함 재현/수정 요청. 결과 이미지를 단지 로드하는 테스트로 의미 검증을 대신하지 않는다.
- 주 에이전트: 통합, 저장소 추적 상태·문서·미리보기 지속 상태, 사용자 전달. state.json은 주 에이전트 한 명만 쓴다.

현재 구현을 막는 사용자 결정은 없다. 공개 배포/커밋은 별도 작업이다.

## 후속: 첫 화면 노출 시1회 자동재생 (2026-11-13)

사용자의 마지막 요청에 따라 위 '수동으로만 시작' 정책은 다음으로 대체한다. 다른 입출력 의미/시각 구성/문구 기준은 유지한다. 기획 담당이 구현·검증에 전달한 정책이다.

- 각 장면의 실제 `.demo-stage`가 화면에50% 이상 처음 노출되면4.8초 한 번 자동재생한다. 기사 전체나 페이지 렌더 시점을 기준으로 삼지 않아 아직 보지 않은 장면이 먼저 끝나지 않는다.
- 다른 장면이 재생 중이면 자동재생은 기다린다. 종료/새 노출 때 현재 보이는 미재생 장면을 DOM순으로 하나 시작하며 수동 재생을 가로채지 않는다. 자동은 타 장면 정지나 paused 장면 재개를 하지 않는다. 수동 start/resume만 기존처럼 타playing을 정지한다.
- 기회는 실제 재생 시작 시 소비한다. 수동 클릭도 해당 장면의 자동 기회를 소비하므로 뒤늦은 노출 감지가 임의 재시작하지 않는다. 단순 재진입으로 자동 재생은 반복하지 않는다. 짧은 재생은 화면 밖으로 나가도 끝까지 진행한다.
- 사용자가 정지한 장면은 자동으로 재개하지 않는다. 수동 정지 자체가 다른 장면의 자동재생을 즉시 유발하지 않는다.
- 감소 모션과 JS 없음은 완결된 정적 결과를 유지한다. 백그라운드 탭에서는 첫 자동 기회를 소비하지 않는다. 표시 중인 페이지로 돌아올 때 노출 조건을 다시 확인한다. 영구 저장 없이 페이지 내 상태만 두며 새로고침/재방문은 새 첫 노출로 본다.
- 기존 버튼 문구는 유지한다. 새 라이브러리/CSS/성능예산 확대는 하지 않는다. 기존 no-autoplay 기대는 명시적인 사용자 요구 변경으로 바꾸고 첫노출 전·후/재진입·수동 제어·감소모션을 검증한다.
