# 홈 차별점 설명 확장 — 2026-11-13

## 요청과 변경 범위

사용자는 현재 로컬 처리 hero 하나만으로는 차별점이 충분히 전달되지 않는다고 했다. 업무에 잠깐 필요한 작업 때문에 프로그램 설치·일회성 결제를 하기 싫고, 웹 도구의 파일 업로드는 보안이 걱정되는 상황을 직접 짚어 달라고 요청했다. 이어서 이 사이트가 어떻게 파일을 기기 안에서 처리하는지, 다양한 도구를 무료로 쓸 수 있는지, 일부 도구에는 처리용 데이터 다운로드와 데이터 사용량이 있다는 사실까지 보여 준 다음 기존 기능 소개를 시작한다.

이 문서는 해당 채팅의 실행 요청과 기존 기획·구현·검증 분리 선호를 근거로 한 변경 기준이다. 사용자 최종 화면 인수와는 구별한다. 계정/대시보드/새 처리 기능/보안 정책 변경은 범위 밖이다.

## 흐름과 와이어프레임

```text
메뉴
설치 번거로움 / 한 번 쓰는데 결제 / 문서를 올려도 될까 — 짧은 공감
파일은 내 기기에. 처리는 브라우저에서. (H1, 기존 로컬 처리 우선 유지)
시작 CTA / 안전성 상세 링크

안전한 이유와 경계
사이트의 공개 처리 프로그램 → 내 브라우저로 받기
┌ 내 기기: 파일 고르기 → 브라우저에서 처리 → 결과 저장 ┐
└ 파일 내용·이름을 서버에 보내지 않음, 광고·통계와 도구 화면 격리 ┘

여러 작업을 무료로: PDF / 이미지 / 텍스트·CSV / 동영상
일부 엔진·모델·언어 데이터의 다운로드 / 용량 안내 / 모바일 데이터 소모 안내

기존 사진 용량 줄이기 실제 결과
기존 대표 기능 4개와 최초 노출 1회 재생
추가 도구 소개 → 전체 도구 목록 → 가이드
```

최종 배치는 구현 담당의 반응형 화면에서 조정하되, 각 항목이 별개의 의미를 더하고 같은 약속의 큰 블록을 반복하지 않는다. 첫 화면의 도구 시작 경로를 유지한다. 정적 HTML/SVG/CSS만 추가하며 홈에서 처리 엔진/모델을 받지 않는다. 광고 위치와 실행 링크 주변 간격을 유지한다.

## 사실과 표현

- 프로그램 설치 없음은 별도 앱 설치가 없다는 뜻이다. 브라우저로 처리 코드·엔진·모델을 내려받는 것과 구분한다.
- 사용자 파일 내용·이름은 네트워크 요청/URL/통계에 담지 않는다. 처리와 결과 저장은 기기 안의 도구 영역에서 한다.
- 배포 도구 영역은 same-origin 권한 없는 sandbox iframe, CSP로 바깥 광고·통계와 격리한다. 격리 설명을 보강하되 실제 설정은 바꾸지 않는다.
- 사이트에서 기기로 내려받는 공개 리소스는 사용자 파일 업로드가 아니다. OCR/배경 제거 등의 큰 자료는 기존 받기 화면에서 크기를 알리고 선택하도록 한다.
- 처리 데이터는 브라우저에 보관해 재사용할 수 있지만 삭제·시크릿 모드·저장 실패·새 버전이면 다시 받을 수 있다. “처음 한 번만”, “데이터 사용 없음”, “모든 도구 오프라인”, “100% 안전”을 주장하지 않는다.
- 무료/회원가입 없음은 현재 `canUse()`와 실제 화면에 근거한다. 도구 개수는 레지스트리에서 계산한다. 가짜 이용자 수·인증·비교 통계는 만들지 않는다.

## 수용 기준

- **R-VALUE-PAIN**: 한영 상단에서 설치/일회 결제/업로드 보안 세 고민을 읽고 그 해결 방식을 연결할 수 있다.
- **R-VALUE-HOW**: 처리용 공개 자료의 수신과 사용자 파일 비전송을 구분하며, 파일 선택→처리→저장이 기기 경계 안에 있고 광고·통계 격리 이유를 설명한다.
- **R-VALUE-OFFER**: 무료·가입 없음·다양한 도구 범위가 기존 기능 예시보다 먼저 소개된다. 처리 데이터 수신, 용량 확인, 모바일 데이터 사용 가능성이 보인다.
- **R-VALUE-PRESERVE**: 기존 제목 계층·진입 링크·실제 사진 결과·대표 4개 동작·최초 노출 단회 재생·도구 전체 탐색·보안 경계를 보존한다.
- **R-VALUE-QUALITY**: 한영·320/390px·데스크톱·밝고 어두운 테마·JS 없음에서 의미/줄바꿈/라벨이 유지된다. 타입/빌드/포맷/폰트/CSP/성능 검사를 통과한다. 성능 상한은 먼저 최적화하며 추가 설명에 필요한 불가피한 증가만 실제 측정과 함께 기록한다.

## 역할과 검증

기획 담당: 사실관계·한영 문구·화면 정보 흐름 독립 검토. 구현 담당: 상단 컴포넌트/홈 연결/문구. 검증 담당: 사실/경계/접근성/회귀 검토. root: 명세/상태/테스트/실제 화면 확인/통합. 에이전트 확인은 사용자 화면 인수를 대신하지 않는다.

새 E2E는 걱정→방법→무료/데이터 안내→기존 기능 순서와 키보드 시작을 검증한다. 기존 홈 실제 처리·다운로드, 대표 장면 재생, 폰트·성능·CSP 검사를 함께 실행한다.

## 구현 중 검토 결정

- 독립 기획 담당의 실제 데스크톱/390px 캡처 검토에서 처음 14px 회색 한 줄의 고민 목록이 부가 주석처럼 읽힌다고 지적했다. 세 항목을16px/600 본문색으로 키우고 데스크톱3열·모바일3행으로 분리했다. 본문을 장문 카드로 늘리지는 않는다.
- 도식의 아이콘이 전역 SVG 표시 규칙 때문에 각 열 왼쪽에 놓여 라벨과 어긋난 점을 발견해 중앙 정렬했다.
- 초기 관련 E2E66개 중65개 통과, 홈 CSS 약10.2KB만 기존10KB 상한을 초과했다. 기존 SVG/미사용·중복 CSS 제거 후에도 새 정적 설명 스타일에 필요한 증가라 홈만10.5KB로 조정하고 최종 실측을 남긴다. 새 JS/이미지/처리자료 요청은 없다. 다른 예산 상한은 유지한다.
