# 홈 화면 개선 · 2026-11-12

사용자 요청: 사진과 실제 사용 결과가 보이는 홈으로 다듬고 업데이트를 진행한다. 앞선 제안을 바탕으로 구현을 맡겼으며, 구체적인 시각 디자인의 최종 인수는 아직 받지 않았다.

범위: 한국어·영어 홈, 홈의 간결한 도구 카드, 직접 호스팅하는 사진 처리 전후 견본. 관리자 대시보드·도구 처리·광고 설정·격리 정책은 범위 밖이다.

## 기준과 화면 구성

- R-HOME: 데스크톱·390×844 모바일 첫 화면에서 대표 도구 진입 링크가 보이고 키보드로 이동할 수 있다.
- 짧은 제목/설명 + 대표 도구 링크 | 실제 사진과 용량 맞추기 결과. 모바일에서는 소개와 링크 다음에 사진을 둔다.
- 사진은 Patrick Pahlke의 Unsplash License 사진을 직접 호스팅한다. 결과는 실제 이미지 용량 맞추기 도구에서 생성하고 수치는 실제 파일 크기로 표시한다. 원본과 결과의 출처·생성 방법은 scripts/home/README.md에 기록한다.
- 전체 도구는 기존 묶음별 목록과 모든 링크를 유지하며, 홈 카드에는 한 줄 summary를 사용한다.
- 안전성은 한 영역으로 줄이고 /safety/로 연결한다. 기존 중복 설명 카드·홈 애니메이션은 홈에서 제거한다.
- 새 런타임 JS·외부 이미지 요청 없이, 토큰 색·반응형·두 테마를 지원한다.
- 기존 광고 슬롯과 버튼의 간격은 최소 48px로 유지한다. 이미지 크기를 미리 지정해 레이아웃이 밀리지 않게 한다.

## 검증

C-HOME: 새 홈의 한영 링크·실제 예시·첫 화면 진입·키보드·모바일 가로 넘침 E2E, 기존 카테고리·언어·검색·CSP·성능·글꼴·광고 위치 회귀. 실제 빌드 화면을 데스크톱/모바일, 밝은/어두운 테마로 확인한다. C-HOME-QUALITY: 타입·빌드·포맷 검사를 통과한다. 테스트 변경은 삭제된 홈 애니메이션 대신 새 홈 사용 흐름을 검증하기 위한 것이다.

## 검증 중 보완

첫 실행에서 기존 영어 제목 기대값과 홈 애니메이션 위치 검사가 변경 전 화면을 기대해 수정했다. 성능 검사에서는 홈 문구를 줄이면서 core에서 빠진 글자가 두 rest 조각에 걸쳐 PDF 합치기의 글꼴 수신량이 156.2KB가 됐다(상한155KB). 글꼴 생성 시 홈·카테고리 목록의 글자를 함께 core로 유지하도록 변경하고 다시 측정한다. 첫 실행의 실패·중단 증거는 보존한다.

## 대표 기능의 실제 전후 예시 확장 · 2026-11-13

사용자: “사진 줄이기 저거 맘에드네. 대표기능들을 너가 선별해서 쫙 보여주면 좋겠네.” 기존 대표 사진 스타일을 유지하고, 아이콘 위주 바로가기를 6개의 시각 예시로 바꾼다. 새 대표 기능 선택과 구현을 맡겼으며, 새 배치의 최종 시각 인수는 별도다.

- R-SHOWCASE: 배경 제거·정사각형 자르기·가로 이어 붙이기·사진을 PDF로·PDF 합치기·개인정보 가리기의 실제 입력/결과를 한영 홈에서 보여준다.
- 흐름: 기존 대표 사진 → 예시 제목 → 데스크톱 2열/모바일 1열의 6개 전후 예시와 도구 링크 → 광고 → 전체 도구 목록. 카드는 이미지·짧은 설명·직접 진입 링크로 구성한다.
- 모든 처리 결과는 실제 도구에서 생성한다. PDF 가리기는 가상의 예시 문서로 만들고, 가린 글자가 결과 PDF에 검색되지 않음을 확인한다. PDF 쪽 수·이미지 크기·투명 배경도 생성 시 확인한다.
- 사진 출처·허가를 기록하고 직접 호스팅한다. 기존 화분 사진과 Erik Esly의 해안, Yana Hurska의 꽃 사진(Unsplash License)을 쓴다. 가로 잇기는 같은 풍경을 세 조각으로 나눈 견본이다.
- 새로운 이미지에는 고정 크기와 지연 로딩을 지정한다. 별도 런타임 JS·외부 이미지 요청·모델 로딩 없이 두 테마와 키보드 탐색을 지원한다. 이미지 예산은 실제 측정 뒤 이유와 수치를 기록하고 필요한 만큼만 조정한다.
- E2E: 한영 6개 도구 연결, 이미지 로딩/대체 글·모바일 넘침·기존 첫 화면 흐름·보안·성능·글꼴을 확인한다. 타입·포맷·빌드와 실제 화면을 확인하고, 기존 테일스케일 미리보기에서 새 홈을 제공한다. 사용자 폰의 접속 자체를 대신 관찰했다고 하지 않는다.

확장 첫 E2E에서 공개 예시 이미지 `photos.webp`의 주소가 기존 개인정보 검사 기준 파일 `photos.pdf`의 확장자를 뗀 이름과 겹쳐 실패했다. 사용자 파일 전송은 없으며, 공개 이미지 이름을 `album.webp`로 바꿔 기존 개인정보 검사를 그대로 유지한다.

## 2026-11-13 후속 — 과정 장면으로 재기획

사용자는 이미지→PDF 결과가 분리된 사진처럼 보이는 오류와 동급 카드 나열 구조를 지적했고, 기획·구현·검증 에이전트를 따로 두고 주요 동작을 보여 달라고 요청했다. 앞선 6개 시각 예시 기준은 이 요청 범위에서 [새 기획 기준](home-motion-plan.md)으로 대체한다. 좋아한 사진 압축 hero와 전체 도구 탐색은 보존한다. 기획 담당이 문구·정보구조·대표4개 장면을 정하고, 구현 담당이 코드·시각 장면을 만들며, 별도 검증 담당이 의미/모바일/성능/접근성을 평가한다. 사용자가 구현을 위임한 근거이며 최종 디자인 수용을 받았다는 기록은 아니다.
