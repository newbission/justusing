## 범위와 기준

- R-RECOVERY: PDF 조립·수정·글자 넣기·이미지 PDF·ZIP의 같은 워커 요청 방식을 공통화한다. AC-1: 첫 스크립트 다운로드를 실패시켜도 두 번째 실행은 새 요청 후 유효한 결과를 만든다. AC-2: 실행 중 오류와 메시지 역직렬화 오류를 감지하면 대기 중 요청을 모두 실패로 끝내고 다음 실행에 새 워커를 만든다. AC-3: 동기 전송 오류도 대기를 끝내고 재실행할 수 있다. 정상 작업 오류는 기존 오류 해석을 유지한다. 파일과 설정은 그대로다. 자동 재실행과 임의 시간제한은 넣지 않는다.
- R-QUALITY: 기존 ↑↓ 버튼을 유지하고 파일 행의 그룹 역할·이름을 제공한다. 소스의 타입/접근성 경고 0개, 외부 작업트리를 고치지 않고 전체 포맷 명령이 통과해야 한다.
- R-DEPS: npm audit의 호환 업데이트만 적용한다. major 변경·강제 다운그레이드는 하지 않는다. 감사 결과와 영향 경로를 기록하고 남은 항목을 보고한다.
- R-WEBKIT: 실제 배포 CSP는 그대로 둔다. 테스트에서 배포 출처로 들어오는 요청을 로컬 빌드로 중계해 WebKit의 opaque frame 동작을 검사한다. 외부 광고는 기존처럼 비운다. PDF 회전·이미지 변환의 결과 바이트, frame 격리와 외부 연결 차단을 검증한다. 실제 Safari 기기 확인을 대신하지 않는다.

## 결정과 출처

- D-1: 앞선 점검 두 건과 같은 요청 코드 다섯 곳까지 수정. 근거: assemble.ts, modify.ts, text-pdf.ts, images-to-pdf.ts, zip.ts의 구현; 저장소 process 문서의 같은 유형 함께 수정 규칙.
- D-2: 사용자 요청은 수정·검증 허가다. 제품 전체 계획이나 결과의 사용자 인수로 기록하지 않는다.
- D-3: 기존 canonical docs를 갱신하며 새 사이트 기능·광고 정책·sandbox/CSP 허용 범위·배포·PR/커밋은 범위 밖이다.
