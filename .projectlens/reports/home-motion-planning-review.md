## 모바일 한국어 다크: 1차 판정

- 이미지→PDF는 왼쪽 사진3장과 오른쪽 하나의 PDF viewer 외곽, 1개파일3쪽/1·3 페이지 표시로 의미가 분명해졌다. 기존 두 독립 사진이 결과로 보이던 문제를 해결한다.
- 작업 이름과 큰 제목, 한 문장 설명, 큰 장면, 단계, 재생/도구링크 순서가 읽힌다. 네 장면을 차례로 두는 구성은 각각 다른 작업을 이해하는 데 적절하다.
- 배경제거는 대상선택 표시와 투명체커보드 결과를 보여 주고, 가리기는 문서일부 표시와 검은 박스를 함께 보여 준다. 원시 결과의 실제 표현을 보존했다.
- 동작재생은 중립색 재생아이콘, 실제 도구 링크는 강조색/외부진입 화살표로 분리된다. 명칭도 명확하다.
- 42개 도구 목록이 장면 뒤에 유지된다. 이번 요청에서4장면의 길이를 더 줄이거나 대표기능 수를 다시 늘릴 필요는 발견하지 못했다.

## 수정 요청

1. PDF 합치기 입력의 보고서4쪽 라벨이 부록 종이에 가려지는 문제: root가 동일 이슈를 먼저 발견해 구현자에게 요청. 단계/최종파일 정보가 보이더라도 입력장수 단서는 가려지지 않아야 한다.
2. 장면 아래 핵심행동설명 `.demo-steps li`의 모바일10px는 작은 편이다. 11px 이상 권장, 320px에서도 줄바꿈/가로넘침 확인. 구현자에게 직접 전달했다. 내부의 작은 문서라벨은 상위안내와 중복이므로 같은 수준 변경을 강제하지 않았다.

재생중 실제 프레임, 감소모션, JS불가 대체, 키보드, 타입/빌드/성능, 영어/데스크톱은 이 모바일 정적 캡처만으로 통과라고 하지 않는다. 별도 검증 담당과 root의 실제 실행 증거가 필요하다.

## 데스크톱·영문 추가 검토

- `.projectlens/evidence/home-motion-gallery.webp`: 실제 IAB 전체 페이지에서 주요작업 영역을 잘라낸 데스크톱 밝은화면을 직접 열어 검토했다. 좌우를 번갈아 두는 넓은 구성에서 작업 설명과 입출력 장면이 대응하고, PDF 결과 외곽/쪽수/썸네일이 하나의 문서로 읽힌다. 배경제거·합치기·가리기의 서로 다른 결과 형식도 구별된다. 카드6개를 동일하게 나열하던 이전 구조보다 사용자의 구체 작업 이해 목표에 맞는다.
- `.projectlens/evidence/home-motion-mobile-en-light.png`: 모바일 영어 밝은화면을 직접 열어 검토했다. “Several photos. One PDF.”와 “one photo on each page”, “1 PDF · 3 pages”가 같은 의미를 전달하며, 재생 “Play the steps”와 실제 도구 “Image to PDF”가 구분된다. 배경제거 제목도 대상/배경의 차이를 직접 설명한다. 줄 잘림이나 입력/출력의 뜻을 바꾸는 번역은 발견하지 못했다.

**기획 최종 판정:** 구성·문구·결과 의미는 구현 목표에 적합하다. 알려진 합치기입력 라벨겹침과 단계설명11px 수정 후 캡처 갱신을 root/구현자가 진행하고 있다. 추가 구조/문구 수정 요청은 없다. 전체 기능·접근성·성능 통과는 별도 검증 담당의 실행 결과를 따른다.
