# 홈 상단 레퍼런스 조사와 구성 선택

관찰일: 2026-11-14. 범위: 홈 상단 재기획. 기획 담당의 직접 관찰이며 사용자 인수나 구현 검증 결과는 아니다.

## 조사 방식과 근거

Chrome 157을 Playwright로 실제 열고 1440×1000와 390×844에서 첫 화면, 약 한 화면 아래, 실제 소개 제목 위치까지 이동했다. 10개 모두 HTTP 200. 검색은 후보 확인에만 썼고 판단은 운영 페이지의 실제 렌더와 DOM을 함께 확인했다. 모션 줄이기를 켠 동일 환경이며 계정 생성/파일 업로드는 하지 않았다.

근거 폴더: `../evidence/home-reference/`. `{id}-desktop-top.webp`, `{id}-desktop-next.webp`, `{id}-mobile-top.webp`, `{id}-mobile-next.webp`가 실제 화면이다. 별도 소개 영역은 `{id}-{desktop|mobile}-intro.webp`. `observations.json`은 응답 코드·최종 URL·페이지 제목·첫 제목의 메타데이터를, `deeper-observations.json`은 소개 영역 관찰을 담는다. `{id}-contact.jpg`는 네 캡처를 합친 검토용 판이다. 화면 관찰과 제품 보안 주장의 독립 검증은 구별한다.

LocalSend의 기기 모형 안쪽은 이 환경에서 빈 상태로 보였다. 해당 빈 화면은 디자인 의도나 사용성의 긍정 근거로 삼지 않는다. PairDrop 데스크톱은 초기 이름이 Loading으로 남았고 모바일은 이름이 나중에 나타났다. 화면 자체와 안내 구조만 평가했다. Squoosh는 문서가 아닌 내부 스크롤 컨테이너라 첫 window 스크롤로는 이동하지 않았다. 제목으로 내부 스크롤을 이동한 추가 `squoosh-*-intro.webp`/`squoosh-*-secure.webp`에서 실제 소개를 확인했다. PairDrop은 긴 아래 소개가 없는 앱형 화면이다.

## 운영 사이트 10개

### 1. Squoosh — 단일 작업으로 바로 들어가기

URL: [Squoosh](https://squoosh.app/) · 근거 id `squoosh`.

첫 메시지와 시각: 제품 로고 아래 큰 이미지 선택 영역이 화면 중심이다. 기능 설명 문장보다 이미지 아이콘과 파일 선택 동작이 먼저 읽힌다. 아래의 실제 견본 이미지와 용량이 직접 시도를 유도한다. 모바일도 같은 순서이며 설명문을 좁게 축소해 넣지 않았다. 내부 컨테이너를 더 내리면 Small→Simple→Secure 순으로 크기 효용, 간단한 작업, 로컬 처리 근거를 각각 다른 그림과 보여준다. 모바일도 이미지/문단을 세로로 풀며 Secure 영역에서 파일이 기기에 머무는 이유를 읽을 수 있다. 신뢰는 처리 방식과 소스 링크로 보완한다.

CTA/다음 흐름: 파일 선택 또는 견본 → 즉시 편집, 아래 스크롤 → 세 가지 설명. 가져올 원리: 선택 부담을 실제 작업·견본으로 줄인다. 맞지 않는 요소: 홈 전체를 하나의 파일 투입구로 만들면 42개 도구를 구별할 수 없고 격리 경계를 지키기 어렵다. 오프라인 준비 안내도 전체 서비스에 일반화하지 않는다.

### 2. PDF24 Tools — 할 수 있는 작업을 먼저 보여주기

URL: [PDF24 Tools](https://tools.pdf24.org/en/) · 근거 id `pdf24`.

첫 메시지: 무료 PDF 도구라는 범주와 생산성 효용을 짧게 설명한다. 제목 아래 검색과 Merge/Split/Compress 등 작업명이 붙은 직접 링크가 있다. 시각은 기능별 일러스트 아이콘. 데스크톱은 큰 목록이 한 화면에 들어가지만 모바일은 2열 목록이 길어 정보 섹션까지 여러 번 내려가야 한다. 아래 Information은 기능·쉬움·안전·설치·가격 근거를 나눈다. 안전 설명은 서버 전송 암호화/삭제를 명시한다.

CTA/다음 흐름: 작업 선택 → 아래 Information. 가져올 원리: 사용자의 목적 언어로 도구를 찾게 한다. 맞지 않는 요소: 첫 화면에 전체 도구를 펼치면 우리의 '기기 안 처리' 차이가 묻힌다. 해당 서비스의 서버 처리 안전 설명은 우리 원리와 다르므로 가져오지 않는다. 반복 3열 장점 소개도 채택하지 않는다.

### 3. TinyWow — 넓은 작업 범위를 쉽게 인식시키기

URL: [TinyWow](https://tinywow.com/) · 근거 id `tinywow`.

첫 메시지: 무료 도구가 일상 일을 간단하게 한다는 효용. 보조 문구가 PDF·동영상·이미지 범위를 명시한다. 검색 아래 여러 카테고리와 대표 작업이 배치되어 '무엇을 하는 곳인지' 빨리 보인다. 모바일은 카테고리 가로 캐러셀, 다음 영역은 인기 작업 목록. 이용량 수치와 도구 수를 신뢰 근거로 내세운다.

CTA/다음 흐름: 검색/카테고리 → 인기 도구 → 가격 효용. 가져올 원리: 처음부터 다양한 파일 작업임을 보여주고 구체적인 작업명으로 연결한다. 맞지 않는 요소: 움직이는 제목·카테고리 캐러셀·이용자 수/처리량·유료 업그레이드 흐름. 확인되지 않은 인기/사용량은 만들지 않는다. 실제 레지스트리 도구 수만 근거로 쓸 수 있다.

### 4. LocalSend — 효용과 처리 위치를 한 문장에 묶기

URL: [LocalSend](https://localsend.org/) · 근거 id `localsend`.

첫 메시지: 클라우드를 거치지 않는 파일 공유를 전면에 둔다. 보조 문구는 공개 소스와 여러 플랫폼 지원으로 범주를 분명히 한다. 다운로드/웹 두 행동이 제목 바로 아래에 있고 모바일에서는 큰 세로 버튼이 된다. 다음은 공개 소스 수치와 기능 설명. 기기 모형은 보였으나 내부 화면은 빈 상태라 제품 시연의 완성도는 판단에서 제외한다.

CTA/다음 흐름: 다운로드/웹 → 공개 근거 → 기능. 가져올 원리: 프라이버시를 추상 가치 대신 '어디서 무엇을 하는지'로 설명한다. 맞지 않는 요소: 앱 설치와 오프라인 주장은 우리와 범위가 다르다. 무광고·추적 없음 표현도 우리 바깥 페이지 구조와 다르다.

### 5. PairDrop — 사용자의 다음 행동을 직접 안내하기

URL: [PairDrop](https://pairdrop.net/) · 근거 id `pairdrop`.

첫 메시지: 다른 기기에서 같은 서비스를 열라는 다음 행동을 안내한다. 보조 문구는 네트워크가 다를 때의 연결 방법이다. 시각은 내 기기 중심의 동심원과 발견 가능 범위. 모바일도 지도 같은 작업 화면을 유지한다. 별도 아래 소개가 없는 앱형 구조이며 정보 버튼에서 서비스 설명/소스 등으로 이동한다. 데스크톱 이름 로딩 미완료는 환경 제한으로 기록한다.

CTA/다음 흐름: 기기 연결 → 전송 대상 선택, 정보 버튼 → 설명. 가져올 원리: 방문자가 지금 무엇을 하면 되는지를 구체적으로 쓴다. 맞지 않는 요소: 파일이 다른 기기로 전송되는 제품이므로 동심원/연결 시각을 가져오면 로컬 처리와 반대로 읽힐 수 있다. 아이콘만으로 설명을 감추는 방식도 피한다.

### 6. Proton — 공통 가치를 먼저, 제품 폭은 다음에

URL: [Proton](https://proton.me/) · 근거 id `proton`.

첫 메시지: 프라이버시라는 공통 목적, 보조 문구는 종단간 암호화라는 작동 근거. 제목 아래 무료 계정과 요금제 CTA, 제품 아이콘들이 서비스 범위를 압축한다. 다음 영역은 소통/탐색, 저장/협업처럼 사용 목적별로 제품을 풀고 실제 UI를 곁들인다. 모바일은 CTA·제품·신뢰 줄·기능으로 길게 쌓인다. 신뢰는 이용 규모·평점·외부 평가를 제시한다.

가져올 원리: 하나의 차별점을 여러 용도 위에 놓고 각 영역이 새 정보를 더하게 한다. 맞지 않는 요소: 브랜드 규모 근거, 가입/요금제, 암호화 클라우드 구조는 우리에게 없다. 긴 신뢰 장식 줄로 실제 시작점을 아래로 미루지 않는다.

### 7. Signal — 주장을 바로 다음 영역에서 설명하기

URL: [Signal](https://signal.org/) · 근거 id `signal`.

첫 메시지는 자유로운 소통이라는 효용이며 보조 문구는 프라이버시 중심 메시지/통화 서비스임을 설명한다. 실제 통화·대화 UI가 제품 범주를 확정한다. CTA는 하나의 시작 행동이다. 다음에 '왜 쓰는가'를 묻고 암호화 구조와 읽을 수 없는 주체를 설명한다. 모바일은 카피/CTA 뒤 기기 화면, 이어 기술 근거의 순서다.

가져올 원리: 일상 효용으로 초대하고 바로 다음에 실제 작동 원리를 설명한다. 맞지 않는 요소: 메신저의 종단간 암호화, 무광고 정책, 기기 사진을 그대로 쓰지 않는다. 우리는 '내 브라우저의 격리 영역'을 직접 그려야 한다. 장면을 반복 자동재생하지 않는다.

### 8. DuckDuckGo — 무료와 프라이버시를 시작 행동과 연결하기

URL: [DuckDuckGo](https://duckduckgo.com/) · 근거 id `duckduckgo`.

첫 메시지는 프라이버시와 무료를 간단히 묶는다. 검색창이 그대로 사용 가능하고 검색 기본 설정/브라우저 받기의 서로 다른 행동을 구분한다. 모바일은 브라우저 받기를 위에 놓아 데스크톱과 행동 우선순위를 달리한다. 아래는 제품 선택 탭과 실제 브라우저 화면, 비교표로 이어진다. 이용 규모와 비교 내용이 신뢰 근거다.

가져올 원리: 핵심 효용 옆에 명확한 시작점, 확장 정보는 다음 영역으로. 맞지 않는 요소: 별도 브라우저 설치, 다운로드 중심 CTA, 광범위한 비교표. 우리 파일 입력과 공개 자료 받기도 같은 '다운로드'로 뭉뚱그리지 않는다.

### 9. Linear — 말보다 제품 화면으로 범주를 확정하기

URL: [Linear](https://linear.app/) · 근거 id `linear`.

첫 메시지는 팀/에이전트의 제품 개발 시스템이라는 명확한 범주다. 짧은 보조 문구 뒤 실제 작업 UI가 크게 이어진다. 모바일은 화면을 무작정 전체 축소하지 않고 일부를 잘라 작업 맥락을 남긴다. 아래 고객 로고를 지나 접수→계획→자동화→출시의 작업 흐름으로 설명한다. 가입 CTA는 상단 탐색에 있다.

가져올 원리: 범주·구체적인 결과를 먼저, 이어서 흐름을 설명하고 영역마다 다른 정보를 준다. 맞지 않는 요소: 큰 동작 UI/고객 로고/모션 중심 연출과 SaaS 가입 CTA. 우리의 도식은 가벼운 HTML/CSS로 만들며 기존 실제 결과 장면을 이어 사용한다.

### 10. Excalidraw — 무료 시작과 유료 선택을 명료하게 나누기

URL: [Excalidraw 소개](https://plus.excalidraw.com/) · 근거 id `excalidraw`.

첫 메시지는 쉬운 온라인 화이트보드라는 범주, 보조 문구는 아이디어·협업·공유의 일이다. 손그림 문법과 실제 편집 화면이 기능을 보여준다. 첫 화면의 무료 화이트보드 링크 뒤 공개 소스 근거/고객 줄, 다음 소개는 가입 없는 무료 시작과 Plus를 분리한다. 모바일도 제목→시연→근거→시작 순서다.

가져올 원리: 기능 범주를 쉬운 말로 쓰고 계정 없는 시작을 구체 행동에 붙인다. 맞지 않는 요소: 여러 화면을 넘겨야 나오는 본문 CTA, 고객 로고, 손글씨 장식을 모방하지 않는다. 우리에게는 별도 유료 갈림길도 없다.

## 교차 관찰에서 도출한 원리

1. 첫 화면에 불편 목록을 길게 대리 발화하는 사이트는 이번 사례에 없다. 효용과 제품 범주를 먼저, 시작 행동을 가까이 둔다.
2. PDF24/TinyWow는 도구 폭과 구체 작업명에 강하다. 그러나 전체 목록이 먼저면 모바일에서 차별점이 늦어진다. 대표 작업 3~4개만 상단에 두고 전체 목록은 유지한다.
3. LocalSend/Signal은 프라이버시를 제품 동작으로 연결한다. 우리는 기기 경계와 파일의 입출력을 보여줘야 한다.
4. Proton/Linear/Excalidraw의 큰 로고·사용량 줄을 빌리지 않는다. 우리 근거는 실제 구조와 공개 소스, 실제 결과다.
5. 모바일은 카피·CTA·시각을 읽는 순서로 쌓아야 한다. 핵심 설명을 접거나 작은 도식 글씨로 대신하지 않는다.

| A. 바로 고르는 도구함 | 효용 → 대표/전체 도구 → 로컬 원리 → 실제 결과 | 가장 빠른 작업 진입 | 파일을 안 보낸다는 차이가 평범한 도구 목록에 묻힘 | 제외 |
| B. 내 브라우저 작업실 | 효용+시작/대표 작업 ↔ 기기 안 처리 도식 → 원리+자료 안내 → 실제 결과 | 무엇/왜/시작이 같은 상단에서 해결. 도구가 내려오고 파일은 안에 머무는 관계를 설명 | 도식 글씨와 모바일 순서를 세심히 조정해야 함 | **선택** |
| C. 원리를 먼저 보는 안내 | 큰 경계 도식 → 설명 → 무료 범위/CTA → 실제 결과 | 차별점 상세 이해에 강함 | 작업 사이트보다 기술 설명 자료처럼 보임. 시작점이 늦음 | 제외 |

선택은 사용자에게 위임받은 합리적 판단이다. 별도 사용자 승인으로 기록하지 않는다. B는 Squoosh/PDF24의 구체 행동, LocalSend/Signal의 작동 원리, Proton의 하나의 공통 가치를 결합한다. 특정 사이트의 레이아웃·카피를 복사하지 않는다.

## 선택안의 정보구조와 한영 카피

### 1. 첫 화면: 할 일과 차별점, 시작점을 함께

- 눈썹 KO: `무료 파일 도구 모음` / EN: `Free tools for everyday files`
- H1 KO: `파일 작업은 가볍게. 내 파일은 내 기기에.` / EN: `Quick file tasks. Your files stay with you.`
- 보조 KO: `PDF를 합치고, 사진 용량을 맞추고, 필요한 형식으로 바꾸세요. 파일 내용과 이름은 서버로 보내지 않고 이 기기에서 처리합니다.`
- 보조 EN: `Merge PDFs, shrink photos, and convert files. Your browser does the work on your device, without sending file contents or names to a server.`
- 이용 조건 KO: `앱 설치 없이 · 가입 없이 · 무료로` / EN: `No app to install · No sign-up · Free to use`
- 주 CTA KO `무료 도구 보기` / EN `Explore free tools` → 기존 `#tools`
- 보조 CTA KO `처리 방식 알아보기` / EN `How it works` → 원리 설명 앵커 또는 기존 안전 안내
- 짧은 대표 작업 링크: PDF 합치기 / 사진 용량 맞추기 / CSV 한글 깨짐 고치기 / 동영상 소리 추출. **도구 메타의 실제 한영 이름과 경로**를 사용한다. 결과가 없는 새 카드/아이콘 반복 대신 단순 링크 또는 간결한 분리선 목록.
- 레지스트리의 실제 도구 수와 PDF·이미지·텍스트·동영상 범위는 한 줄 보완한다. 인기/이용자 수를 만들지 않는다.

### 2. 처리 그림: 내 파일의 경로가 기기 경계를 벗어나지 않음

데스크톱은 첫 카피 옆, 모바일은 CTA/대표 링크 뒤. 새 실행 스크립트·파일 투입구 없이 정적 HTML/CSS로 그린다. 모바일 가로 축소 SVG 텍스트는 피한다.

- 기기 밖 시작: `이 사이트` / `This site`
- 기기로만 내려오는 화살표: `처리 프로그램·공개 자료 받기` / `Download tool code and public resources`
- 큰 경계: `내 기기 · 이 브라우저` / `Your device · This browser`
- 안쪽 경계: `격리된 도구 영역` / `Isolated tool area`
- 안쪽 파일 흐름: `파일 선택 → 브라우저 처리 → 결과 저장` / `Choose a file → Process locally → Save the result`
- 기기 안이되 도구 경계 밖: `광고·방문 통계는 도구 영역 바깥에` / `Ads and analytics stay outside the tool area`
- 핵심 캡션: `파일 내용과 이름은 서버로 보내지 않습니다.` / `File contents and names are not sent to a server.`

공개 자료 화살표를 '결과 다운로드'와 연결하지 않는다. 파일은 기기에서 골라 같은 기기에 저장한다. 별도 기기 아이콘·브라우저·도구의 3중 상자를 만들 필요 없이 기기/브라우저를 한 경계, 격리 도구를 두 번째 경계로 표현하면 읽기 쉽고 비용도 적다.

### 3. 주장의 근거와 자료 받기: 두 정보가 다른 역할을 함

원리 제목 KO: `파일 대신, 도구가 내 기기로 옵니다.` / EN: `The tools come to your files.`

원리 본문 KO: `이 사이트에서 처리 프로그램과 필요한 공개 엔진·모델·언어 자료를 받아 브라우저가 실행합니다. 파일 선택부터 결과 저장까지는 광고·방문 통계와 분리된 도구 영역 안에서 진행됩니다.`

원리 본문 EN: `Your browser gets the tool code and any public engines, models or language resources it needs from this site. File selection, processing and saving happen in a tool area isolated from ads and visitor analytics.`

자료 제목 KO: `앱 설치는 없어요. 처리용 자료는 필요할 수 있어요.` / EN: `No app installation. Some tools need processing resources.`

자료 본문 KO: `글자 인식·배경 제거처럼 큰 자료가 필요한 도구는 용량을 먼저 보여주고 받을지 묻습니다. 모바일 데이터가 소모될 수 있어요. 이 브라우저에 보관한 자료는 재사용하지만, 삭제되면 다시 받을 수 있습니다.`

자료 본문 EN: `Tools such as text recognition and background removal show the size of large resources and ask before downloading them. Downloads may use mobile data. Resources kept in this browser are reused, but may need downloading again if removed.`

본문 기본 14~16px, 읽기 폭 제한. 숨긴 details나 푸터 각주로 밀지 않는다. 일반 도구 코드도 매번 동의받는다고 쓰지 않는다. 모바일 데이터 안내의 적용 대상을 자료 수신에 분명히 붙인다. Wi-Fi 권고는 필요하면 짧게 추가할 수 있으나 불필요한 경고 문단을 키우지 않는다.

### 4. 기존 결과 소개로 연결

기존 사진 용량 실측 전후와 4개 주요 장면은 다음에 둔다. 새 상단에서 효용을 충분히 설명하므로 기존 도입 제목이 같은 말을 반복하면 연결용 카피만 조정할 수 있다. 실제 결과/수치/출처/첫 노출 1회 자동재생·이후 수동은 그대로 유지한다.

## 소스로 대조한 사실과 구현 주의

- `src/components/ToolFrame.astro`: 배포 iframe은 allow-scripts/allow-downloads만. 광고·통계와 파일 영역의 DOM 접근 분리.
- `src/frame/FrameLayout.astro`: frame에서 자체 사이트 리소스 수신 허용, 그 밖의 연결 제한. 따라서 전체 외부 통신 없음은 아님.
- `src/lib/worker.ts`: 워커 코드를 받아 blob Worker로 실행. 무거운 작업은 기존 경로 유지.
- `src/frame/data.ts`, `src/lib/data-store.ts`: 공개 자료 경로/해시만 바깥으로 요청. 사용자 파일을 넘기지 않음. Cache 재사용·삭제 확인·수신 무결성 검사.
- `src/frame/download.ts`: 결과 Blob URL+a download. 서버에서 결과를 받아오는 구조가 아님.
- libheif 등 일반 엔진은 필요 시 자동 수신한다. '모든 자료는 선택한 뒤 받는다'는 문구 금지. 큰 데이터 묶음의 용량/선택만 설명.
- 새 라이브러리/모델/도구 Worker를 홈에서 받지 않는다. 기존 상단의 중복 CSS를 없애 홈 CSS 10.5KB 안에서 먼저 구현한다.
- 한영/1440·390·320/두 테마/감소 모션/JS 없음에서 도식 라벨·CTA·안내가 읽혀야 한다. 링크 이름은 실제 도구 메타에서 가져온다.

## 기획 수용 기준

R-HERO: 처음 읽는 사람이 파일 작업 도구 모음/무료 이용/설치가입 불필요/기기 내 처리를 CTA 앞뒤에서 파악한다.
R-FLOW: 공개 코드가 내려오는 방향과 사용자 파일이 기기에 머무는 흐름을 시각적으로 구별한다.
R-BOUNDARY: 광고통계는 도구 경계 밖이며 파일을 다루는 단계는 경계 안에 있다.
R-DATA: 앱 설치와 처리자료 수신을 구분하고 큰 묶음의 용량·선택·모바일 데이터·재수신을 읽을 수 있다.
R-CONTINUITY: 실제 사진 비교/대표장면/도구 목록으로 자연스럽게 이어진다. 기존 동작 회귀 없음.
