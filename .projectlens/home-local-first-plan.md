# 홈 우선순위 변경: 로컬 처리부터 — 2026-11-13

## 목표와 요청 출처

사용자가 “이 모든 게 안전하게 로컬에서 진행되는 게 우리의 차별점인데 그걸 어필하는 게 1순위 아닐까? 지금 만든 상단 주요 기능 소개는 두 번째로 나오면 좋겠다”고 요청했다. 파일이 기기를 떠나지 않고 내 브라우저에서 처리된다는 약속을 홈 첫인상으로 만든다. 기존 사진 용량 줄이기 실제 결과와 주요 작업4개는 다음 순서로 보존한다.

본 변경은 사용자 자율 진행 위임에 따른 기획 기준이다. 기획·구현·검증은 별도 담당자가 맡고, 본 문서는 사용자 최종 수용 기록을 대신하지 않는다. 소스/state 편집은 각각 구현 담당/root가 한다.

## 사실 근거와 메시지 경계

확인한 실제 구조:

- `src/components/ToolFrame.astro`: 배포 빌드의 도구칸은 `sandbox="allow-scripts allow-downloads"`. same-origin을 허용하지 않아 바깥 광고·방문통계 스크립트가 도구 안 파일 이름/미리보기를 읽을 수 없다.
- `src/frame/FrameLayout.astro`: 도구 영역 CSP는 기본 차단, 우리 사이트 리소스 연결만 허용한다. 우리 사이트로도 파일 이름/내용을 요청에 싣지 않는 것은 `tests/e2e/local-only.ts`와 도구 E2E가 검증한다.
- 파일 선택·미리보기·처리·결과 저장은 도구 영역에서 동작한다. 바깥과의 메시지는 테마/활동 등 신호와 공개 도구 데이터이며 사용자 파일을 전달하지 않는다.
- 사이트 바깥에는 광고/방문통계 스크립트가 있고, 도구·모델·글꼴 등 자체호스팅 리소스를 받을 네트워크 연결도 존재한다. `/safety/`는 인터넷을 끊으면 일부 도구가 멈출 수 있음을 설명한다.

따라서 **“파일 내용과 이름을 서버로 보내지 않는다”, “처리는 내 브라우저에서 한다”, “파일을 다루는 도구 화면은 광고·방문통계와 분리되어 있다”**를 강조한다. 100% 안전/완벽한 보안/외부 통신 없음/인터넷 불필요/모든 도구 오프라인/모든 위협 방어 같은 주장은 하지 않는다. 가상의 인증 배지, 보안 검사 완료 점수, 암호화 보장도 만들지 않는다.

근거 문서: `CLAUDE.md`, `docs/foundations/frame-isolation/README.md`, `src/pages/safety.astro`, `src/site.config.ts`. 검증 담당도 위 구조를 독립 확인했다.

## 정보구조와 간단 와이어프레임

```text
공통 메뉴

[1. 새 로컬처리 hero]
업로드 없는 무료 파일 도구
파일은 내 기기에.                   ┌ 내 기기 ──────────────────┐
처리는 브라우저에서.                 │ 이 브라우저                │
내용/이름 비전송 + 기기내처리 본문    │ 파일선택 → 처리 → 결과저장 │
[도구 골라 시작하기] [처리 방식 보기] └───────────────────────────┘
파일을 다루는 도구 화면은 광고·방문 통계와 분리

[2. 기존 기능 소개]
파일 작업, 가볍게 끝내세요.          실제 사진 용량 줄이기 전후/바이트
기존 짧은 기능 소개 + 사진줄이기링크
이렇게 바뀝니다. → 주요작업4개 장면(기존 의미/재생정책 유지)

다른도구 소개 연결문구 → 도구모아보기42개 → 가이드 → 바닥글
```

기존 광고 슬롯의 상대 흐름/버튼과 거리 규칙을 유지한다. 로컬처리 hero 안에는 광고를 새로 넣지 않는다. 기존 하단 `trust`는 같은 약속을 반복하므로 제거하고 `/safety/` 링크를 첫 hero에 배치한다. 하단 가이드 안내와 바닥글의 기존 안전/방침 진입은 유지한다.

첫 hero는 제목/문구만 크게 늘리는 구성이 아니다. 하나의 기기/브라우저 경계 안에 파일 선택→처리→결과 저장이 모두 들어 있는 가벼운 도식을 함께 보여 준다. 실제 파일을 넣으라는 UI나 실행 가능한 보안검사 화면처럼 보이지 않게 한다.

데스크톱: 왼쪽 핵심약속/두 CTA, 오른쪽 경계가 명확한 도식. 모바일: 제목/짧은 설명/CTA/도식의 자연스러운 한 열. 첫 화면에서 로컬 처리 약속과 시작 경로가 보이고, 도식 때문에 본문/버튼이 밀려나지 않게 한다. 다음 구간의 사진압축은 h2 수준으로 내려 첫 h1과 경쟁하지 않는다.

장면은 HTML/SVG/CSS로 간단히 만든다. 새 래스터 자산, 애니메이션/보안 라이브러리, 외부 리소스 요청은 필요하지 않다. 기존 `LocalProcessing`의 개념은 참고할 수 있지만 600줄짜리 별도 모션을 그대로 싣지 않는다. 새 hero는 정적이어도 로컬 처리 흐름이 보인다. 이미 사용자 요청으로 만든 주요작업4개 첫노출1회 모션은 그대로 유지한다.

외부서버로 가는 선을 X로 끊는 그림은 넣지 않는다. 사이트 리소스/통계 연결도 전부 차단된 것으로 오해할 수 있다. 파일이 기기 외곽을 넘지 않는 긍정적 흐름만 그린다. 광고격리의 자세한 구조는 보조 링크의 `/safety/`에 맡긴다.

### 두 번째 기능 소개

기존 사진 전후·576.7KB→99.5KB·견본수치·출처·사진줄이기 도구 링크를 보존한다. 제목은 기존 문구를 h2로 옮긴다.

- 한국어: **파일 작업, 가볍게 끝내세요.** / **PDF를 합치고, 사진 용량을 줄이고, 필요한 형식으로 바꾸세요.**
- English: **File tasks. Simply done.** / **Merge PDFs, shrink photos, and turn your files into the format you need.**

기존 `무료·가입 없이·파일 업로드 없이` 한 줄은 첫 hero에서 전달되므로 두 번째 구간에서 중복을 강제하지 않는다. 사진압축 도구 CTA와 전체 도구 링크의 유지/중복정리는 구현 재량이다. 첫 구간의 일반 도구선택 CTA와 두 번째의 구체 사진줄이기 CTA는 뜻이 달라 유지 가능하다.

## 수용기준

- **R-LOCAL-FIRST**: 홈 최초 h1/첫 주요구간에서 파일 비전송/기기내 브라우저 처리가 최우선으로 읽힌다. 기존 기능 소개/사진압축은 그 다음 구간이며 h2 이하이다. h1은 한 개다.
- **R-LOCAL-TRUTH**: 한영 문구가 실제 구조와 맞고 금지 과장을 하지 않는다. 도식의 세 단계는 기기 경계 안에 있고 네트워크/사이트 전체가 차단된 것으로 그리지 않는다. 도구 격리는 구현/CSP를 느슨하게 하지 않고 설명만 바꾼다.
- **R-LOCAL-ENTRY**: 첫 hero 주 CTA는 기존42개 도구영역으로 가며 보조 CTA는 같은 언어 `/safety/`의 실제 설명을 연다. 키보드 이름/포커스/터치가 명확하고 별도 회원가입이나 권한요청을 만들지 않는다.
- **R-LOCAL-FLOW**: 기기내 처리 도식은 데스크톱/390px/320px, 두테마/두언어에서 경계/단계/순서가 잘리지 않고 읽힌다. 화면읽기에는 동등한 설명을 제공하고 시각도식 중복낭독은 피한다. JS없음/감소모션에서도 의미가 완결된다.
- **R-LOCAL-PRESERVE**: 사진압축 실제 수치/전후/도구진입, 주요작업4개의 결과의미/첫노출단회모션/수동제어, 다른도구 연결문구,42도구탐색이 유지된다. 중복 하단trust 제거로 같은 큰약속 구간이 반복되지 않는다.
- **R-LOCAL-QUALITY**: 성능예산·CSP·직접호스팅·로컬처리 약속 유지. 첫 hero 때문에 사진/도구모델을 불필요하게 eager로드하지 않는다. 기존상한 안으로 최적화하며 광고슬롯/간격을 유지한다.
- **R-LOCAL-REVIEW**: 구현 담당과 별도 검증 담당이 실제 빌드의 첫인상/순서/문구/진입을 확인하고, 기획 담당이 최종캡처로 정보우선순위와 표현을 독립 검토한다. 에이전트 통과를 사용자 최종 수용으로 기록하지 않는다.

## 열린 사항과 역할

사용자 결정을 기다려야 하는 내용은 없다. 구현 담당은 화면·소스·한영 적용, 검증 담당은 독립 사실/실행/회귀 검증, 기획 담당은 본 기준과 최종 화면의 문구·계층 리뷰를 맡는다. root는 단일 작성자로 추적상태와 문서를 관리한다. 공개배포/커밋은 별도 범위다.
